# 互动版写法

`README.md` 写的是规矩：单文件、不联网、能检查。这一份写的是**怎么做得好**，从 001–006 六页总结出来。新页面先读这两份，再看 001–006 的成品（`dist/`，或线上 `https://layout.xiaoxiaodong.ai/001/play/`）。

## 每页都一样的骨架

1. **开场**：标题 + 一个能上手玩的东西（3D 或者可拖动的图）。手机竖屏（390×844、360×740）第一屏就要看到它的大半（≥ 45% 屏高）：标题压紧，说明文字放到它后面。
   竖着的平板（1024×1366）也看一眼：开场写了 `min-height: 100svh` 的话，内容填不满，中间会空出一大条。
2. **编号小节** `01`…`0N`，一般 6–8 节。每节一个意思，标题用大字，旁边一行英文小字。
3. **最后一节**：原海报（`<img id="poster" src="poster.webp">`，点开能放大、拖动、Esc 关）和海报上的关键词。放大后能拖的那张图加 `draggable="false"`，不然鼠标一拖就成了浏览器的「拖图片」，看图拖不动。
4. **页脚一行**：`在线版 / 全部 350 种排版：layout.xiaoxiaodong.ai` · `海报 CC BY 4.0` · `源文件 GitHub`。在线版地址是 `https://layout.xiaoxiaodong.ai/<id>/play/`。

## 内容

- **海报上的话先照用**：要点、英文小标签、用法、关键词都从 `site/src/data/poster-text.json` 拿，原话引出来，再用白话展开。
- **讲清为什么**，不只讲是什么：每个控件的读数要说「这样摆会让人怎么看」，不是只报数字。
- **每页都有**：这个方法从哪来（只写查得到的：人名、书名、年份；查不准就不写）、什么时候用、**什么时候别用**、一个小练习（几个选项挑最好的，选完给理由）。
- **海报说过头的地方，温和地改正**：001–003 的做法是引原话，标一个小签（如「说多了一点」），再说实际情况。不编统计数字、不编名人语录。
- **页面之间互相提一句就行**：讲到别页的主题，一句话 + 链接到它的在线版，不在本页重讲。

## 好看

- **颜色从海报来**：每页的底色、主色、线条色都取自自己的海报。001 米纸朱红墨黑，002 墨绿配金，003 黑底金光。
- **每页换一套字体搭配**，相邻两页不要一样。挑之前 `npm run fonts` 看各页用了什么；和前一页或后一页一模一样，`build` 会提醒。
- **标题本身就是示范**：001 的「三分法」压在自己的三分线上，002 的 1.618 : 1 色块真按 φ 分。能这样做就这样做。
- **要用的字形，字体里得有**：Inter 没有「」，站酷庆科黄油体没有 θ φ。build 完跑 `npm run glyphs -- <id>`，它列出每个字体缺页面上的哪些字；用到的地方缺了就换字体或画成 SVG（002 的 `glyphs.js`）。
- **动效有目的**：线画进来、主体缓缓落到点上、视线沿曲线走一遍。不要一直晃的装饰动画。
- **开场动画的每一刻都要好看**，不只是最后停住的样子：有人打开页面时它正走到一半，`check` 的第一屏截图（打开 0.9 秒）也常常落在半路。
- **主体可以直接从海报上裁**：读 `document.getElementById("poster").src`，在画布上 `drawImage` 裁出那一块，海报画在主体上的标注小框、虚线要补平（006 的 `peony.js`）。不另存一份图，海报还是只内联一次。

## 交互

- **一个主角玩具**，放在开场：拖、点、方向键都能操作，靠近答案时轻轻吸附，并就地说明。
- **状态只存「在画框里的位置」**（0–1 的比例），3D 和关掉 WebGL 后的 SVG 版共用它，降级几乎不用另写（001 的 `model.js`）。
- **控件用原生的** `<button>`、`<input type="range">`，看得见的 `:focus-visible`，手机上点击区 ≥ 40px，按钮文字不换行。
- **触屏**：页面要能滚。拖动只绑在明确的把手上，或者只取横向拖动。
- **开场玩具的把手标上 `data-perf-drag`**：`npm run perf` 从它的中心起左右拖，量「动起来」时的帧率。没标就拖 `.hero` 里第一块 canvas / svg，玩具是靠把手拖的（001 的对焦框、004 的太阳）就一定要标。

## 技术上的坑

- **不要** `scroll-behavior: smooth`：检查脚本快速滚到底会停在半路，后面几节截不到。
- **发光（bloom）最贵**：手机上像素比最多 1.5，bloom 用半分辨率（003 在软件渲染下从 20 帧升到 60 帧）。粒子数量按屏幕大小减少。
- **夜空底色**用 `scene.background`，不要 `setClearColor`：后者会被 bloom 提亮成灰紫。
- **`loop()` 的 `dt` 为 0 不是信号**：每次开始转的第一帧、调 `draw()` 都是 0。要不要直接画终点（跳过开场、缓动一步到位）看第三个参数：`loop(el, (t, dt, { still }) => …)`，`still` 为 true 表示后面没有帧了（减少动态效果）。004 起初把 dt 为 0 当「跳到终点」，开场动画就没了。
- 汉字只出现在 JS 里也没关系：build 已经按原样收进字体（`charset: utf8`）。只有运行时才拼出来的字（`Intl` 日期、从数字算出的字）才要写进 page.json 的 `glyphs`。

## 做完怎么算好

1. `npm run build -- --only <id> && npm run check -- --only <id>` 全过。
2. 自己看截图：`.build/shots/<id>-*.png`，每个尺寸都看；整页按 `<id>-tour-390-NN.png`、`<id>-tour-1440-NN.png` 一屏一屏往下看（不用整页长图：它会把 100svh 的开场拉成几千像素高）。好看、清楚、不挤，才算过。
3. 用真的鼠标和键盘事件把每个控件点一遍，没有报错、读数对得上（001–003 都是这样查出 bug 的）。
4. `ONLY=<id> npm run perf`，`hero` 和 `drag` 两行中位数都 ≥ 40 帧，`drag` 那行的 `drew` 要接近 `frames`（拖的时候真在重画；接近 0 说明没拖到玩具，标 `data-perf-drag`）；再用软件渲染跑一遍（命令在 `tools/perf.mjs` 开头）。
