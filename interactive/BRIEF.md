# 互动版页面任务（给批量作者的通用说明）

## 目标
把 350 种排版教学海报一张一张做成独立的互动网页：一个 HTML 文件，双击离线就能打开，也挂在 https://layout.xiaoxiaodong.ai/<编号>/play/。知识丰富、交互好、动画好、字体和审美讲究、各种屏幕都好看，每页都和别的页不一样。001–015 已经做完上线，是你的参照。

## 在哪做
- 工作区：/Users/admin/Desktop/js/350-layout-interactive，目录 interactive/。
- 先读 interactive/README.md 和 interactive/GUIDE.md，**全部照做**。再挑两三页已完成的看源码（interactive/pages/0*/）和线上成品，学它们的做法（比如 001 的 model.js：状态只存画框里的位置，3D 和 SVG 降级共用）。
- `npm run new -- <编号>` 起骨架。**只写 interactive/pages/<编号>-*/ 里面的文件**。不改 build.mjs、check.mjs、lib/、tools/、fonts.json、package.json、GUIDE.md、BRIEF.md；觉得指南有错或缺什么，写进最后的报告。
- 不要 git commit，不要 git stash，不要 `npm run dev`，不要部署。
- 同时还有别的作者在做别的编号；不要碰别的编号的目录。
- 内容来源：pages/<编号>-*/poster.webp（仔细看：配色、字体气质、图形母题）和 site/src/data/poster-text.json 里这个编号。site/src/data/guides.json 里如果有这个编号，可以参考，但里面的说法要先核实再用（已发现它有年份和数量写错的地方）。
- 选字体前先跑 `npm run fonts` 看已用的搭配，选一套和前后编号都不一样的；做完前再跑一次（别的作者可能刚用掉）。用 `npm run glyphs -- <编号>` 查字体缺字。
- 不编历史、不编统计数字、不编名人语录；查不准就不写。引用的书、论文、人名、年份要上网核实，报告里列出核实用的网址。经验值要写明是经验值。
- 长相要从海报来，不要通用的「深色仪表盘 + 圆角卡片」模板感：形状、线条、圆角与否、版面节奏都跟着这张海报的设计语言走。
- 画人时不画五官细节（眼、嘴），用侧影、剪影或背影；用户觉得有五官的面具脸吓人。
- 3D（Three.js）用在它真能帮上忙的地方；纯 DOM / SVG / 2D 画布同样可以，只要好看好玩。
- 同一小类的其他编号各有一页：不重讲它们的重点，提到时一句话加链接到它的在线版。

## 不要和别的页长得一样（最要紧）
- 开工前先打开批量提示里列出的「最近做完的页」的开场截图，一张张看。你的开场玩具的玩法、版式骨架、配色、字体都要和它们**明显不同**。
- 已经用烂、不许再用的开场：一个画框 + 拖准星 / 十字 / 把手挪主体 + 右边一列三段式按钮和读数卡，以及「按 Home 归中」这类照抄来的细节。
- 开场玩具从这个排版**本身的动作**来：网页 UI 就做一个真能用的小界面；字体和网格就让人排字、拖栏、改字距；影视镜头就让人取景、换焦段、剪两个镜头；中国传统版式就用它的材料和规矩（竖排、界栏、印章、留白）；演示文稿就让人翻页、改一页。问自己：别的编号能不能原样套用这个玩具？能，就换一个。
- 版式骨架也换，不是每页都「标题在上、左边舞台右边面板」：全屏舞台、竖向长卷、横向滚动、左右分屏对照、杂志跨页、卡片堆叠、一张大图上直接标注……跟着这张海报的版式走。
- 字体：fonts.json 现在有 38 款（含站酷快乐体、志莽行书、龙藏体、流江毛草这几款中文手写/书法字，字少，只做标题或几个大字，用 glyphs 查缺字）。**至少一款字体是最近做完的页都没用过的**；Noto Sans SC 只在真需要无衬线正文时用。
- page.json 里写 `"concept": { "toy": "开场玩具一句话", "layout": "版式骨架一句话", "look": "配色和质感一句话" }`，后面的作者靠它避开你。

## 先写方案（PLAN.md）
新页先只写 pages/<编号>-*/PLAN.md 和 page.json 的 concept，主编看过才写代码。方案写这几项，每项几行就够：
1. **一句话道理**：这种排版为什么有效。
2. **开场玩具**：怎么玩（拖什么、点什么）、一打开是什么状态（不能已经是答案）、**怎样算玩错、错了读数怎么说**、读数说什么「为什么」、和最近做完的哪几页不同在哪。
3. **版式骨架**：1440×900、390×844、844×390 各怎么排；宽屏主体占多大，窄屏怎么不被压扁。
4. **配色和字体**：从海报取的色值；字体搭配，标出最近没用过的那款。
5. **节目录**：每节一个标题（12 个字以内）+ 一句话 + 用什么交互；相邻两节不用同一种控件做同一件事。
6. **来源**：人名、书名、年份 + 核实用的网址。
7. **练习**：题目、四个选项各差在哪（只差一个变量）、正确答案的理由。

## 交付前自审：最常被打回的问题
主编审过的前 17 次里，这些反复出现。交付前对着截图一条条查：
1. **开场撞车**：和最近哪页是同一种玩法换了皮（拖把手调比例、拖主体看偏离读数……）。
2. **答案先给**：一打开或 1 秒后就自动摆到正确状态，用户没事可做。
   **玩不错**：随便点几下、按任意顺序都「过关」，读数也不看用户做了什么。开场玩具要能玩错：做错时读数和画面要说清错在哪，做对靠的是看懂了这一页讲的道理，不是靠点满。
3. **读数对不上**：读数要从画出来的同一组数算，不要写死常量；同一个数值（比如「上提 3%」）在读数、正文、按钮里只有一个来源。
4. **假精确**：示意公式算出的「张力 94%」像测量值——改成档位，或标「示意」。
5. **练习太容易**：选项标签写出了好坏（「实空分明」「失衡」），或者三个错项一眼排除。标签只写 A/B/C/D 或中性描述，四个只差一个变量。
6. **宽屏主体太小、窄屏压扁**：2560 和 1440 下主体缩在中间、两边大片空；390 下被挤成一条、圆被拉成椭圆（不要不等比缩放）；844×390 横屏也要看。
7. **两栏一边先结束**：左栏写完右栏还很长，留下大块空白——用 sticky 或重新分配内容。
8. **标题太长**：h2 断成三四行。控制在 12 个字以内，后半句放到英文小字或正文第一句。
9. **事实**：年份、首版、出处查原始来源（博物馆藏品页、出版社页）；描述原海报（颜色、位置）要和海报一致。
10. **混排跳动**：中文段落里的西文人名、年份换成另一款衬线字，一行里忽大忽小；正文里跟正文同一字体。
11. **方位词**：写「右边的实验台」，手机上它其实在下面——写「旁边」或按宽度换说法。
12. **小字和浅字**：小于 10px、对比度低于 3、透明度低于 0.45 的字，`check` 会直接报错。

## 做完的标准（GUIDE.md「做完怎么算好」全部四条）
1. `npm run build -- --only <编号> && npm run check -- --only <编号>` 全过。
2. 自己一张张看截图（.build/shots/<编号>-*.png，包括 tour 截图），好看、清楚、不挤才算过。
3. 写一个脚本用真实的鼠标、键盘、触摸事件把每个控件操作一遍，没有报错、读数对（脚本放 interactive/.build/probe/<编号>/，起 Chrome 用 tools/cdp.mjs 的 `launch`）。**每条命令都要有时限**：`timeout 300 node ...`，脚本里每个等待也要有超时；卡住就杀掉重来，不要一直等。
4. `ONLY=<编号> npm run perf`：开场和拖动两段中位数 ≥ 40 帧；再用软件渲染跑一遍（命令在 tools/perf.mjs 开头）。

整页的时间预算是 60 分钟；超过 90 分钟会被强行停掉。
