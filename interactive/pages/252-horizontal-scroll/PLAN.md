# 252 · 横向卷轴（HORIZONTAL SCROLL）互动版设计方案

## 1. 一句话道理
当一组同质信息或连续流程放不进单一屏幕宽度时，横向卷轴用「固定高度的可视窗口 + 向右延展的单轨序列」保住阅读连续性与页面纵深，而它能否成立全看三件事：**右缘露边告诉人还有下文、吸附停驻避免半卡腰斩、双端线索让键鼠和触屏都能顺手滑过去**。

## 2. 开场玩具：活体横向卷轴片窗台（Scrollport & Reel Deck）
- **怎么玩**：
  - 舞台本身就是一座 1:1 承袭 252 原海报深海午夜蓝与亮湖青双层「可视窗口 VIEWPORT」的 **2D 物理惯性横向卷轴（`data-perf-drag`）**，装载 6 张同源卡片（支持切换「原海报 · 流程卷 / 影展 · 时间轴 / 商城 · 商品轨」三题材）。
  - 用户可直接用**手指/鼠标按住左拖右拖并松手甩动**（触发真实阻尼惯性与吸附落位）、点击左右露出的邻卡直接滑入视窗、点两侧实体翻页箭、用滚轮/触控板横滑或键盘 `←`/`→` 步进。
  - 底沿 1:1 复刻原海报的「按住内容 HOLD > 向左拖动 DRAG LEFT > 松手惯性滑动 RELEASE」三步手势带会随真实交互逐阶段亮起并回显位移与初速度。
  - 舞台下方原海报三栏细竖线控制台提供 4 组横向卷轴专属参数：**卡宽占比（32%–118%）**、**吸附模式（关闭自由滑 / proximity 临近 / mandatory 强吸）**、**方向线索与桌端可达（全关盲滑 / 仅露边 / 露边+进度点+桌端按钮 / 遮挡劫持）**、**边缘安全距（0px / 20px / 68px）**与**透视窗幕开关（真实裁切 vs X光透视轨道）**，同步输出可复制的 `.reel` CSS。
- **开场初始状态（刻意停在复合错态，绝非答案）**：
  - 卡宽占比 `100%`（严丝合缝零露边 `peek = 0%`，形成假底边盲区）；
  - 吸附模式 `off`，卷轴停在 `01` 与 `02` 交界处（偏移 `0.48` 卡，主体被视窗左右刀口腰斩，主卡完整度仅 `52%`）；
  - 方向线索 `off`（无桌面翻页按钮、无进度点）、边缘安全距 `0px`（贴边啃字）。
  - 前 0.9s 开场带轻柔阻尼惯性滑至错位停驻点并亮出「半卡腰斩 · 零露边盲区」实时红标，用户必须动手调校或校准才能修好。
- **怎样算玩错，错了读数怎么说（单真源 `model.js` 双向核验）**：
  - **错态 1 · 零露边盲区（假底边）**：右缘露边 `< 8%`（例如卡宽 `100%` 塞满 1 张，或 `50%` 刚好平分 2 张）。读数直指「右缘刚好齐平视窗，下一张只露出 X%（Ypx），读者以为到此为止，违背露边线索原则」。
  - **错态 2 · 半卡腰斩停驻**：未开吸附且停在两卡中缝，主卡可见度 `< 82%`。读数指出「当前主卡被视窗切掉 Z%，画面与标题一分为二」。
  - **错态 3 · 超宽强吸锁死**：卡宽 `> 100%`（如 `118%`）同时开 `mandatory` 强吸附。读数指出「单卡比视窗还宽，强吸附把卡片锁死在中心或左缘，溢出的右侧文字永远滑不到视野里」。
  - **错态 4 · 窄条挤碎**：等效 390px 手机端单卡宽度 `< 150px`（卡宽占比 `< 36%`）。读数指出「单卡被压成窄条，标题频繁折行，失去独立卡片语义」。
  - **错态 5 · 桌端盲滑无抓手**：方向线索全关。读数指出「没有翻页按钮与进度轨，桌面端鼠轮默认只走纵轴，读者找不到向右入口」。
  - **错态 6 · 遮罩吃字 / 滚轮劫持**：切到过载干扰态时，厚重暗角盖住卡片两侧文字并警告禁止绑架整页垂直滚动。
  - **错态 7 · 贴边啃字 / 留边过胖**：`edgePad = 0px` 时卡缘顶死视窗框；`edgePad = 68px` 时吃掉过多可视宽度。
  - **多组合法解**：接受「原海报单焦露边解（78% 卡宽 + mandatory + 完整线索）」「双卡货架露边解（43% 卡宽 + proximity）」「宽轨三卡导览解（36% 卡宽 + 完整线索）」，不锁死唯一标准答案。
- **与最近 12 页的区别**：
  - 251/250/208/209/293 都是「拖容器边界或比例把手看重排/裁切」，而 252 本身是一座**真能按住拖拽并松手甩出阻尼惯性的横向卷轴片窗台**，并联动原海报三步手势遥测条与原生 CSS Scroll Snap 实验室。

## 3. 版式骨架
- **1440×900（主宽 1380px，2560 舒展至 1720px）**：
  - 1:1 忠实转译 252 原海报「极夜海蓝全出血横卷剧场」纵向四段结构（零深色顶眉导航盒、零左右仪表盘箱、绝不锁 `100svh` 避平板空洞）：
  - ① 顶沿开放海蓝刊头（左：粗白大标 `横向卷轴` + 随卷轴进度推进的自示范珊瑚粉箭头虚线 + `HORIZONTAL SCROLL` + 原话；右：`FLOW · WINDOW · CONTINUITY` + 三题材切签 + 状态胶囊）；
  - ② 全幅横向卷轴主舞台（贯穿视野宽度、中置双层亮湖青 `可视窗口 VIEWPORT`、左右实体翻页箭与青色双向延展箭头）；
  - ③ 舞台下原海报三栏细竖线「原理×参数×单真源诊单」控制台；
  - ④ 底沿圆角细框「如何滑动 HOW TO SCROLL」活体三步手势遥测条与多解/试错快切。
- **平板（1024×1366 / 768×1024）**：自然文档流，无 `100svh` 空洞；1024 保持三栏精排，768 折为单列诊单 + 双列参数。
- **390×844 手机竖屏**：压紧单行刊头（`横向卷轴` + 短粉箭 + 状态灯），三题材紧凑成一行，原话总述后置至舞台后，让等比横向卷轴主舞台（含亮湖青可视窗口框）稳占首屏 ≥ 47% 高度，并在首屏内直露白话诊单首句与滑尺。
- **844×390 手机横屏**：切为左 57% 卷轴主舞台（含手势状态）× 右 43% 精简刊头、单真源诊单与核心切签并行。

## 5. 节目录（7 节，每节标题 ≤ 12 字，相邻控件完全不同）
1. **01 · 视窗如何裁出卷轴** (`FLOW · WINDOW · CONTINUITY`)：拆解原海报三要点并温和校正「桌面横滑并非天然顺手」；交互：**SVG 视窗幕帘切刀切换器**（裸轨透视 / 真实视窗 / 假底边盲区三镜对照）。
2. **02 · 露边，才是真正的箭头** (`THE PEEK AFFORDANCE`)：讲清 12%–34% 露边如何靠视觉未闭合诱导右探；交互：**真原生 CSS `overflow-x: auto` 活体卷轴实测架**（亲手用触控板/手势/按钮滑原生容器，实时测量右缘露边像素并切换羽化遮罩）。
3. **03 · 吸附与惯性怎么配合** (`SCROLL SNAP & MOMENTUM`)（深海暗室）：详解 `scroll-snap-type`、`scroll-snap-align`、`scroll-snap-stop` 与 `overscroll-behavior-x`；交互：**2D 物理抛掷示波仪 Canvas**（按轻/中/急三种推力发射一次拨动，双轨同屏比较自由惯性、proximity、mandatory 的衰减曲线与停驻点）。
4. **04 · 横向卷轴从哪来** (`FROM HANDSCROLL TO THE REEL`)（暖象牙原纸）：从东亚手卷的臂展视窗、2004–2006 Cover Flow、2014/2017 NN/g 桌面横滑警示，到 2016–2021 W3C CSS Scroll Snap 与 2019 *Every Layout* The Reel；交互：**水平年代刻度检视卡**（点按年代切换历史器物/界面微缩图谱）。
5. **05 · 键盘、鼠标与防误触** (`ACCESSIBILITY & ERGONOMICS`)：拆解鼠轮纵轴冲突、键盘可达、`overscroll-behavior-x` 防误触浏览器后退与滚轮劫持反模式；交互：**三设备（触屏/鼠轮/纯键盘）工程防线体检矩阵**（勾选防线实时验证能否无障碍到达第 4 卡）。
6. **06 · 什么时候用，什么时候别用** (`BOUNDARIES & SIBLINGS`)（柔珊瑚雾纸）：明确适用场景、四大禁用边界，并一句话链接 243–254 同小类其他 11 个布局原语；交互：**真实需求分诊决策卡**（点选需求对比「横卷方案」与「更合适的兄弟原语」结构简图）。
7. **07 · 练眼力与原海报档案** (`PRACTICE & ORIGINAL POSTER`)（深海展墙）：4 选 1 单变量眼力测试 + 原海报放大拖拽灯箱（`draggable="false"`、Esc 关闭）+ 关键词档案 + 标准页脚。

## 7. 小练习（单变量眼力测试）
- **题目**：在 390px 手机屏幕的一条横向卡片卷轴中，四个方案只改了一个变量——**单卡占视窗宽度的比例**（配色、字号、间距、吸附方式完全相同）。哪一个方案最能既读清当前卡、又自然让人看出右边还有更多卡片？
- **四个选项（中性标签，不泄露好坏）**：
  - `A · 单卡 100% 占满视窗`（右缘露边 0%）
  - `B · 单卡 78% 占视窗`（右缘露出下卡约 18%）
  - `C · 单卡 50% 平分视窗`（同屏恰好 2 张，右缘露边 0%）
  - `D · 单卡 118% 超出视窗`（超出视窗右边界，配合强吸附导致右端文字被裁）
- **正确答案与理由**：**B**。A（100%）与 C（50%）都因为整除视窗而在右侧形成严丝合缝的「假底边」，缺少向右延伸的未闭合线索；D 超宽加吸附造成内容永远被切在视窗外；B 让主卡保有舒适宽度的同时露出 18% 邻卡切面，最稳妥。
