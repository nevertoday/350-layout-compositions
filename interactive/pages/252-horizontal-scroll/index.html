01

视窗如何裁出卷轴

FLOW · WINDOW · CONTINUITY

横向卷轴不是「把东西排成很长一行」那么简单，它的本质是用一扇定高定宽的可视窗口（Scrollport）去套住一条比窗口更长的内容轨道。

原海报把这件事拆成三个彼此咬合的环节：「连续浏览（内容在同一轨道上延展，保持阅读节奏与思维连贯）」、「窗口裁切（视窗仅显示局部内容，其余内容可滑动进入视野）」和「方向引导（通过方向线与视觉 cues，引导用户向右探索）」。

原海报说多了一点

海报底部的「按住 → 向左拖动 → 松手惯性滑动」准确描绘了触屏直觉，却略过了桌面端的物理现实：普通鼠标滚轮只有垂直轴，桌面用户也习惯自上而下阅读。把触屏横滑原封不动搬上电脑，如果没有明确的露边或翻页抓手，窗外的内容就会变成隐形死角。

同一条 6 卡轨道，三种视窗幕帘

视窗宽度略大于一张卡（约 1.28 张），主卡完整居中，右侧切出 18% 邻卡——眼睛立刻知道轨道还没结束。

02

露边，才是真正的箭头

THE PEEK AFFORDANCE

让用户发现「右边还有内容」，最管用的办法往往不是写一行「向左滑动查看更多」，而是把下一张卡片的左缘直接切进视窗里。

在视觉心理里，一张只露出 12%–32%（经验区间）的残缺卡片会自然触发未闭合的张力，不需要解释就能说明「这里是一条可滑动的轨道」。相反，只要卡片宽度恰好整除视窗——不管是单卡 100% 还是双卡 50%——右缘齐平都会制造出假底边（False Floor），让人误以为列表到此为止。

01

设定轨道容器

用 display: flex 与 overflow-x: auto 建立单行不折行的原生滚动区。

02

打破整数等分

避免 100% 或 50% 严丝合缝，把下一张卡的左缘留在视窗内约四分之一。

03

锁住不缩水

给子卡写 flex: 0 0 76%，防止 Flexbox 默认把它硬压回视窗内部。

04

留出首尾安全距

配对使用 padding-inline 与 scroll-padding-inline，聚焦外框不被切。

05

守住左右尽头

加上 overscroll-behavior-x: contain，滑到头不误触浏览器后退手势。

实测：右缘露出第 02 卡 18%（约 126px） 这是一条真实原生 CSS 卷轴，试试直接用触控板、手指或上方 ‹ › 按钮滑一遍。

03

吸附与惯性怎么配合

SCROLL SNAP & MOMENTUM

松手之后卡片停在哪，决定了卷轴像「精密的胶片片门」还是「一推就跑偏的散页」。

W3C 的 CSS Scroll Snap Module Level 1 把吸附分成两档：proximity 只在落点本来就靠近卡边时轻轻拉齐，保留自由浏览余地；mandatory 则强制每次松手都必须落回某个吸附槽，适合画廊、引导流程和移动端单卡流。

还有一个容易忽略的开关叫 scroll-snap-stop：默认 normal 允许用力一甩连续越过两三张卡；设为 always 后，无论甩得多急都一次只过一张，适合不能跳步的向导或轮播。

点上方不同力度按钮发射一次模拟拨动，对比三条轨道最终停在整卡还是中缝。

04

横向卷轴从哪来

FROM HANDSCROLL TO THE REEL

屏幕里的横向卷轴并非凭空发明，它一头连着人类展开纸卷与放映胶片的物理习惯，另一头连着 Web 标准从「排斥横滚」到「局部收编」的二十年演进。

器物原型 · 移步换景

双臂展幅，就是最早的可视窗口

中国传统手卷动辄数米，观赏时并不一次性全幅铺墙，而是左手缓缓展开、右手同步卷收，眼前始终只保留双臂自然展开的数十厘米画幅（经验视域）。电影 35mm 胶片同样把连续画面排成一条定轨，由片门逐帧截取——「轨道大于窗口，视窗随手推进」的结构在此已完全成型。

05

键盘、鼠标与防误触

ACCESSIBILITY & INPUT ERGONOMICS

一条在手机上丝滑的横卷，搬到鼠标和键盘面前常常立刻失灵——因为三种输入设备的「默认轴」并不一样。

按 WCAG 2.1 成功标准 1.4.10（Reflow），正文页面必须能在等效 320 CSS 像素宽下纵向重排、不能迫使读者双向滚屏来读普通段落；它只对数据表、图谱、工具条或画廊这类局部二维组件网开一面。也就是说，横向卷轴应当被严格隔离在组件内部，绝不能拖垮整页。

06

什么时候用，什么时候别用

BOUNDARIES & SIBLINGS

适合放进横向卷轴

  • 同质并列卡片流：商品推荐、影集海报、设计样张，顺序浏览、不必同屏全看完。
  • 步骤与时间轴：像 252 原海报 01→04 的阶段演进，左到右天然贴合时间方向。
  • 移动端的次级筛选条：省下纵向首屏空间，把正文尽快推到眼前。
  • 宽数据表的局部隔离容器：表内独立横滑，不让整张网页跟着横向溢出。

这些时候别用横向卷轴

  • 连续正文与长段落：每读完一行还要左右来回拉动，阅读效率直接崩塌。
  • 必须同时比对的决策项：核心价格表或参数对比藏在屏外，迫使读者靠短时记忆硬背。
  • 藏住唯一主导航或关键入口：NN/g 眼动观察指出桌面端八成注视落在左半屏，屏外入口点击率极低。
  • 整页劫持垂直滚轮做横向展示：夺走用户对滚动条的掌控感，破坏无障碍与浏览器常规预期。

需求分诊台：这批内容该不该进横卷？

推荐横向卷轴

同质视觉卡片，最适合单轨横卷

作品集不需要把 12 张图同时铺满三屏纵深。把单卡设为 76% 露边并配桌端翻页箭，既能保持浏览节奏，又不会拉长整页结构。

同一小类的其他布局原语

横向卷轴常和其他布局原语配合出场；各自的原理与互动实验请去它们的独立页面：

  • 用内边距与边框把内容围成独立单元，见 244 盒子；
  • 锁住阅读最大行宽并水平居中，见 245 居中器；
  • 让多枚标签或按钮自然换行聚合，见 246 簇群；
  • 主区配定宽窄边栏且窄屏自动上下折，见 247 侧栏原语；
  • 容器窄到阈值整排一起折为纵列，见 248 切换器；
  • 撑满首屏高度并把核心元素垂直置中，见 249 封面原语；
  • 不横滑而是按最小列宽自动换行成多列，见 250 自适应网格原语；
