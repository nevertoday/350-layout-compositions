01

一暗一亮，四个支点

Four pillars from the poster

为什么列表—详情一打开就显得有条理？不只是把页面劈成左右两半，而是同时靠导航、主次、对照、聚焦四股力撑住整个界面。

  1. 导航 NAVIGATION

    清晰的列表 指引方向

    列表是一张常驻地图：人一眼就能看到全局有多少条、自己停在第几条，不必摸黑往里点。

  2. 主次 PRIORITY

    突出重点 弱化次要

    左栏用深色退后、右栏用米纸提亮，亮橙只给唯一当前项与主按钮——明度差先替眼睛排好了先后。

  3. 对照 COMPARISON

    左右分区 形成对照

    清单在左、详文在右，视线横向扫一眼就能把当前项和邻近项放在一起比较，不必反复退回上一页。

  4. 聚焦 FOCUS

    集中注意 高效传达

    把阅读、看图和点击操作全部收拢进右栏，一次只专心处理一条内容，避免几十条按钮互相打架。

试试关掉明暗对照和唯一焦点

同样的两栏结构，只改色彩与强调策略，看眼睛落点怎么变。

02

从代码浏览器到今天的收件箱

Where it comes from

列表—详情不是网页时代才发明的新花样。它的源头可以追溯到 1970 年代中后期施乐帕克研究中心（Xerox PARC）的图形界面实验——工程师们发现，把「选目录」和「看内容」钉在同一个窗口里，比不断打开、关闭新窗口省力得多。

拉里·特斯勒（Larry Tesler）在 Smalltalk-76 时期做出最早的类浏览器，Smalltalk-80 沿用并定型，由阿黛尔·戈德伯格（Adele Goldberg）在 1984 年的著作《Smalltalk-80: The Interactive Programming Environment》中完整记述：上方几列按层级列出类目与方法，下方一整块详情区直接显示并编辑选中方法的代码。

名字换过好几次

早期开发文档里常叫它 Master–Detail（主—从 / 主—详）。如今 Google Material Design 3 称它为 List–Detail，苹果人机界面指南（Apple HIG）则称它为 Split View——换了更直白的名字，解决的仍是同一件事：左选、右看。

  1. 1976 / 1984

    Smalltalk-76 至 Smalltalk-80 浏览器

    特斯勒在 Smalltalk-76 时期做出最早的层级类浏览器；Smalltalk-80 沿用并由阿黛尔·戈德伯格于 1984 年成书记述，奠定「选中即刷新」的原型。

  2. 1989

    NeXTSTEP 1.0 Mail

    将「消息头列表 + 就地阅读窗格」带进日常电子邮件工作流，成为后来桌面收件箱与 macOS Mail 的直接源流。

  3. 2005

    《Designing Interfaces》定名模式

    珍妮弗·蒂德韦尔（Jenifer Tidwell）在 O'Reilly 出版的第 1 版第 2 章中，将其归纳为 Two-Panel Selector（双面板选择器）。

  4. 2010

    iPad 与 UISplitViewController

    苹果随初代 iPad（iPhone OS 3.2）推出分栏控制器（后在 SwiftUI 演进为 NavigationSplitView），确立大屏双栏、小屏单栈的自适应规范。

  5. 今天

    现代设计系统的标准布局

    Material Design 3 将 List–Detail 列为三大标准自适应布局之一，邮件、笔记、工单、系统设置几乎都沿用这套骨架。

不要和同类的几个兄弟混用：左栏如果放的是全站频道而不是同类条目清单，看 侧边栏页面（No. 258）；主内容在左、右侧只挂工具检查器或目录，看 辅助窗格布局（No. 268）；两栏平级不分主从，看 分屏布局（No. 259）。

03

算一笔「切换的账」

Context & switching cost

如果你每天只需要看一篇文章，列表—详情并不比普通单页更快。它真正的威力出现在连续浏览、筛选、批处理多条同类信息的时候。

在传统的「列表页 ⇄ 详情页」跳转里，你点进第 1 条，原来的清单就从屏幕上消失了；看完想点第 2 条，必须先点「返回」，再在脑子里回忆刚才看到第几行。列表—详情把清单一直留着，用屏幕上的视觉锚点替人扛住了这份工作记忆。

05

列表放什么，详情放什么

Division of labor

做坏列表—详情布局，最常见的原因不是比例，而是左栏塞了不该塞的东西。

  • 列表只放「认得出、选得准」的最小线索：标题、状态点、时间或一句摘要，让视线能一口气往下扫完一整屏。
  • 选中态必须一眼钉死：像海报那样，左侧一根亮橙竖杠 + 提亮底色 + 右向小箭头，视线一扫就知道右边是谁的详情。
  • 完整内容与动作归详情：长段落、大图、字段编辑、回复框与主按钮，全部放进右栏。左栏只管挑，右栏只管办。

06

什么时候用，什么时候别用

When it helps, when it hurts

适合用

  • 收件箱与消息流：邮件、即时聊天、通知中心，需要逐条扫标题、点中就地回复。
  • 工单、审核与订单后台：每天连续翻看几十上百条同类记录，边保留列表进度边在右侧做决定。
  • 笔记、文档与系统设置：条目层级清晰，用户频繁在不同笔记或配置项之间来回切看。
  • 大屏端媒体与文件预览：选文件名、右侧立刻看大图、参数或播放，不必反复弹窗。

别用它

  • 总共只有 2–4 个固定板块：左边挂一条几乎空着的窄栏很浪费，改用 顶部导航（No. 262） 或 标签页（No. 265）。
  • 每条内容只有两三行：点开右边空荡荡一大片，不如直接用 手风琴布局（No. 266） 就地展开，或 单列页面（No. 255） 顺排。
  • 需要一次横向对比多条记录的多个字段：列表—详情一次只露一条详情，跨行比价格和参数该用完整表格。
  • 沉浸式长文阅读或全屏画布：左边常驻列表会抢走视野与专注力，该让主内容独占舞台，或提供一键收起。
  • 小屏手机强行并排：空间不够时硬分两栏只会两头受气，应退回单栏钻取或配合 底部导航（No. 264）。
