01

一座自给自足的小容器

CORE PRINCIPLES

给块级容器写上 display: flow-root，不是换一套网格系统，而是在 222 普通流布局 里划出一块独立的块格式化上下文（BFC）：里面照常排块与浮动，但一切流动到此为止，不漏出去，也不让外面钻进来。

温和补充

原海报第三条题为「清除影响」，指对外界呈现的干净结果；机制上 flow-root 并非在后续受害元素上打 clear: both，而是从源头把 223 块级布局 容器封成独立流根。而且它内部依然是普通流，要做等高对齐或二维轨道应交给 226 弹性盒布局 或 227 网格布局。

03

从补丁时代到流根标准

WHERE IT COMES FROM · 1998–2020

浏览器早在 1998 年的 CSS2 就写明了块格式化上下文，却整整隔了 17 年才在工作草案里给出一个没有副作用的正规开关。点按年代印章，看清这行代码走过的弯路。

1998-05-12 W3C CSS2 §9.4.1

首次正式定义块格式化上下文（BFC）

W3C 在 CSS2 正式推荐标准里写出了 Block formatting contexts 的概念，规定浮动、绝对定位、非 visible 的 overflow 等情形会触发新 BFC，但没有为普通流盒提供专门开关。

当时痛点：想要隔离浮动，只能往 HTML 里硬塞空的 <div style="clear: both">，结构与表现混为一谈。

06

什么时候别用流根

WHEN NOT TO USE FLOW-ROOT

flow-root 只管「隔离开内部普通流」。碰到对齐分布、刻意跨段绕排或分节标题自然合并外边距时，硬套流根反倒帮倒忙；而碰上吸顶定位，背锅的其实不是它。

要做等高卡片或多列对齐，别用浮动加 flow-root 硬拼

flow-root 只能把浮动包起来，既不能让两列自动等高，也没法一行代码做居中对齐或均匀间距。

更稳做法：单轴对齐交给 226 弹性盒布局，二维轨道交给 227 网格布局，报刊流式分栏交给 229 多栏布局。
