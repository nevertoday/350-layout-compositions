流体布局让页面像水一样顺着浏览器窗口的宽窄自由舒展，既不会在窄屏上多出横向滚动条，也不会在大屏上缩成孤零零的一小条。然而窗口从手机一路拉到超宽显示器，跨度往往达到四五倍，如果不给文字栏设下宽度护栏，单行字数就会越拉越长。读者顺着过长的句子扫到行尾，再回头寻找下一行开头时极易跳行或重读，阅读节奏很快就会被打散；反过来一旦窗口收得太窄，按死比例切出来的侧栏又会被压成细条，导航和正文双双挤成碎块。真正耐拉的流体页面，总是靠比例承接变化、靠护栏守住两端。

01

三条流律与一道除法

Three fluid mechanics & target ÷ context

原海报把流体布局浓缩成三句极简口诀——先看原话，再把它翻译成浏览器里真正跑起来的数学规则。

比例伸缩

PERCENT
「按比例分配空间」

不再写死「左栏 240px」，而是改写「左栏占父容器 25%」。只要父容器一变宽或变窄，三栏就按同一套比例同步膨胀或收缩，永远加起来正好 100%。

随窗变化

FLEX
「跟随窗口自由伸缩」

当两侧需要稳住图标与菜单宽度时，把「伸缩权」集中交给中间主栏（flex: 1 或 1fr），让它像弹簧一样吞吐全部剩余空间。

连续适配

STRETCH
「适配各种屏幕尺寸」说满了一点

纯百分比确实能做到「每 1 像素都不断档」，但它并不能单靠自己吃下所有屏幕：从 320px 手机到 2560px 超宽屏跨度高达 8 倍，没有下限会被压扁，没有上限会把正文拉成面条行。

把设计稿像素翻译成流体百分比

2009 年 Ethan Marcotte 在《Fluid Grids》里给出那道著名除法：目标宽 ÷ 父容器宽 = 比例。调下面三项设计稿参数，再切实测屏宽档位，看固定像素怎样变成精确的百分比 CSS。

原稿 1200px 换成 900px 窗口时，三栏和栏距全部按 0.75× 等比收缩，整行总和依然精确咬合 100%，不会多出 1 像素横向滚动条。

03

从哪来：网页天生是液体

Where fluid layout came from

流体布局并不是后来发明的奇技淫巧——恰恰相反，它是网页被发明出来的第一天就自带的本性。

纸张有裁切死的四条边，浏览器窗口却没有。最早的 HTML 文档放进任何尺寸的显示器里，段落都会顺着窗口自动重新折行，这就是 普通流布局（No. 222） 与生俱来的流动性。后来九十年代设计师试图用表格把网页钉死成印刷海报，行业才不得不重新找回「让页面像水一样跟着容器走」的方法。

THREE ERAS OF WIDTH

1990s 表格钉死像素
2009–10 百分比 + 媒体查询
2018+ 内生流体 + clamp 护栏

从「控制像素」到「放手比例」，再到「给比例装上河岸」，二十年绕回的正是网页的液体本性。

  1. 2000

    John Allsopp《A Dao of Web Design》

    2000 年 4 月 7 日发表于 A List Apart。文章直言网页设计师把印刷品「像素掌控欲」错搬到了屏幕上，提出应当顺应网页的可变性，用相对单位而非死像素去排版——这是流体与响应式思想最早的宣言。

  2. 2006

    Matthew Levine《In Search of the Holy Grail》

    2006 年 1 月 30 日发表于 A List Apart。它解决了当时最棘手的纯 CSS 难题：左右两栏固定宽度、中间主栏随窗连续拉伸（圣杯布局）——这正是 239 号海报中段「连续拉伸 FLEX」的工程前身。

  3. 2009

    Ethan Marcotte《Fluid Grids》

    2009 年 3 月 3 日发表于 A List Apart。Marcotte 用极简的 target ÷ context = result 证明：固定网格里的每一栏和每一道栏距，都能精确换算成百分比流体网格，而不必牺牲版面比例。

  4. 2010

    Ethan Marcotte《Responsive Web Design》

    2010 年 5 月 25 日，Marcotte 把「流体网格」放在响应式设计三大支柱的第一位，再加上弹性图片与 CSS 媒体查询，让流体布局从此长出了跨断点变阵的能力。

  5. 2018+

    Jen Simmons「Intrinsic Web Design」与 CSS 数学护栏

    2018 年 Jen Simmons 提出结合 弹性盒（No. 226）、网格（No. 227） 与 fr、minmax() 的「内生网页设计」；随后 2020 年 clamp() 落地主流浏览器，一栏定、一栏流、两端自带上下限护栏，让流体布局真正成熟。

04

给流体装上护栏

clamp(min, val, max) · flat-slope-flat transfer curve

纯百分比的栏宽随窗口是一条没有尽头的直线（虚线）。现代 CSS 的 clamp(下限, 流体值, 上限) 把这条直线掰成「平 — 斜 — 平」三段：直接拖动曲线上的两个拐点，看栏宽究竟在哪个窗宽处停止缩小、又在哪个窗宽处停止拉长。

width: clamp(300px, 50vw, 570px);
下限拐点（停止缩小） vw = 600px → 300px

300 ÷ 50% = 600px

流体斜坡（连续跟随） 600 – 1140px（宽 540px）

移到曲线上可查任意窗宽

上限拐点（停止拉长） vw = 1140px → 570px

570 ÷ 50% = 1140px

三段护栏生效

拖曲线上的青/绿圆点拐点（或聚焦圆点按 ←→↑↓）实时移动拐点位置；指针滑过坐标系可读出任意窗宽下的实算栏宽。

WCAG 1.4.4

流体字号的小陷阱：用 font-size: clamp(1rem, 0.85rem + 0.8vw, 1.35rem) 让字号随窗微调时，中间的流体项务必混入 rem（不要只写纯 2vw）且收窄上下限比值——否则浏览器按 Ctrl / Cmd + 放大 200% 时，视口 CSS 宽度减半会把纯视口单位的增幅抵消掉；上线前仍需在 200% 缩放下实测。

05

什么时候用，什么时候别用

When to flow — and when to hold back

✓ 这些地方，流体布局最好用

  • 文档站、知识库与管理后台——主内容区吃进剩余空间（1fr），大屏少翻页，窄屏不溢出。
  • 图表画布、代码编辑器与地图工作台——窗口越宽、视野越大，每一寸像素都是真实工作面积。
  • 电商商品墙与素材流——配合网格自动换列与百分比列宽，从平板到带鱼屏自然多排一列。
  • 跨端 Web 应用（桌面分屏 / iPad 分屏）——用户随时把窗口拉到任意奇怪宽度（比如 613px），没有固定档位能猜中，只能靠流体连续承接。

× 这些时候，千万别直接裸奔纯流体

  • 长篇深度阅读直接 width: 100%——超宽屏一行飙到六七十字，眼球来回扫读极易疲惫、换行串行。
  • 含固定宽度表单、日期选择器的侧栏写死 20%——屏幕一窄就压穿控件最小宽度，按钮文字被挤成竖条。
  • 强构图海报、杂志跨页或精准图文对齐——窗口拉长 10% 就会把原本算好的留白与对齐彻底扯松，更适合受控的 固定宽度（No. 238） 或 多栏布局（No. 229）。
  • 密集财务报表与多列数据表——强行把 12 列塞进窄屏百分比里，数字会互相撞车截断；应保列宽并允许表格局部横向滚动。

反面教材急救箱

点三种最常见的裸流体事故，再按「看修复写法」对比一行 CSS 怎样把它救活。

.article { width: 100%; } /* 事故：1440px 下单行超 75 字 */

06

容器能流，图不能歪

Fluid boxes vs aspect-locked media

流体布局里最容易翻车的细节，是把「宽度设成 100%」和「高度写死像素」混在一起用——框是跟着窗口流了，里面的圆却被扯成了椭圆。拖动容器宽度，对比三种图片缩放策略。

img { width: 100%; height: 150px; }

框宽 620px 而高度锁死 150px（宽高比 4.1:1），原图 16:9，里面的正圆和正方形被拉成椭圆和扁矩形——流体只该伸缩容器，绝不该扭曲图形比例。
