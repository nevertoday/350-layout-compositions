01

三条原则与
四个分工角色

Principles & Four Roles

「通过主内容区与辅助窗格的组合，在保证信息聚焦的同时，提供必要的上下文与支撑，帮助理解、过滤与决策。」
原海报 · 总述

辅助窗格不是随便在页面边上多加一列。它之所以成立，靠的是海报右侧用一条虚线串联起的三条骨架原则：主次分明保证视线先落到主角，信息互补确保右栏不重复主区的话，保持关联让两边真正对话。

  1. 主次分明 HIERARCHY

    「主内容占据视觉重心，辅助窗格宽度适中，避免干扰阅读。」

    去掉辅助窗格，主内容仍能独立成立；反过来，离开主内容，辅助窗格就没有单独存在的意义。

  2. 信息互补 COMPLEMENT

    「辅助窗格提供筛选、说明、提示或关联，与主内容形成互补。」

    海报底部把这种分工拆成四个角色：● 主内容承载核心任务，■ 上下文补充环境与口径，▲ 支撑提供筛选与操作，◆ 关联把你引向更深一层。

  3. 保持关联 CONNECTED

    「通过位置相邻与视觉一致，建立清晰的信息关联路径。」

    主区选中什么，辅助窗格就立刻跟着更新什么；右栏点下筛选，主区也实时响应。一旦断开这种联动，右栏立刻退化成无人问津的杂物栏。

02

从阻塞弹窗到
非模态窗格

From Modal Dialogs to Modeless Inspectors

今天的右侧检查器、文档评论栏、AI 辅助窗格，背后有一条清晰演进了四十多年的界面主线：尽量别用弹窗打断主任务，让上下文始终触手可及。

  1. 1981
    Xerox Star 8010：属性表（Property Sheets）

    David Canfield Smith、Charles Irby 等人在 1982 年 4 月《BYTE》发表《Designing the Star User Interface》，记录了 Star 1981 年推出的按需属性表——按下专用键即在旁侧查看和修改对象属性，避免把满屏参数塞进主文档。

  2. 1989
    NeXTSTEP 1.0：非模态检查器（Inspector）

    随着 Interface Builder（由 Jean-Marie Hullot 创制）普及，检查器面板成为桌面经典：画布选中哪个组件，检查器就实时切换为它的参数，不必反复关闭弹窗。

  3. 1995
    Alan Cooper《About Face》：消灭「附加工」

    Alan Cooper 在初版《About Face》中明确提出「附加工（Excise）」与非模态反馈（Modeless Feedback）——反复点开、拖走、关闭遮挡画面的模态对话框，全都是与用户目标无关的摩擦成本。

  4. 2013
    NN/g：警惕「右栏盲视（Right-Rail Blindness）」

    尼尔森诺曼集团（Hoa Loranger）指出，由于网页右栏长期塞满广告和无关推广，用户练出了自动跳过右侧的本能；辅助窗格必须视觉克制、与主内容强联动，才能赢得信任。

  5. 2021+
    现代设计系统正式定名与标准化

    Google Material Design 3 将 Supporting Pane（支撑窗格）列为三大标准自适应布局之一（规定 840 dp 以上并列、默认宽约 360 dp）；Apple Human Interface Guidelines 则把跟随选区变化的尾侧面板定名为 Inspector，与前置导航 Sidebar 清晰分工。

03

「宽度适中」的真相：
别死绑百分比，更要控噪声

Fixed Width vs. Fluid Ratio & Visual Weight

说多了一点海报写着「辅助窗格宽度适中，避免干扰阅读」，容易让人只去盯一个固定百分比（比如写死 30%）。在真实响应式界面里，辅助窗格往往应该用「定宽经验值（如 260–380 px，M3 默认 360 dp）+ 弹性主内容区」，而不是随屏幕无限等比拉宽。

另一个常被忽略的坑是视觉重量：即使窗格只占 25% 宽，只要里面堆满高饱和徽章、红点和推广横幅，它的视觉引力就会盖过左侧主内容；要么抢走焦点，要么直接诱发右栏盲视。

06

什么时候用，
什么时候别硬凑

When to Use · When to Walk Away

适合用辅助窗格 Use it

  • 主任务连续且高频查上下文改设计属性、看数据口径、读长文批注——任何跳页或弹窗都会把思绪斩断。
  • 信息天然分主次去掉辅栏，主内容仍完整；离开主内容，辅栏没有独立意义。
  • 宽屏余量充足或可折叠桌面/横屏平板 ≥ 840 px 可并排，小屏有清晰的底部抽屉降级方案。
  • 多类轻支撑需要稳定落脚点筛选、标签、备注、提示、关联都归拢在一处，不再满屏飘浮零散气泡。

什么时候别用 Skip it

  • 两栏平起平坐、需要对照代码 Diff、双语翻译、地图与列表并重，改用 259 分屏布局 或 256 双列页面。
  • 纯粹的「列表选一条看详情」收件箱、聊天窗口、通讯录属于父子浏览，该用 267 列表—详情布局。
  • 沉浸阅读、品牌发布页或线性结账任何侧边补充都是干扰，老老实实用 255 单列页面 或 261 页眉—主体—页脚。
  • 移动优先的轻工具与主导航切换手机竖屏没有并列余地，一级切换看 264 底部导航布局 或 262 顶部导航布局。
  • 左导航 + 中主区 + 右窗格同时锁死桌面三列框架（见 257 三列页面）若两边都不能折叠，主内容会被夹到窒息。

原海报与关键词

The Original Poster & Keywords

海报四个关键词 Keywords

  • 主内容 MAIN

    聚焦核心信息，承载主要任务。

  • 上下文 CONTEXT

    提供环境信息，解释与补充。

  • 支撑 SUPPORT

    辅助操作与参考，提升效率。

  • 关联 RELATION

    建立信息联系，引导深入探索。
