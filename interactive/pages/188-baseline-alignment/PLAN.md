# 188 · 基线对齐（BASELINE ALIGNMENT）互动页方案

> 所属分类：字体、网格与东亚文字 / 对齐、缩进与文字造型  
> 原海报总述：「不同字号共享同一基线，能够建立秩序感与专业感。」

---

## 1. 一句话道理

眼睛横向扫读一行大小不一的文字时，并不去核对看不见的矩形外框（em-box / 行框）是否顶齐、居中或底齐，而是沿着**字符落脚的同一条隐形地平线（基线）**滑行。字号跨度越大、各块外框的上升部与下降部差值越悬殊——如果只让外框中轴或底边齐平，字脚就会上下颠簸；唯有把西文字母基线、双行标末行基线与汉字字面底锁到同一水平基准线上，才能既拉开强烈字号对比，又让整行稳如建筑地基。

### 关键定义（全页单一口径，由 `model.js` 通过 `TextMetrics` 实时实测）
- **外框（em-box / 行框）**：字体度量里由 `fontBoundingBoxAscent`（上升线）与 `fontBoundingBoxDescent`（下降线）包住的矩形框；无论当前文字是否包含 `g / p / y`，外框底边都预留与字号成正比的下降部空间。
- **每块的「真基线」**：
  - **西文单行块**（如 `Ag`）：拉丁字母基线（`alphabetic` / OpenType `romn`），平底字母 `A / H` 坐在线上，降部 `g / p / y` 自然垂出基线下方。
  - **双行标块**（如 `VISUAL / ORDER`、`Design / Typography`）：末行字母基线（`last baseline`，即第二行的 `romn` 基线），与左侧大标共享底部地平线。
  - **汉字块**（如 `视觉秩序`、`让信息自然呼吸`）：定死为当前字体实测的**汉字字面底**（实测笔画底边落脚线）；其正方形字框底（`ideo` 线）位于拉丁字母基线下方实测比例 `ideoDropPct`（由当前加载的 `Noto Sans SC` `TextMetrics` 实时测得，不写死常量，全页读数、01 节「海报细读」与 03 节滑块默认标尺及滑块范围共用这唯一实测值）。
- **严格区分「框底对齐」与「字墨底对齐」两种错法**：
  1. **框底对齐（外框底边齐平）**：所有块的外框下降线压齐到同一水平线。因为下降线深度随字号等比放大，**字号越大的块基线被抬得越高，字号越小的块基线越低**，形成大字上浮、小字下沉的阶梯错位。
  2. **字墨底对齐（最底端墨迹贴线）**：把每块最底端的真实笔画强行压到基线上。一旦出现带降部字母（如 `g / p / y`），降部尾巴尖端被顶上基准线，连带把字母躯干（如 `A` 的脚、`g` 的圆腹）整体顶离基线半空。

> **对原海报的温和补充（01 节「海报细读」小签）**：  
> ① 原海报底栏 `永 字 文 A a` 示意把汉字字脚与 `A a` 的字母基线压在同一红虚线上，没有画出 `g / p / y` 的降部垂出，也省略了汉字正方形外框底（`ideo` 线）低于西文基线约实测 `ideoDropPct` 这一偏移细节。  
> ② 原海报中段右侧双行英文（`VISUAL / ORDER`、`CLEAR / EXPRESSION`、`STABLE / RHYTHM`）均以**末行基线（`last baseline`）**落在线上与大标齐底。  
> ③ 原海报右上角「红黑竖柱 + 钴蓝直角三角」的底边也落在同一条隐形基线上。

## 2. 开场玩具：五栏通栏基线校对台（Five-Column Baseline Proofing Table）

- **怎么玩（直接垂直排字 + 横向垫片游标轨 + 四类错法对照，无一键通关按钮）**：
  - 直接把 188 号原海报中段的**「基线」表格**化为首屏无重外框的 2D Canvas 活体校对台：左端放原海报同款钴蓝 **`基线`** 行标，一根高纯钴蓝（`#0448D3`）水平主基线横贯全幅，四条冷灰垂直虚线从顶部刊头一路贯通穿过校对台直达底部诊断框，划分出 **5 栏**：
    1. **栏 1（左端锚定 · 大号黑体汉字）**：**`视觉秩序`** — 汉字字面底稳踩钴蓝基线（`0.00 em` 基准锚）。
    2. **栏 2（可调 · 超大西文含降部）**：**`Ag`**（`Chivo 900`）— 真基线为字母基线，`g` 降部应自然垂出蓝线下方。
    3. **栏 3（可调 · 中号中文正文）**：**`让信息自然呼吸`**（`Noto Sans SC 500`）— 真基线为汉字字面底，字号小、居中时极易飘起。
    4. **栏 4（可调 · 双行小号英文）**：**`VISUAL` / `ORDER`**（`Chivo 700` 双行）— 真基线为末行 `ORDER` 字母基线；向下拖低时会误踩首行基线导致 `ORDER` 漏底。
    5. **栏 5（右端锚定 · 微缩原海报几何徽记）**：原海报「红黑双色柱 + 钴蓝直角三角 + 上方小钴蓝圆」缩小嵌入第五栏，**黑柱底边与钴蓝三角底边稳踩在同一条钴蓝基线上**，与左端 `视觉秩序` 形成一头一尾双基准参照。
  - **三条操作路径**：
    1. **直接抓拖**：鼠标按住栏 2–4 任意字块或其显式钴蓝 `↕` 拖柄上下拖动；触屏仅在 `≥ 44×44px` 的 `↕` 拖柄上锁 `touch-action: none`，舞台其余区域保留页面竖滑。
    2. **横向垫片游标轨（标 `data-perf-drag`）**：点选栏 2–4 任一字块（默认选中 `Ag`），左右拖动下方横向游标轨微调该块相对真基线的偏移 `Δy`（统一按该块字号 `em` 计，步长 `0.02 em`），触屏单手横拖零冲突。
    3. **键盘与四种真实错法对照钮**：`Tab` 切块、`↑ / ↓` 或 `← / →` 微调（`Shift` 精细 `0.01 em`）。工具带只放设计软件里最易误触的四枚错法对照钮——**`框顶对齐`**、**`框体居中`**、**`框底对齐`**、**`字墨底对齐`**，外加 `字框透视` 开关与 `复原居中` 钮。**不提供一键对齐答案钮**，必须亲手把三块文字拉进基线磁吸区。
  - **统一比例磁吸与读数口径**：
    - 磁吸区与过关判定统一按各块自身字号比例 **`±0.04 em`**（进入该区间松手即磁吸归 `0.00 em`），所有读数统一报同一口径的 **`Δy`（`em` 为主口径，括注当前屏幕实测 `px`）**。
    - 390×844 手机竖屏下，大字 `Ag` 与锚定大标/中号正文之间字号跨度充足，开场默认态实测最大基线错位 **`≥ 8 px`**（约 `9–12 px`，红虚折线上下总跨度 `≥ 15 px`），肉眼一眼可见。
  - **朱红虚线实时扫读折线**：台面叠绘原海报底栏同款**朱红虚线（`#FC3414`）**，串起五栏实测真基线位置；偏离时在栏缝明显折跃并标出 `Δy`，全部落入 `±0.04 em` 后折线绷直合入钴蓝主基线。

- **一打开是什么状态（绝不先给答案）**：
  - 默认停在 **`框体居中`（外框中轴齐平）**态：`Ag` 真基线沉在蓝线之下（约 `-0.15 em`），`让信息自然呼吸` 飘在蓝线之上（约 `+0.46 em`），`VISUAL / ORDER` 亦偏离基线，朱红折线剧烈锯齿折跃，状态标为 **`框体居中 · 字脚飘浮`**。

- **怎样算玩错、错了读数怎么说（五类独立精准诊断）**：
  1. **`框顶对齐 · 阶梯下坠`**：四块外框顶边齐平，小字全被吊在天花板高度，扫读像踩空下台阶。
  2. **`框体居中 · 字脚飘浮`（开场态）**：四块外框中轴齐平，大字基线下沉、小字悬空，眼睛找不到连贯地平线。
  3. **`框底对齐 · 大字基线抬高`**：四块外框底边（下降线）齐平；由于下降线深度随字号变大，字号最大的 `Ag` 基线被越深的下降部空间抬高，小字则因下降部浅而基线沉低。
  4. **`字墨底对齐 · 降部顶翘`**：四块最底端墨迹强压蓝线；`Ag` 中 `g` 的降部尾巴尖端踩住蓝线，把 `A` 脚和 `g` 圆腹整体顶浮到蓝线上方半空。
  5. **`误落首基线 · 末行漏底`**：把 `VISUAL / ORDER` 拖低到第一行 `VISUAL` 落上蓝线，导致第二行 `ORDER` 整行掉穿底线。
  6. **`局部错位`**：任意拖动后若仅部分对齐，实时点名未对齐字块及其统一口径的 `Δy`（`em` / `px`）。
  7. **`五栏共线 · 秩序成立`（过关态）**：三块可调文字全部落入 `±0.04 em`（`Ag` 降部自然垂出蓝线、`让信息自然呼吸` 字面底落线、`VISUAL / ORDER` 末行落线），与左右两端锚定的 `视觉秩序` 和几何徽记三角底边共踩一条平直钴蓝地平线。

- **和最近做完的页不同在哪**：
  - 彻底避开 **186 首行缩进**的「左大标 + 右上蓝圆 + 带框舞台」同构骨架，也区别于 **187 凸排标点**（玄夜黑底左右拉标点）、**129 古腾堡图式**（2×2 报版互换）、**296 堆叠重排**（宽屏与 375 手机双蓝图）与 **240 响应式布局**（三端设备框切刀）。本页将 188 号海报中段独有的「左端基线行标 + 通栏钴蓝线 + 贯通竖虚线分栏表格」升格为全屏贯穿骨架。

## 3. 版式骨架

以 188 号原海报中段的**「通栏基线分栏表格」**作为从页顶贯通至底部的唯一结构母题：

- **贯通竖虚线网格（从刊头直通诊断框）**：整个首屏区域共享同一套 4 条冷灰垂直虚线分栏线，没有孤立卡片外框，也没有右上角大蓝圆。
- **1440×900（及 2560×1440 超宽屏）**：
  - 顶沿细眉（~32px）：左分类，右 `NO. 188 · BASELINE ALIGNMENT`。
  - **第 0 行 · 示范基线刊头行（~108px）**：左端同样标出浅钴蓝小标 `基线`，下方贯穿一条细钴蓝基线；栏 1 排粗黑大标 **`基线对齐`**、栏 2 同基线并排 **`Alignment`**（`g` 降部真垂落于刊头蓝线之下）、栏 3–4 同基线排 `BASELINE ALIGNMENT` 与原海报总述「不同字号共享同一基线，能够建立秩序感与专业感。」——**刊头本身就是第一行基线表格**，取消右上独立几何块。
  - **第 1 行 · 五栏通栏基线校对台（宽 `min(1320px, 94vw)`，2560 放宽至 `min(1760px, 84vw)`，画布高 `~330px` / 2560 `~410px`）**：无封闭重框，左端 `基线` 行标 + 通栏钴蓝主基线 + 四条贯通竖虚线分出五栏（含第五栏微缩红黑柱 + 钴蓝三角共底几何徽记）。
  - **紧贴游标与错法对照带（~58px）**：左选块签与横向游标轨（`data-perf-drag`），右四枚错法钮（`框顶对齐 / 框体居中 / 框底对齐 / 字墨底对齐`）+ `字框透视` + `复原居中`。
  - **底沿原海报蓝虚线圆角诊断框（~92px）**：上缘承接同一套冷灰竖虚线，内含状态章、统一口径 `Δy`（`em` + `px`）与两行「为什么」诊断。
- **390×844（手机竖屏）**：
  - 刊头示范行压紧至 ~74px（`基线对齐` + 同基线 `Alignment` + `BASELINE ALIGNMENT`，总述并入诊断说明），首屏上半立刻露出满宽五栏校对台（宽 `358px`，高 `~320px`）+ `50px` 横向游标轨（合计占首屏 **≥ 45% 高度**）；五栏单行横排不压扁、不换行、`Ag` 实测错位 `≥ 8 px`，三枚 `↕` 拖柄热区均 `≥ 44×44px`，其下紧凑排四枚错法钮与两行实时诊断。
- **844×390（手机横屏）**：
  - 顶部单行薄眉（~38px：大标 + `NO. 188` + 快捷错法钮）；下方切为**左 64% 满高五栏校对台配游标轨 / 右 36% 选块与诊断栏**，一屏完整零裁切。
- **1024×1366 / 768×1024（平板竖屏）**：
  - 不设 `min-height: 100svh`，刊头、校对台、游标带与诊断框按内容高度自然贴合，杜绝空带。
- **正文八节底色节奏**：
  - 在**暖白制图纸 `#FBF9F5`**、**淡冰蓝图纸 `#EEF2F9`**、**纯白档案纸 `#FFFFFF`** 与第 05 节唯一一段**深钴蓝晒印工程底 `#071A45`** 间交替；双栏结构全部采用 `sticky` 或上文下全幅展台，两侧等高收尾。

## 6. 来源（均已逐条核实）

1. **Inland Type Foundry（1894 年创立于密苏里州圣路易斯）— 「Standard Line Type」**：由 Carl Schraubstadter 的三个儿子 **William A. Schraubstadter、Oswald Schraubstadter 与 Carl Schraubstadter Jr.** 创立；因无旧式非统一基线库存，率先将同字号不同字体铸造在统一基线上并以「Standard Line Type」推广（参见维基百科原文）。  
   - 核实网址：`https://en.wikipedia.org/wiki/Inland_Type_Foundry`
2. **Josef Müller-Brockmann**，*Grid Systems in Graphic Design / Raster-Systeme für die visuelle Gestaltung*（Verlag Niggli，1981 年英德双语版）：阐述以正文字号和行距驱动跨页多栏网格与垂直秩序的现代版式方法。  
   - 核实网址：`https://en.wikipedia.org/wiki/Josef_M%C3%BCller-Brockmann`
3. **Robert Bringhurst**，*The Elements of Typographic Style*（Hartley & Marks，1992 年首版）：系统论述书籍排版中的垂直韵律、行距节拍与版面秩序。  
   - 核实网址：`https://en.wikipedia.org/wiki/The_Elements_of_Typographic_Style`
4. **光学过冲（Overshoot，经验值）**：圆弧字符（如 `O / o`）略微探出基线约 **1%–3%**（相对大写高或 x 字高，为字体设计常见经验值，因字体与设计师而异；Peter Karow 在 *Digital Formats for Typefaces* 中曾建议 `O` 约 3%、`A` 约 5%），以补偿视觉上圆弧显矮的错觉。  
   - 核实网址：`https://en.wikipedia.org/wiki/Overshoot_(typography)`
5. **Microsoft OpenType Specification — `BASE` Table & Baseline Tag Registry**：定义 `romn`（拉丁字母基线）、`ideo`（表意方块底边）、`icfb / icft`（字面底/顶）、`hang`（悬挂基线）与 `math`（数学基线）。  
   - 核实网址：`https://learn.microsoft.com/en-us/typography/opentype/spec/base`  
   - 核实网址：`https://learn.microsoft.com/en-us/typography/opentype/spec/baselinetags`
6. **W3C《中文排版需求》（CLREQ）§6.4「基线、行高等（Baselines, line height, etc.）」**（已实测抓取原文核对节号）：阐明汉字拥有等宽正方形文字外框（character frame）及居中内嵌的字面（character face），字面与外框间留有空白。  
   - 核实网址：`https://www.w3.org/TR/clreq/`
7. **W3C CSS Inline Layout Module Level 3** & **CSS Box Alignment Module Level 3** & **MDN Web Docs**：规范 `vertical-align: baseline`、`align-items: first baseline` 与 `last baseline`。  
   - 核实网址：`https://www.w3.org/TR/css-inline-3/`  
   - 核实网址：`https://www.w3.org/TR/css-align-3/`  
   - 核实网址：`https://developer.mozilla.org/en-US/docs/Web/CSS/align-items`

## 7. 小练习设计（单变量四选一盲测，无一眼排除项）

- **题目**：下面四行版式标本采用完全相同的三段文字——中文大标 **`清晰表达`**、中文正文 **`从标题到正文`**、英文双行标 **`Design` / `Typography`**（第二行含 `y / p / g` 降部）——字体、字号、间距与色值完全一致，答题前不显示任何辅助线，**唯一变量是三块的垂直对齐方式**。哪一行排得最稳、底脚最连贯？
- **四个选项（标签仅写 `A` / `B` / `C` / `D`，零暗示）**：
  - **`A`（框底对齐）**：三块的外框底边（下降线）压在同一直线上。大标 `清晰表达` 字号最大、下降部最深，真基线相对被抬高；中号正文与小号英文下降部浅，真基线相对下沉，三块字脚呈阶梯错落。
  - **`B`（双行标误用首行基线）**：大标和正文真基线齐平，但双行标误以第一行 `Design` 对齐基线，第二行 `Typography` 整行掉穿基准线下方，破坏整行底界。
  - **`C`（真基线对齐 — 正确答案）**：大标字面底、正文字面底与双行标末行 `Typography` 的字母基线共踩同一水平地平线，`Typography` 中 `y / p / g` 的降部自然垂落基线下方，实测 `Δy = 0.00 em`。
  - **`D`（字墨底对齐）**：三块最底端实际墨迹强行压到同一直线上；`Typography` 的 `y / p / g` 尾巴尖端贴死基线，把整句英文的字母躯干顶高一截，双行标明显上浮。
- **揭晓方式**：提交后四张 Canvas 卡同步叠绘钴蓝主基线、外框底灰虚线与朱红真基线折线，并列出各版由 `model.js` 实测的最大 `Δy`（`em` 与 `px`），对照指出四者的几何成因。
