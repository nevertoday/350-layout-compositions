# 246 簇群（CLUSTER GROUPING）互动页设计方案

## 1. 一句话道理
人眼先按**距离远近（接近）**与**外观同异（相似）**把零散元素自动打包成「单元」，再读取单元里的内容；只要让**组内间距明显小于组间间距**并保持同组外观一致，页面不用堆满重边框，信息结构也能一目了然；落到网页工程里，这就是 `display: flex; flex-wrap: wrap; gap` 构成的自适应「簇群（The Cluster）」布局原语。

## 2. 开场玩具
- **名字与形态**：**活体簇群涌现盘（Live Perceptual Cluster Field × Real CSS Cluster Strip）**——1:1 承袭 246 原海报的 21 件几何标本（簇群 A 五枚朱橘圆、簇群 B 五枚朱橘圆角矩形、簇群 C 六枚柔珊瑚粉圆、簇群 D 四枚纯墨黑圆角方、以及一枚孤悬右侧的纯墨黑圆角菱形「离群点」），同时支持一键切换「顶部导航 + 工具栏（真实 UI 簇群）」与「筛选标签云（CSS Cluster 折行）」两种真实网页题材。
- **单真源几何感知引擎（`model.js`）**：虚线感知包络（凸包圆角壳）不是写死的贴图，而是由 `model.js` 每帧依据所有元素的实绘 2D 坐标实时运行单链近邻聚类（single-linkage perceptual clustering）算出来的：
  - 实时核算真实组内最近邻均值 `dIn`、跨组最小边界净距 `dOut`、分离比 `R = dOut / dIn`、外观相似冲突数、游离成员数与离群点独立净距。
  - 当两簇靠得太近时，它们的虚线包络会**当场融合塌成一团警示红虚线大包**；当成员飘远时，它会脱离本组虚线壳变成「误生孤儿」；当离群菱形贴近簇群 D 时，簇群 D 的虚线壳会直接把它吞进去。
- **怎么玩**：
  1. 在画布空白通道横向直拖（`data-perf-drag`）：连续拉合簇间呼吸廊道（调整组间距与组内距分离比），实时目睹虚线包络从粘连一团分裂成清晰的 A / B / C / D 四簇。
  2. 直接拖拽画布上的**游离成员**回本组、直接拖拽**离群菱形**远离簇群 D 独立成焦点，或拖拽任意一簇微调位置。
  3. 直接点击画布上**形态/配色混杂的干扰点**（或点底带编码钮）恢复同组相似性，也可点击画布红标定位修复，支持键盘方向键与 Tab 聚焦微调。
- **开场状态（0/4 待归群，绝不先给答案）**：一打开刻意停在 4 项齐发的混沌错态——（1）组内松 28px、组间挤 12px（分离比约 `0.43×`），四簇粘成一团红虚线乱麻；（2）A/C/D 之间混入错色错形元素，接近与相似互相拉扯；（3）簇群 A 飘出一枚游离孤点破坏整体感；（4）黑菱形离群点紧贴簇群 D 边缘被当场吞并。
- **怎样算玩错、读数怎么说「为什么」**：
  - 组内挤成 0–3px → 报「簇内挤压贴边」，说明触控与视线难以分辨单个元素边界；
  - 组间 ≤ 组内 1.35× → 报「跨簇边界融化」，说明眼睛会把两个不同功能的单元读成同一排；
  - 拖出游离成员 → 报「误造离群点」，说明本应同组的成员脱离了接近场；
  - 离群点贴近其他簇 → 报「离群焦点被吞」，说明刻意孤立的强调元素失去了留白护城河；
  - 相似编码混乱 → 报「相似与接近打架」，说明颜色/形状把视线斜向拉跨了空间分组；
  - 过度加硬框 → 报「冗余硬框噪音」，说明仅靠间距已够清楚时满屏画实线框反而增加视觉负担。
  - 接受**多组合法解**（原海报经典态、紧凑工具栏态、宽松杂志目录态），只要四项实算几何与相似条件同时满足即通关。
- **和最近 12 页的明显区别**：不拖视口边墙（245）、不转星盘半径（203）、不拉斜投影角（074）、不做搜索摘要（286）、不拉裁切刀窗（324）、不推正负轮廓（119）、不剥盒模型层（244）、不做文字绕排（158）、不排 Z 路径（035）、不调等距网格槽（202）、不切分步表单闸门（285）、不移轴（073）——独占**「动态感知聚类包络涌现 + 接近/相似/离群四维空间校准 + 同步 CSS Cluster 实算」**。

## 3. 版式骨架
忠实承袭 246 原海报的**开放暖杏米纸展面**（无深色顶条、无右侧仪表盘侧栏、绝不锁 `100svh` 避开平板空洞）：
- **顶沿非对称双联**：左侧以原海报标志性**朱橘圆角开口括号（左上圆拐 + 顶沿实心朱橘圆点 + 左下回勾）**框住自示范大标「**簇群**」与宽体英标 `CLUSTER GROUPING`；右侧以原海报**细红圆角说明框**承接总述文字（关键字标朱橘），通过一道**SVG 珊瑚虚线折角引线**垂直落入下方开放画布。
- **中段全宽开放簇群画布**：铺满主栏宽（1440 下主宽 `1340px`，2560 舒展至 `1680px`），不加沉重外框，让四簇虚线包络与离群菱形直接浮在 `#FDF6ED` 原纸上。
- **底沿原海报标志暖桃色圆角原理带（`#FFE9D9`）**：内置四栏细线分隔——第 1 栏为单真源白话诊单与实算比值、第 2 栏（2×2 橘点徽）控接近与组距、第 3 栏（圆方三角徽）控相似编码与离群、第 4 栏（`↔` 双向箭徽）实时输出 CSS `.cluster` 代码；再下接原海报纯黑细线、左下同心橘环标语与右下波浪线关键词带。
- **多端适配**：
  - `1440×900`：首屏同时完整呈现圆角括号刊头、开放簇群画布与暖桃原理带上半诊断。
  - `2560×1440`：内容区同步延展至 `1680px`，画布按等比坐标舒展不缩水。
  - `1024×1366` / `768×1024`：自然流排零空洞，暖桃原理带折成整齐 2×2 四格。
  - `390×844`：刊头压紧为精炼单行括号标 + 题材胶囊，等比 4:3 画布稳占首屏 ≥46% 屏高，下方紧贴暖桃诊单首句；全程等比映射，圆绝不压成椭圆。
  - `844×390`：横屏切换为左 56% 开放画布 × 右 44% 紧凑刊头 + 诊单与核心控轨并排。

## 5. 节目录（7 节，每节标题 ≤ 11 字，相邻不用同款控件）
- **01 为什么靠得近就算一组**（*WHY PROXIMITY GROUPS*，亮象牙纸 `#FFFBF5`）：逐句展开原海报三条原理，配**行距/列距比值翻转点阵台 + 表单标签归属开关**，亲眼看见同一组点如何在横行、均质、竖列之间翻转，以及经验值（1.5×–2.5× 组间/组内比）的来由。
- **02 接近、相似与外框谁更强**（*WHEN CUES COMPETE*，暖杏砂纸 `#F7ECE0`）：补全 Stephen Palmer 1992「共同区域」并温和校准海报「说多了一点」之处；配**四线索冲突拔河切换台**（接近 / 颜色 / 形状 / 外框独立勾选 + 冲突对撞预设），测试谁压过谁。
- **03 从格式塔到网页簇群原语**（*FROM GESTALT TO CSS CLUSTER*，深炭黑暗室 `#161312`）：梳理 1923 Wertheimer → 1992 Palmer → 2019 *Every Layout* The Cluster → 2021 Safari 14.1 Flexbox `gap` 历史脉络；配**真实可拉伸 DOM CSS Cluster 折行装调盒**（拖容器宽、动态增删长短标签、切换 `justify-content` / `align-items` / `flex-wrap` / 负边距对比，零媒体查询实测）。
- **04 簇群和其他原语怎么分工**（*WHERE CLUSTER FITS*，暖杏米原纸 `#FDF6ED`）：明确适用场景，并以一句话链接区分同小类其余 11 个原语（243–254）；配**真实产品页眉「簇群套簇群」三层 X 光剖视器**，点选外层/导航/动作三层或拉窄页眉看嵌套簇群自然换排。
- **05 什么时候别用簇群**（*WHEN NOT TO USE CLUSTER*，暖桃底 `#FFE9D9`）：给出 4 类典型反例；配**翻车现场 vs 换对方案对照翻牌台**（多标签霸屏、表格错列、表单误绑、硬凑杂项）。
- **06 眼力小练习**（*QUICK CHECK*，亮象牙纸 `#FFFBF5`）：单变量四选一实战题（仅改组内/组间距，A/B/C/D 中性标签），选后高亮像素间距并给出逐项理由。
- **07 原海报与关键词**（*ORIGINAL POSTER & KEYWORDS*，暖杏米原纸 `#FDF6ED`）：原海报全貌图（点击放大、拖动、`draggable="false"`、Esc 关闭）+ 原海报结构导读与 `PROXIMITY · UNIT · FOCUS` 关键词。

## 7. 练习设计
- **题目**：同一条「文章标签 + 阅读操作」工具栏（左 3 枚主题标签「设计系统」「布局原语」「无障碍」，右 2 枚动作钮「收藏」「分享」），下面四个方案的外观、字号、配色完全相同，**唯一变量是组内间距与组间间距的搭配**。哪一方案不用加任何竖线或大框，就能让读者一眼分清「分类标签」和「操作按钮」？
- **四个中性选项**：
  - **方案 A**：组内 18px · 组间 18px（全员等距，两类元素融成一排，失去分组边界）
  - **方案 B（正确答案）**：组内 8px · 组间 32px（组间为组内的 4 倍，三标签自聚一簇、两按钮自聚一簇，无需额外边框即一目了然）
  - **方案 C**：组内 26px · 组间 8px（内松外紧倒挂，「无障碍」反而与「收藏」紧贴误绑）
  - **方案 D**：组内 2px · 组间 28px（组内过度挤压，同组胶囊几近相撞，可点性与辨识度受损）
