# 298 折叠双窗格 · FOLDED DUAL-PANE 设计方案

## 1. 一句话道理
人的工作记忆容不下频繁切页，但专注阅读又容不下旁枝末节常年占屏；把界面沿一条折轴分成「主窗聚焦」与「副窗承载」，并用低成本的一开一合在「对照查信息」与「全幅沉浸」之间切换且不丢上下文，就能同时兼得宽度与深度。

## 2. 开场玩具：双面活体折页工作台（Folded Dual-Pane Workbench）
- **物理与交互动作**：1:1 承袭 298 原海报松林深绿底中央沿垂直白色虚线「折叠轴（○---○）」立体折合的双页纸面（2D 透视投影 Canvas，标 `data-perf-drag`）。用户可直接**横拖画布**（或拉折角滑轨 / 按 `←` `→` 键 / 点中下「展开 OPEN ⟷ 折叠 FOLDED」实体开关）让副窗从 0° 完全叠入主窗背后（右缘仅留淡青折边，复刻原海报底部「折叠状态 FOLDED」）经 90° 半立、138° 原海报立体展角到 180° 平摊展开；并可直接**点击主/副窗内的真实内容块**（原海报构图 / 长文批注 / 代码审查三题材），在折叠后再展开，亲眼验证「情境保留」与「销毁清零」的差别。
- **开场初始态（绝非答案）**：刻意停在复合失衡错态——① 折角卡在 **102° 半掩夹角**（两头不讨好）；② **副窗占比 52% 喧宾夺主**且视觉权重过重（亮橘大块抢走焦点）；③ **跨折缝开关开启**，关键提交条骑在中央折叠轴上被一分为二；④ **情境保留设为关闭（销毁清零）**，折起再开会丢失选中条目。
- **可玩错的 6 类双向失误（由 `model.js` 单真源实算）**：
  1. 副窗过宽抢焦（副窗 ≥ 45% 或副窗强色权重压过主窗）；
  2. 副窗过窄挤碎（展开时副窗 < 22%，文字折断成细条）；
  3. 半折夹角卡壳（折角在 22°–112° 之间，主窗未回收空间、副窗又透视压扁）；
  4. 跨折缝截断（展开时关键元素横跨折叠轴中线）；
  5. 折叠失忆（上下文策略设为销毁清零，收起再开丢失选定锚点与进度）；
  6. 窄屏强行并排（将模拟设备切到 390px 窄屏仍展开双窗，主窗被压碎）。
- **多组合法解**：接受「展开对照解 OPEN」（130°–180°、副窗 25%–38%、次级克制、避折缝、保状态）、「折叠专注解 FOLDED」（0°–12°、回收 100% 主窗宽、保状态且留唤回折边）与「平摊书页解」（175°–180°、避折缝、层级清晰、保状态）等多组合法方案；读数用白话说明**为什么**（视线拉锯、估算行宽字数、折痕遮挡、工作记忆断裂），主窗占比、回收空间 %、折角 °、折缝净空 px 与正文/开关同源。
- **与近 12 页的明显区别**：297 是深蓝阶梯排顺，331 是暖米纸左右双门围合留白，294 是微调字形像素，252 是午夜蓝横向卷轴，166 是复古图录，251 是比例框裁切；298 以松林深绿底上的**书页式中轴折合双面真实 UI + 上下文保留实测 + 物理折缝避让**为核心动作，无法套用到其他任何编号。

## 3. 版式骨架
- **忠实转译原海报纵向四段开放结构**（零通用深灰顶眉、零圆角仪表盘黑箱、绝不锁 `100svh` 避平板空洞）：
  - **1440×900（主宽 1380px，2560 舒展至 1680px）**：开放刊头（左自示范微折大标「折叠双窗格」+ 朱橘短横 + 总述 × 右三题材切换与状态徽标）→ 三段式舞台（左 21% 原海报虚线引注「主窗聚焦 FOCUS」与单真源白话诊断 × 中 58% 立体双折页 Canvas 舞台 × 右 21% 原海报虚线引注「副窗承载 CONTEXT」与快捷控阀）→ 1:1 复刻原海报浅鼠尾草米纸四栏细竖线实况横带（含实体可拨「高效切换」开关）→ 1:1 复刻底部绿细线透底圆角盒「使用示例 USAGE DEMO（展开 OPEN ⟷ 折叠 FOLDED）」配单行参数操轨。
  - **1024×1366 / 768×1024 平板**：自然流排零空洞，主折叠舞台上方全宽，左右双注并排居下均衡成双栏。
  - **390×844 手机竖屏**：压缩刊头为紧凑两行、总述后置，等比立体双折页舞台稳占首屏 ≥ 48% 高度，同屏直见「展开 ⟷ 折叠」核心拨动按钮与诊断首句；仅拦截水平拖动手势，竖向顺畅滚页。
  - **844×390 手机横屏**：切为左 56% 折叠画布 × 右 44% 刊头、核心开关与单真源诊断并行。

## 5. 节目录（7 大节，h2 均 ≤ 12 字，明暗交替，相邻不同控件）
1. **01｜主副为什么要一开一合？**（象牙宣纸）：拆解原海报核心三要点与工作记忆成本，温和指出「自由切换」的前提；交互：**三场景任务流步进对照卡**（对比单窗跳转 / 常驻双栏 / 折叠双窗格）。
2. **02｜一页变双页的演化史**（鼠尾草淡雾纸）：从 1988 NeXTSTEP Inspector、1995/2014 Cooper《About Face》、2010 Apple iPad Split View、2020 Surface Duo & W3C Viewport Segments 到 Material Design 3 Supporting Pane；交互：**五年代书签步进器 + 动态 SVG 架构剖面图**。
3. **03｜分屏比例与折缝避让**（深松暗室）：大屏经验分屏区间、物理折缝安全带、实时 CSS 规则与跨小类衔接（链接 291/292/293/295/296）；交互：**真实 DOM 可拖分屏手柄 + 四设备形态（含折叠屏物理铰链）实时切换器**。
4. **04｜展开与折叠的四种动线**（象牙宣纸）：推开重排 vs 浮层遮盖、上下文保留、收折边条唤回与无障碍焦点，自然提及并链接 294/297/299/300；交互：**策略组合矩阵 + 一键「折合→重开」实时状态仿真器**。
5. **05｜什么时候别用它**（暖砂纸）：四类典型失效反例（单线程结账、强同步双栏比对、390px 窄屏硬折半、副窗藏必填校验）；交互：**四幕反例/正解对照切签剧场**。
6. **06｜练一练：哪套双窗方案最稳？**（深松暗室）：880px 折叠屏合同审阅场景 4 选 1；交互：**四张中性标号 SVG 方案卡片择优 + 揭示结构标尺与逐项解析**。
7. **07｜原海报与关键词**（象牙宣纸 + 深松页脚）：可点开缩放/拖拽/Esc 收起的原海报灯箱 + 原海报四关键词实绘图标卡片 + 规范页脚。

## 7. 练习设计
- **题目**：880px 宽折叠屏（中央 24px 折缝）上的「长篇合同审阅」应用，左为主窗审阅正文、右为副窗查修订记录与法条注释，选最稳的一套双窗方案。
- **选项（仅标 A / B / C / D 与中性结构代号，只差单个关键变量）**：
  - `A · 方案甲`：65:35 比例、副窗层级克制、留收折耳签，但底部「确认签署」按钮条横跨中央 24px 折缝；
  - `B · 方案乙`：避开中央折缝、留收折耳签且保留上下文，但副窗占 56% 且大块高饱和色压过 44% 主窗；
  - `C · 方案丙`（正确）：避开中央折缝、主窗 66% 与副窗 34% 主次分明、收折后留清晰唤回耳签并保留副窗阅读位置；
  - `D · 方案丁`：避开中央折缝、68:32 主次分明，但折叠收起后界面无任何唤回耳签且每次重开滚回顶部。
- **理由**：只有 C 同时守住了「主副比重」「避开物理折缝」「可唤回与情境保留」三条底线，A/B/D 各只破掉其中一条，必须逐项对照才能选对。
