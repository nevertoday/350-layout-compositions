01

AUTO-FILL & AUTO-FIT

列数自己算的秘密

原海报把自适应网格拆成两句核心：「列宽 fluid，随容器变化」和「根据可用空间自动填充列数」。真正让它告别写满七八套媒体查询的，是浏览器每当容器改宽就重跑一次的朴素算式：列数 = floor((容器宽 + 间隙) ÷ (最小列宽 + 间隙))（向下取整），算完列数再把剩下的余宽按 1fr 均分给每一列。

补充一笔

原海报给出「最小列宽 ≥ 120px，保证易读性」。这对应紧凑图标卡或 8–12 列基础轨的经验底线；若是带配图与两行摘要的完整卡片，经验上常把最小轨设为 220–280px。更关键的是写成 minmax(min(220px, 100%), 1fr)——万一容器窄到只有 190px，轨道才会顺从容器，不会自己撑出横向滚动条。

02

SPAN & DENSE FLOW

跨列层级与填洞代价

全是 span 1 的网格像一排均质货架，眼睛找不到落脚点；于是原海报专门列了「按需跨列：使用 span 构建层级」。可一旦卡片有了宽窄之分，新矛盾立刻冒出来：宽卡塞不进当前行尾就会换行留下空白缺口。打开 CSS 的 grid-auto-flow: dense 确实能自动把后面的小卡搬来填平空洞，却会悄悄拆散视觉顺序与代码顺序——如果模块有严格的阅读先后，应当改用 顺序重排（297） 或 堆叠重排（296），而不要盲目填洞。

03

GUTTER RHYTHM

间隙撑起呼吸与归属

原海报把「统一的 gutter 保持呼吸感与秩序」列在第二条。间隙绝不只是留白装饰，而是格式塔接近性原则的标尺：眼睛会自动把彼此更近的元素归成一组。如果卡片之间的 外间隙 gutter 小于卡片内部的 内边距 padding，隔壁卡片里的标题反而离你的图标更近，版面立刻串行失序；反过来，若间隙膨胀超过单列宽的三成，原本成套的模块就被撕成了孤岛。

内边距决定卡内要素的亲疏，外间隙划清模块之间的界线。

模块 B · 跨列层级

当外间隙小于内边距，两张卡片的内容在余光里会互相串门。

模块 C · 呼吸节拍

经验上令外间隙大于等于内边距（约 1.0–1.5 倍），归属最干脆。

ORIGIN · 1981—2018

从瑞士网格到浏览器

自适应网格不是某个 CSS 属性一夜冒出来的，而是平面印刷的模块网格与多终端网页碰撞了近四十年的结果——纸面有固定裁切尺寸，屏幕却从 320px 延伸到 2560px，于是「按尺画栏」一步步进化成「把算列公式交给浏览器」。

05

WHEN TO USE & AVOID

什么时候用，什么时候别用

自适应网格最擅长「同批模块化内容跨多端重排」，但它不是万能药。遇到长文阅读、强步骤先后、主副结构突变或只随父容器走的孤立卡片时，强套自适应网格反而适得其反。点开下方六种真实页面需求，逐一判断该留还是该换。

模块结构同质且彼此独立，宽屏需要一眼扫完 4–6 列，手机竖屏自然折成 1–2 列，重点款给 span 2 提亮即可，几乎无需维护多套断点模板。

小指标卡占 1–2 列、主折线图占 3–4 列，只要加上最小列宽护盾与窄屏跨列钳制，就能一套布局通吃笔记本、平板与手机巡检。

连续长文追求舒适的每行字数测度（经验上中文约 28–42 字/行），拆成多列自适应格反而打断视线。更适合整体柔顺伸缩的 大体流动模式（291），或在固定大框里轻调字号留白的 微调模式（294）。

当侧边栏和主内容在角色上截然不同，需要窄屏藏进抽屉、整栏下落、换骨架或可折合双窗时，应直接采用 列下落模式（292）、布局切换模式（293）、画布外模式（295） 或 折叠双窗格（298）。

阅读与填写顺序一旦不能打乱，千万别开 dense 填洞，也别让宽窄混排导致视线跳格；若只为小屏调整先后优先级，请看 堆叠重排（296） 与 顺序重排（297）。

页面级自适应网格能管好卡片占几列，却管不了“卡片自己变窄后内部图文从左右排切回上下排”。这种按父容器独立变形的卡片，要交给基于容器查询的 组件级响应布局（300）。
