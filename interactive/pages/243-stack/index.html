01

间距该归父容器管

PARENT OWNS THE SPACE

原海报用三句话概括了堆栈：「垂直叠放，层级清晰有序」「顺序明确，信息按序呈现」「易于扩展，模块灵活增删」。注意第三条底下的英文小标签并不是 EXTEND，而是 SPACING（间距）——这恰好点破了堆栈之所以能自由增删模块的真正秘密。

如果每个按钮、段落、卡片都自己背着一段写死的 margin-bottom，一旦需求变化要删除最后一块、在顶部临时插一条公告，或者上下调换顺序，外边距就会漏出容器底边、互相粘连撞车。堆栈做的第一件事，就是把子元素自身的外边距全部清零，把「相邻两块隔多远」的权力唯一交给外层父容器。

试一次真实维护改动：
旧写法 · 子项自带 margin-bottom 看起来差不多，但底部多出 20px 死白
堆栈原语 · 父容器 gap: 20px 父容器 gap: 20px，只在相邻两块之间加空隙

02

用嵌套拉开主次

NESTED RHYTHM

许多人第一次用堆栈，会把页面上所有元素一股脑塞进同一个大容器、设同一个 gap: 20px，结果标题离自己正文的距离和离下一段操作按钮的距离一模一样，画面顿时失去亲疏感。堆栈的正确用法是大堆栈套小堆栈：外层给大节拍分隔不同板块，内层给小节拍把「标题 + 说明」牢牢捆成一组；至于单块自身的内边距与描边交给244 盒子，整列阅读宽度的收束交给245 居中器。

外边距塌陷暗室

05

什么时候别用堆栈

WHEN NOT TO STACK

原海报说多了一点

原海报把「头部、内容、操作区」画成三块等宽等高的大横条，容易让人以为堆栈只用来码三张大卡片。实际上小到标签与输入框、大到整页章节，凡是单一纵轴流都是堆栈；反过来，一旦超过约 5–7 个同等权重的宽卡在桌面端硬堆成一根超长单列，用户的滚轮疲劳就会盖过「秩序清晰」的好处——此时就该换用其他布局原语。

布局原语家族速查：什么时候交给隔壁原语

  • 需要给单块本身加内边距、描边或背景边界 → 244 盒子
  • 堆栈拉太宽、每行字数过长需要收束居中 → 245 居中器
  • 按钮组、筛选标签沿横轴自然聚拢并自动换行 → 246 簇群
  • 宽屏主次双区并排、窄屏自动折落成上下 → 247 侧栏原语
  • 等权多块在阈值处整体从横排切为竖排 → 248 切换器
  • 让主视觉居中占满首屏、顶底附带辅助信息 → 249 封面原语
  • 大量同类卡片在宽屏自动按列铺开对比 → 250 自适应网格原语
  • 图片、视频需要锁死 16:9 或 4:3 画幅防变形 → 251 比例框
  • 同一类长列表需要保留横向滑动浏览轨道 → 252 横向卷轴
  • 提示条、角标或弹窗要叠在底层内容之上 → 253 悬浮层
  • 小图标与紧随文字在行内按基线稳稳对齐 → 254 图标文字组合
