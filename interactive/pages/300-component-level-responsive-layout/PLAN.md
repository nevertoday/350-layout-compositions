# 300 组件级响应布局 · 设计方案

## 1. 一句话道理
响应式布局不该只看整张屏幕有多宽：当同一个组件被放进宽主栏、窄边栏或弹窗等不同容器时，只有让组件盯紧自己的父容器可用宽度而非全局视口，才能在不改业务代码的前提下自动重排，同时守住信息完整与主次层级。

## 2. 开场玩具
- **名称**：一页三槽 · 活体组件分轨台（Slot-Drop & `@container` vs `@media` Live Workbench），2D Canvas 高帧率真实排版引擎（标 `data-perf-drag`）。
- **怎么玩**：画布呈现一张**总视口固定为 1280px** 的模拟桌面网页，中央有一道可横拖的薰衣草紫实体分栏脊柱，把画面分为左「主内容槽」与右「侧边栏槽」（还可在下方「双拼中槽」同步或切换观察），**同一个组件**（支持原海报三大真实组件切换：信息卡片 / 数据统计 / 内容列表）同时住进不同宽度的槽位。用户可以直接横拖中缝改变两槽宽度配比（包括拖到左侧变窄、右侧反超变宽的翻转瞬间）、点击切换响应依据（`@media 盯视口` vs `@container 盯容器`）、拖动组件自变断点阈值（220px–720px）、点击「投递/互换槽位」或拨动「信息完整」「优先级顺序」保真开关，也能用键盘 `←/→` 拖中缝、`↑/↓` 调断点、`Space` 切机制、`1–3` 切换三类组件。
- **开场初始错态（非答案）**：刻意停在 **`@media 盯视口`**（无视侧栏仅 260px 宽，按 1280px 桌面视口硬撑横排）的经典工程事故现场——侧栏里的卡片图片被压扁、文案碎折、星级与按钮惨烈溢出裁切；四枚原海报核心原则实时灯亮起预警。
- **怎样算玩错 & 读数怎么说为什么**：由 `model.js` 从真实计算出的每个子元素矩形框与实测宽单真源核算 **6 类双向错态**：
  1. `media_blind`（视口盲区·窄槽爆框）：盯 `@media` 1280px，窄槽误判宽屏硬撑横排，导致内容挤压溢出；
  2. `threshold_low`（断点过低·该折不折）：开了 `@container` 但切换断点设太低，窄槽仍拒不重排导致挤爆；
  3. `threshold_high`（断点过高·宽槽早塌）：切换断点设过高，宽敞的主槽也过早塌成细长竖卡、浪费大片横向空间；
  4. `slot_crushed`（槽位过窄·物理失守）：把某槽挤破组件最小可读底线（< 200px），连紧凑形态也装不下；
  5. `info_dropped`（野蛮删减·信息丢失）：窄态直接藏掉评分/指标/操作按钮，违背「信息完整、保留关键操作」；
  6. `priority_flipped`（层级倒置·视觉失序）：重排时把次要操作顶到标题/主图上方，破坏「元素优先级不变」。
  多组合法解均被认可（经典宽窄双态解、侧栏反超互换解、双宽舒展解、双紧凑匀称解），读数不仅报出实测容器宽度与阈值差，更解释「为什么这样排读者能一眼扫清 / 为什么会断层」。
- **与最近 12 页的差异**：紧邻的 299 是单一大网格框拉宽改列数与 SPAN；298 是中轴立体翻折双页；254 是图文 2×3 矩阵拉内距；其余皆为不同构图与阅读器。本页独有「**全局视口锁定不变、靠拖分栏脊柱让同一组件在多槽之间此消彼长甚至宽窄反超互换**」的动作，专属于 300 号组件级响应，别的编号无法套用。

## 3. 版式骨架
忠实转译 300 原海报「深靛紫底 × 开放双翼刊头 + 薄荷波浪线 + 右上虚线重排图符 × 四枚竖线分隔核心原则实况脊 × 通栏大圆角深紫画廊框（上宽阔双槽互动台 + 下紧贴的原海报风洞察诊单与精控双栏齐底舱）」：
- **1440×900**：主宽 1360px（2560 舒展至 1680px），零通用深灰顶栏、零侧栏仪表盘箱，首屏完整呈现刊头、四原则脊、大圆角双槽画布与底舱诊单首句；不锁 `100svh`，彻底避免 1024×1366 平板竖屏大空洞。
- **390×844（手机竖屏）**：单行极紧凑刊头（NO.300 + 标题 + 状态签），右上装饰移出、总述与四原则脊移至画布下方，等比缩放的双槽画布稳占首屏 ≥ 46% 屏高，首屏折线内同屏直见 `@media / @container` 切换与洞察诊单首句。
- **844×390（手机横屏）**：切为左 55% 活体双槽舞台 × 右 45% 紧凑刊头、机制切换与洞察诊单并行布局。
- 正文 7 节在暖象牙白、薄荷雾纸、03 深靛紫暗室、微暖象牙纸、浅紫雾纸、06 深靛紫考场与 07 暖象牙展墙 + 深靛紫原海报页脚之间明暗交替推进。

## 5. 节目录（01–07）
- **01 为什么页面响应不够用**（`WHY PAGE-LEVEL FAILS`）：拆解视口响应的复用死结；交互：**原生 CSS `@container` 活体搬家盒**，一键把同一段真实 DOM 卡片投进「宽主栏 / 双栏格 / 窄边栏 / 迷你抽屉」四种真实容器，实时高亮命中的 `@container` CSS 代码行。
- **02 三大组件变形规律**（`THREE COMPONENT PATTERNS`）：承接原海报信息卡片、数据统计、内容列表三套原话要点与洞察；交互：**原生 CSS 三联组件同步/锁定拉伸廊**，同步拖宽观察三者不同经验断点的错拍重排节奏，并支持单卡锁定对照。
- **03 自治背后的代价与机制**（`HOW CONTAINER QUERIES WORK`）：深靛紫暗室，揭示「元素查询循环依赖死结」如何靠 `container-type: inline-size` 破局，及 `size` 遏制导致高度塌陷的工程陷阱；交互：**2D Canvas 布局因果与遏制模拟器**（三种模式切换：无遏制死循环 / `inline-size` 安全单向流 / `size` 全轴高度塌陷）。
- **04 从媒体查询到容器自治**（`ORIGIN & EVOLUTION`）：经联网核实的 2010→2013→2022→2023 演进史，并一句话链接 291–299 同小类姐妹页说明分工；交互：**四纪元代码演变切换器**（点击年份对照当年真实写法与维护痛点）。
- **05 什么时候用，什么时候别用**（`WHEN TO USE & AVOID`）：先展原海报四项核心价值，再温和补充海报未言明的四条边界禁区（全局宏观导航、内容撑宽元素、同排过密临界差、高密精密对账表）；交互：**四场景选型分诊卡片组**（点击真实业务场景，揭晓 `@container` / `@media` / 局部横滚的最佳决策与踩坑预警）。
- **06 眼力小练习**（`PRACTICE CHECK`）：深靛紫考场，两道「四选一、严格只差单一变量、绝不写好坏标签」的高保真微缩组件审校题，选完展开逐项剖析。
- **07 原海报与关键词**（`ORIGINAL POSTER`）：左侧原海报（点击放大、可拖、Esc 关），右侧四组关键词与金句 + 同小类 291–299 传送带 + 规范页脚。

## 7. 练习设计
- **第 1 题**：一张信息卡片被放进 1440px 桌面页的 280px 窄侧栏，四项 A/B/C/D 视觉素材一致，**仅改变内部重排策略**：
  - A：保持左图右文 1:1 横排
  - B：切换为上图下文竖排，依次呈现主图、标题摘要、星级与操作按钮（**正确**：契合窄容器宽度且保持信息完整与元素优先级不变）
  - C：切换为上图下文竖排，但把操作按钮置顶、主图沉底
  - D：切换为上图下文竖排，仅保留标题并隐藏星级与操作按钮
- **第 2 题**：四项同等权重的数据统计组件装进 300px 窄侧栏，**仅改变网格重排结构**：
  - A：维持单行四列并压缩字号硬塞
  - B：重排为 2×2 均等网格，保留数值与趋势微图（**正确**：保持四项数据关联、对齐与可扫描性优先）
  - C：重排为上 3 下 1 不对称两行
  - D：仅保留前两项并隐藏后两项
