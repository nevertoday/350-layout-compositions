01 TWO LENSES · UI VS. PRINT BLEED

拆开「越界」与「抽屉」

跨界混讲了 · 先对齐口径 一张海报其实装着两层意思：295 号排在「网页与 UI / 响应式重排模式」小类里，英文名 OFF-CANVAS PATTERN 在响应式网页中特指把导航、筛选等次级面板先放在视口之外、按需滑入屏幕的交互模式；而原海报正文却借用了平面构图的语言——越界（BLEED）、裁切（CROP）、张力（TENSION），同时又在右上角悄悄画了一块伸出右缘的朱红色三条横线抽屉耳。

把两层意思拆开看，反倒能看懂一条被 UI 教程忽略的底层联系：平面的「越界与裁切」正是让界面里「画布外抽屉」被用户一眼发现的视觉线索。

+

越界 BLEED

海报原话：元素突破画面边界，延伸视觉，暗示更大空间

+

裁切 CROP

海报原话：有意裁切部分内容，引导关注，保留想象

+

张力 TENSION

海报原话：边缘关系制造不平衡，产生动势与能量

关键关系：边界 ≠ 终点 · 边界 = 工具 · 向外，才有更多可能

02 ORIGIN · 1981 TO MODERN WEB

从哪来：三条横线三十年

三条横线在工作站里诞生三十年后，才真正遇见手机小屏——画布外模式并非拍脑袋发明的新花样，而是「窄屏装不下桌面多栏结构」逼出来的解法，前后经历了四十余年演变。点击任意年代或顺势滚动，同步查看界面形态演变图解。

1981 XEROX STAR 8010 · NORM COX

Norm Cox 在 16×16 像素格子里画下三条平行横线，用来向用户示意「这里折叠着一叠菜单选项」。

03 MECHANICS · PUSH / OVERLAY / REVEAL / SQUEEZE

四种进场动作，手感各异

同样是从画布外滑进来，四种位移机制的视觉稳定度差了一大截。拉动下面这根 0%–100% 慢动作进度轨，或一键展开，紧盯各格里的正文段落和边界线——尤其看第四种「挤压重排」反例，文字是怎样在动画半途疯狂跳行抖动的。

1. 推挤 PUSH

GPU transform · 零跳行
目录
≡主画布

边框不是终点，推开后右缘露出截断正文，一眼知道往回一划就能归位。

抽屉与主画布像拼接在一起的硬纸板同步平移，空间连贯感最强，对侧露出的裁切边就是天然返回把手。

2. 浮层 OVERLAY

M3 默认 · 零位移
≡主画布

主内容停在原地纹丝不动，深蓝遮罩压低亮度，让视线立刻锁在浮出的抽屉上。

目录

抽屉凌空滑过主画布上方，完全不扰动底下排版；最适合筛选器、临时菜单与移动端模态导航。

3. 掀开 REVEAL

双层纵深 · 经典手势
目录
≡主画布

抽屉本来就压在底层，拉开的是上层主画布本身，像掀开一页纸露出背后的夹层。

Path 与早期 Facebook 的成名手法；注意给上层主画布左缘加清晰边界线或投影，否则两层文字容易混在一起。

4. 挤压重排 SQUEEZE

反例 · 触发布局抖动
目录
≡主画布

如果用修改宽度硬挤主画布，每拖动一像素文字就重新折行跳动，手机帧率也会掉下去。

窄屏里绝对不要靠缩窄 width 腾出抽屉位：每帧都触发排版重算（Reflow），文字狂跳，眼睛根本抓不住读到哪一行。

  • 291 大体流动模式：宽屏锁住最大行宽、窄屏顺势堆叠。
  • 292 列下落模式：屏宽不够时把整列依次落到下方。
  • 293 布局切换模式：不同断点直接换用差异最大的独立结构。
  • 294 微调模式：本身单列，跨屏仅微调字号与留白。
  • 296 堆叠重排：把横排多块按阅读优先级转为纵向堆叠。
  • 297 顺序重排：小屏里调换区块视觉先后，把核心内容提上来。
  • 298 折叠双窗格：为折叠屏折痕左右分置主副双窗格。
  • 299 自适应网格：卡片列数按可用轨道宽度自动增减。
  • 300 组件级响应布局：由容器自身宽度而非整页视口决定重排。
06 ENGINEERING GUARDRAILS & WHEN TO SKIP

工程底线与什么时候别用

工程防踩坑实测 · ACCESSIBILITY CHECK

对比「忘加 inert 的坏抽屉」与「规范抽屉」

底层页面
模拟抽屉

试试点「模拟按 Tab」或点击遮罩

先点测试框里的「≡ 打开测试抽屉」，再试着点「模拟按 Tab」或「模拟按 Esc」，看焦点会不会漏到底层危险按钮上。

  • 1. 背景加原生 inert：模态抽屉打开后，禁止键盘与读屏器穿墙点到背后的按钮。
  • 2. 宽度留出逃生缝：手机端经验值占屏宽 80%–85%，留 ≥ 48 px 可点遮罩；宽屏抽屉参考 Material Design 3 上限 360 dp。
  • 3. 关完还焦点、尊降动：按 Esc 或点遮罩关闭后焦点回到原触发钮；prefers-reduced-motion 下取消位移滑动。

适合用画布外 USE IT

  • 窄屏多级导航或复杂筛选电商多维度筛选项、文档长目录，在手机上不能堆满首屏，收进画布外按需拉出最清爽。
  • 沉浸式阅读器与创作画布电子书目录、画板图层栏平时退居边界之外，把每一寸像素留给阅读与创作。
  • 跨设备同一套多栏骨架手机停在边界外、平板左栏常驻、桌面三列摊开——一套 DOM 顺应不同屏宽。

什么时候别用 SKIP IT

  • 桌面宽屏空间充裕却藏起主导航顶部明明空着几百像素，仍把 4 个一级栏目塞进左上三条线，等于让主导航的使用率几乎腰斩。
  • 核心频道只有 3–5 项的手机应用高频主切换应直接放进底部标签栏，不要藏在左手大拇指够不到的左上角抽屉里。
  • 需要与正文实时并排对照的辅助信息批注、属性检查器或双屏协作应优先常驻分栏，折叠屏见 298 折叠双窗格。
  • 原本就只有单列内容的轻量页面没有侧栏负担的文章或着陆页，用 294 微调模式 就够了，别凭空造一个空抽屉。
  • 结账确认、错误提醒或必选步骤绝不能把关键转化路径藏到边界之外，用户看不见就会直接流失。
07 PRACTICE · SPOT THE WORKING DESIGN

小练习：哪一稿真能上线

场景：为一份跨设备线上设计期刊规划高频「目录导航」与低频「筛选面板」（同时交付 375px 手机与 1280px 桌面两套断点）。四份方案都很工整，但其中三份各自只错了一个变量——逐一比对双端再选。

点选四份稿里唯一双端变量全对的一份。

提示：重点逐一对照三个变量——① 375px 展开抽屉后有没有返回锚点；② 1280px 宽屏有没有白白把导航藏起；③ 宽屏常驻位究竟留给了高频主目录还是低频筛选。
