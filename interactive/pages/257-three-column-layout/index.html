01

为什么分成三列

WHY THREE COLUMNS

原海报用一句话概括三列页面：「内容分为三部分，结构清晰，节奏明快。」从一列到两列再到三列，不只是多切了一条缝——255 单列页面服务单一线性叙事，256 双列页面建立两项成对对照，只有走到三列，屏幕才第一次拥有「中心舞台 + 左右双翼」或「三档并行比较」的奇数结构弹性。

① 左列锚定目录 → ② 中列聚焦核心 → ③ 右列轻量补充

对称中轴：让眼睛直落中间主角

像原海报第一幅图那样，用左实、中橙圆、右疏点的视觉重量差，把读者的第一眼锁定在正中核心区，左右两列分别退作导航坐标与轻辅助。

典型落点：新闻专题页、知识文档、邮件与文档工作台。

说多了一点

原海报写「三列分布均衡，左右视觉更稳定」——这句话容易让人误以为三列必须死板三等分（33% : 33% : 34%）。实际上，视觉均衡不等于几何等宽：当三列承担不同职责（如目录 + 长文 + 图注）时，20 : 56 : 24 或 48 : 28 : 24 的非对称配比反而更稳、更易读；只有在三项内容权重完全平行（如三档方案对比、三位成员介绍）时，等宽三列才是最优解。

03

三列从哪来

FROM ZURICH PRINT TO CSS GRID

三列不是网页时代的突然发明，它从瑞士战后多语种杂志的排字架一路走进浏览器规范，每一次技术跨越都在解决同一个难题：如何在有限幅面里让三股信息互不吞噬。

04

屏幕变窄怎么折叠

RESPONSIVE COLLAPSE RULER

纸媒页宽印完就不变，网页视口却能从 1440px 一路缩到 360px。W3C WCAG 2.1（1.4.8 视觉呈现）标明了中文单行不超过 40 汉字的阅读上限，而经验上单列正文低于约 180px 时每行只剩七八个字，同样难读。拖动下方视口卡尺，对比三种折叠策略。

05

什么时候别用三列

WHEN TO USE & WHEN TO AVOID

三列擅长并行展示与功能分治，但绝不是“信息多就硬塞三栏”的万能模板。下面 6 个真实需求，先替每个需求拍板「适合三列」还是「换别的布局」，看看理由对不对。

别硬用 01

沉浸式线性长文

散文、深度报道或故事型页面追求一气呵成，左右多出两列只会制造眼球分流。直接用 255 单列页面。

别硬用 02

天生只有两股信息

只有「左图右文」或「A/B 对照」时，硬凑第三列往往会塞进无用的推荐标签。改用 256 双列页面 或 259 分屏布局。

别硬用 03

高密度主从切换与工作台

若第三列只是偶尔展开的检查器，或主任务是左侧列表点选看右侧详情，专用框架更贴手：见 267 列表—详情布局、268 辅助窗格布局 与 260 圣杯布局。

别硬用 04

窄屏表单与重首屏冲击

手机端分类多时用 265 标签页布局 或 266 手风琴布局；需要通栏大视觉开场时用 261 页眉—主体—页脚 或 262 顶部导航布局。
