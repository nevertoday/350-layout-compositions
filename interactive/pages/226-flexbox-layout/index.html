01

一根主轴，九十度旋转

MAIN & CROSS AXES

普通流里，块级元素天生竖着摞，行内元素天生横着排；弹性盒先废掉「上下左右」，只认一根主轴和垂直于它的交叉轴。

普通文档流的默认堆叠与行内排列分别见 222 普通流布局、223 块级布局 与 224 行内布局。

原海报要点：「主轴方向 flex-direction」「主轴对齐 justify-content」「交叉轴对齐 align-items」

横排主轴（row）：justify-content 管左右分配，align-items 管上下对齐。

试着在罗盘里切到 column，再点同一组 space-between 或 center——你会亲眼看见两个属性的管辖方向跟着主轴一起旋转了 90 度；切到 baseline 时，三个大小不同的字母 A 会自动对齐文字底脚。

为什么记不住谁管横谁管竖？

因为记「水平/垂直」本身就是错的。永远记住 justify 管主轴，align 管交叉轴——主轴朝哪走，它俩就跟着转。

三种分散间距的细微差别

space-between 两头贴墙；space-around 项间空隙是两侧边缘的 2 倍；space-evenly 连两侧边缘和项间缝都严格等宽。

02

伸缩三件套怎么算账

GROW · SHRINK · BASIS

容器比内容宽，按 flex-grow 分余量；容器比内容窄，按 flex-shrink × flex-basis 加权分赤字——而所有计算，都从 flex-basis 出发。

原海报要点：「弹性分配 flex-grow: 1 / 2 / 1」「固定与自适应 flex: 1 1 200px / 1 1 auto / 0 0 100px」

实战里最常踩的坑，是把 flex: 1（等价于 1 1 0%，先归零再平分全宽）和 flex-grow: 1（保留 basis: auto，只平分剩余空间）当成同一件事。

03

换行后，行轨归谁管

WRAP & ALIGN-CONTENT

默认状态下弹性盒死守一行（nowrap）；打开 wrap 折出多行后，容器里会多出一层新对象：每一条弹性行。

温和补充

原海报「一行排列（默认不换行）」把 5 个红块工整画在框内，仿佛 nowrap 永远不会出事。实际上，一旦子项多过容器能承受的最小宽度，默认不换行并不会自动折行，而是直接撑爆容器边界。

记住两兄弟的分工：align-items 管行内单项，align-content 管多行之间。只有 1 行时，align-content 彻底休眠。

04

从补丁时代到弹性标准

WHERE FLEXBOX CAME FROM

在弹性盒成熟之前，为了把一段文字垂直居中或让侧栏与主区等高，前端工程师借用过 230 表格布局、用过 231 浮动布局 配清除补丁（如今已由 225 流根布局 替代），也用过 233 绝对定位布局 加负边距硬算。标准本身也经历了三次语法推倒重写，才走到今天的两行代码。

2009-07-23 · W3C Working Draft

从 XUL 走出的第一代 box 语法

W3C 发布首份 Flexible Box Layout Module 工作草案，编辑为 Mozilla 的 L. David Baron，早期作者还包括 Neil Deakin、Ian Hickson 与 David Hyatt。它脱胎于 Firefox 界面使用的 XUL 盒模型，语法写作 display: box 与 box-pack、box-orient，虽在早期 WebKit 与 Gecko 中实验落地，但架构扩展性受限。

出处：W3C Flexible Box Layout Module (WD-css3-flexbox-20090723)

当年写法（2009 草案）

.bar {
  display: -webkit-box;
  display: -moz-box;
  -webkit-box-pack: justify;
  -webkit-box-align: center;
}

今日标准写法

.bar {
  display: flex;
  justify-content: space-between;
  align-items: center;
  gap: 12px;
}

05

原海报整页怎么搭

NESTED 1D COMPOSITION

原海报右下角的「综合示例（应用）」看似是一张完整的二维网站，拆开以后，它其实是 4 个一维弹性盒层层套娃的结果。

温和澄清

口号「一个维度，多种可能」不是说一个 display: flex 能同时管横纵二维——它一次只管一根轴。真正搭出完整页面，靠的是外层用 column 管上下骨架，内层各带再用 row 管左右分配。

若要让顶栏吸顶或随屏宽换列，只需把这套一维骨架与 234 固定定位布局、235 粘性定位布局、240 响应式布局 或 242 容器查询布局 配合。

L0 整页外壳：主轴竖排（flex-direction: column），把顶栏、中区、三卡与页脚从上到下连成一列。

把页脚自动压在视口最底（俗称粘底页脚），只要给中间区加 flex: 1，或给页脚加 margin-top: auto 就能办到，彻底不用算高度。

什么时候别用弹性盒

WHEN NOT TO USE FLEXBOX

弹性盒强在一维内容驱动，一旦拿它硬扛二维对齐、长串不折行文本或视觉重排，就会露馅。跨行严丝合缝请交由 227 网格布局 与 228 子网格布局；报纸式流淌分栏看 229 多栏布局，不等高卡墙看 236 瀑布流布局，图文绕排与叠层定位看 231 浮动布局、232 相对定位布局 与 237 覆盖布局。

原因：W3C 规范让弹性子项默认带自动最小宽度（min-width: auto），防止内容被压成零。但遇到长 URL 或不换行标题时，它反而会让 text-overflow: ellipsis 失效，给该弹性子项补一句 min-width: 0 即可解套。

小练习：谁会拿到多宽？

PRACTICE · PREDICT THE WIDTH

检验一下你是否真正看透了 flex-grow 与 flex-basis 的关系。先别翻回上文，凭手算选一个答案。

一个宽 600px、无内边距、无间距（gap: 0）的横向弹性容器里放着两项：甲项文字自然宽 60px，乙项文字自然宽 240px。两项都只写了一句 flex-grow: 1（未改写 flex-basis）。渲染后甲、乙两项的实测宽度分别是多少？

.container { display: flex; width: 600px; gap: 0; }
.a, .b     { flex-grow: 1; /* flex-basis 保持默认 auto */ }

点选上方 A / B / C / D，立刻启动真实 Flexbox 同比例拆账验证。
