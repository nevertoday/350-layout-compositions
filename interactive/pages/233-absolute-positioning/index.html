脱离文档流发生了什么

            
REMOVED FROM FLOW · SPACE COLLAPSE VS OVERLAY

          

        


        

          

            

              原海报要点 · 脱离文档流
              「不占用空间，不影响其他元素布局」
            

            
在 222 普通流布局 里，块级盒子像书架上的书一样按顺序排座，每人占着自己的身高。切到 232 相对定位布局 时，元素人走位、坑还在原地。

            
只有 position: absolute 会把元素彻底提离书架：后面的兄弟块立刻往上补位，仿佛它从未存在。也正因为不占高度，这里要给原海报补充一点——

            

              补充一点
              
虽然它不推开兄弟元素，但如果一个父容器里全部子元素都写了 absolute 且父级没写死 height，父容器就会因为「里面没东西撑着」而直接塌成 0px，背景和边框瞬间消失。

              原海报要点 · 参照容器
              「相对于最近的已定位祖先（非 static）」
            

            

            

              不止这一种
              
原海报讲的是最经典规则。现代 CSS 规范（MDN 包含块规则与 CSS Positioned Layout 3）里，哪怕祖先仍是 position: static，只要挂了非 none 的 transform、filter、perspective、backdrop-filter，或 contain: layout / paint，它也会静悄悄变成包含块，把后代的 absolute 甚至 234 固定定位 都拦在自己框内！

            

            
另一个容易忽略的细节：参照起点是包含块的 padding 盒内沿（紧贴边框内侧），不是 content 盒。所以即使卡片写了 padding: 16px，top: 0; right: 0 依然会贴到边框内侧，不会被 padding 推开。

现代 CSS Positioned Layout 3 提供简写 inset: 24px（等价四边同值）；经典蒙层和 237 覆盖布局 常靠 inset: 0 一行铺满父框。

                等轴测图层剖面 · 侧看 Z 轴
                弹窗被 B 截断
              

              
            

            

          


          

            

              原海报要点 · 层叠控制
              「通过 z-index 控制叠放顺序」
            

            
很多工程师都踩过这个坑：把卡片 A 里的下拉弹窗调到 z-index: 9999，它却死活盖不住旁边 z-index: 2 的卡片 B。原因不是数字不够大，而是层叠比较只在同一个「层叠上下文」内部有效。


            

              

                父容器 A 是否封屋（建层叠上下文）
                

                  
                  
                  
                  
                

              


              

                

                  弹窗 A（在父 A 内）
                  

                    
                    9999
                    
                  

                

                

                  邻居容器 B
                  

                    
                    2
                    
                  

                

              

            


            
切到 「auto 不封屋」 试试：只要父容器 A 不创建独立层叠上下文，弹窗 A 的 z-index 立刻和邻居 B 进入同一间房比高低，不用盲目堆到 999999。
