01

为什么分出一条边道

WHY A SIDEBAR WORKS · COGNITIVE OFFLOADING

海报把侧栏版式的价值压成八个字：「内容优先，层次清晰」。人眼在连续阅读时最怕频繁跳出主线：正文里每插进一段名词解释、一串标签或一条章节跳转，读者就得打断语流，重新找回刚才读到哪一行。把这些「偶尔要瞄一眼、但绝非句句必看」的信息剥到页面一侧，主栏立刻干净，辅栏也随时待命。

02

左栏还是右栏

LEFT VS RIGHT RAIL · ATTENTION BIAS

尼尔森诺曼集团（Nielsen Norman Group）在 2010 年与 2017 年的眼动研究（Horizontal Attention Leans Left）发现，从左向右阅读的桌面用户约把八成注视时间停留在页面左半边，右半边仅分得约两成；其 2021 年针对桌面竖向导航的研究（Left-Side Vertical Navigation on Desktop）进一步指出，高频跨页目录放在左侧更容易扫读定位。反过来，长年累月的右侧广告位也养出了「右栏盲视」——凡是贴在最右窄条里的按钮或公告，用户常会下意识过滤掉。

契合左倾扫读

高频导航放左侧，视线落地就能定位

复杂文档或后台系统里，用户每完成一步就要切频道。把目录锚在左侧，贴合从左到右阅读的起笔位置，无需横穿整块内容就能快速跳转。

经验选边法则
  • 左侧栏：全局目录、文档树、筛选器等「先选后看」的导航工具。
  • 右侧栏：术语注释、本页小纲、相关阅读等「边看边瞄」的陪伴信息（如 156 原海报）。
  • 慎用双侧栏：除非屏幕足够宽且中间主栏仍保住 600px 以上，否则三列夹击会让正文沦为窄缝。

若注释必须逐行精确钉在对应句子旁，见 157 边注版式；若文字顺着核心图像轮廓绕行，见 158 环绕图版式；若模块脱离分栏网格自由悬浮呼吸，见 159 浮动块版式。

03

从宽切口到内在弹性

WHERE IT CAME FROM · PRINT TO INTRINSIC CSS

侧栏并非网页时代凭空冒出来的界面零件。从古典书页预留宽阔外切口（outer margin）安放批注与提要，到现代前端写下无需媒体查询的弹性侧栏原语，跨越几百年的核心追问始终没变：主栏需要多宽才好读，辅栏什么时候该让路？

  1. 1992

    纸书比例里的「有宽度的边白」

    加拿大排印学者 Robert Bringhurst 在 The Elements of Typographic Style（Hartley & Marks，1992 年初版）里系统梳理了书页版心与外切口比例：宽阔的外侧边道不仅保护正文行长落入舒适区间，也天然成为提要、图注与参考索引的栖身之处。

  2. 2006

    网页「圣杯布局」守住主文优先

    2006 年 1 月 30 日，Matthew Levine 在 A List Apart 发表 In Search of the Holy Grail。在缺乏现代栅格的年代，他用负外边距与浮动实现「流动主栏 + 定宽侧栏」，并首次做到在 HTML 源码里让主内容排在侧栏前面——让屏幕阅读器与搜索爬虫先读主角。

  3. 2014

    HTML5 确立 <aside> 语义标签

    2014 年 10 月 28 日成为 W3C 正式推荐标准的 HTML5（以及持续演进的 WHATWG HTML Living Standard）专门定义了 <aside> 元素：只用于与周边正文「间接相关、可独立看待」的旁支内容，规范原文直接注明「在印刷排印中常呈现为侧栏（sidebars）」。

  4. 2018

    WCAG 2.1 划定 320px 重排红线

    2018 年发布的 W3C WCAG 2.1 在成功准则 1.4.10（Reflow）中要求：在相当于 320 CSS 像素宽（1280px 桌面放大 400%）的竖向流里，页面不能出现横向滚动条，也不得为了挤进去而直接丢掉信息——这迫使侧栏必须具备安全的退场机制。

  5. 2019

    Every Layout 提出无断点内在侧栏

    2019 年，Heydon Pickering 与 Andy Bell 在 Every Layout 的「The Sidebar」原语中提出不依赖 @media 视口断点的写法：给侧栏设 flex-basis，给主区设 flex-grow: 999 与 min-inline-size；只要容器缩到主区守不住下限，浏览器自己把侧栏折到下方。

04

四条要点与工程现实

DESIGN GUIDELINES & PRACTICAL NUANCES

156 原海报右下角那张斜贴着橘色胶带的纸条，总结了四条非常管用的「设计要点」。放到真实的大屏显示器与小屏手机里落地时，有两条值得再补上一句工程提醒。

01 不只是看百分比

「侧栏宽度适中，避免喧宾夺主」

桌面端经验参考带通常在 20%–36%（156 原海报约 68% : 32%）。但如果只写死 width: 30%，在 2560px 超宽屏上侧栏会吹胖到 768px——比平板还宽！工程里常改用 clamp(240px, 26%, 340px) 既保小桌可读又给超宽封顶。

02 原话正中要害

「内容分组清晰，留白舒适」

侧栏天生偏窄，一旦把不同用途的文字、数字与按钮糊在一起，扫描速度立刻归零。像 156 原海报右侧那样用细虚线与图标把 2–4 组信息隔开，每组只放一句短说，留白比塞满更有用。

03 对比不等于撞色

「视觉统一，风格与主内容协调」

原海报右栏虽然反色用了深普鲁士靛，但文字、图标圆徽与橘色点缀完全来自左主区的山日配色。好的侧栏对比靠明度差或细线切出边界，而不是贴一块毫不相干的霓虹广告牌。

04 说宽了一点

「移动端可折叠或隐藏，按需呈现」

「折叠按需呈现」很对，但「直接隐藏（display: none）」要极其小心：如果侧栏里放着章节目录、术语定义或筛选项，手机端直接删掉不留入口就会造成信息丢失（触碰 WCAG 1.4.10）。只该彻底隐藏纯装饰模块。

长文滚读：静态空洞 vs sticky 伴行

第一段 · 起步　当主内容长达两三千字，读者一路往下滑时，顶部的目录很快就会滚出视野之外。

第二段 · 中段阅读　如果侧栏只有短短三百像素且原地不动，右侧从此处开始便会拖出一长条空白死区，版面显得头重脚轻。

第三段 · 查词对照　读者中途想回头看某个章节标题或术语注释，只能放弃当前位置滚回页顶，再费力找回刚读到的段落。

第四段 · 尾声收束　把较短的侧栏设为 position: sticky 后，边栏目录始终安静悬在视野侧方，既消除了长条空洞，也让跳转一步到位。

05

什么时候别用侧栏

WHEN NOT TO USE A SIDEBAR

侧栏是一把锋利的层次工具，但绝非每个页面都要硬塞一条边栏。下面四种场景里，撤掉侧栏反而能立刻救回体验——点按任意卡片，对照「硬加侧栏」与「改用专注流」的版面差异。

反例 01 · 沉浸叙事

摄影画册与全出血故事页

常驻深色侧栏像一堵竖墙，硬生生砍掉三成画面呼吸，把全景照片和叙事节奏截成憋屈的方框。

反例 02 · 单步转化

结账、注册与长表单填报

表单任务需要线性推进到底。旁边摆满频道导航和推荐商品，等于亲手递给用户一排离开页面的逃生门。

反例 03 · 窄幅短文

短公告与窄屏移动端主面

正文一共不到两百字，或者屏幕本就不到 600px，硬拆侧栏只会让主文碎成三四字一行，边栏还空荡荡没话可写。

反例 04 · 关键动作

把核心按钮或告警塞进右栏

右栏盲视会让读者自动把右侧小卡片归为广告或补充信息。凡是必须完成的操作与报错提示，都必须留在主阅读轴里。
