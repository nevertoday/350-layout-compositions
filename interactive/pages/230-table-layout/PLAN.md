# 230 表格布局（TABLE LAYOUT）互动版方案

## 1. 一句话道理
表格的本质不是“画满格线的方框”，而是用**行（记录）× 列（属性）的二维坐标**，把多维同构数据对齐到同一套视觉标尺上，让眼睛只靠顺列直扫与按行定位，就能在毫秒间完成查值与对比。

## 2. 开场玩具：活体表盘排版室（Live Table Specimen）
- **形态与动作**：主角是一张真正可交互、可排序、可实时拖改列宽的原生语义 HTML `<table>`（直承 230 原海报的深梅紫底、紫晶表头、香槟焦点块与玫瑰汇总行），外覆极轻 2D Canvas 测绘层（实测 DOM 列宽标尺、原海报同款粉色虚线 `列/行` 维度括号、选中单元格的行列坐标连线，以及数字对齐错位时的锯齿折线）。
- **开场初始态（0 / 5 错版，绝不先给答案）**：
  1. `table-layout: auto` + 第 4 行混入一条超长说明文，劫持列宽把项目列与数字列挤扁；
  2. 对齐方式为「全部居中」+ 比例数字，数字个位与小数点左右锯齿漂移；
  3. 隔线密度为「重铁笼全框」，20 个单元格被粗亮竖横线关进牢笼；
  4. 层次结构为「乱合并数据区」，一块跨列跨行合并块直接压在原始数据上，打断列顺序且锁死表头排序。
- **怎么玩 & 怎样算玩错**：
  - **拖列宽标尺（`data-perf-drag`）+ 切 `auto/fixed`**：拖太窄（首列 < 26%）触发「首列挤折/截断」；拖太宽（首列 > 50%）触发「挤压数值列」；停在 `auto` 仍受长文劫持；切 `fixed` 并将首列拖进经验平衡带（26%–44%）列宽才稳。
  - **切对齐与等宽数字**：切「全部居中」画布亮出个位锯齿偏移；切「全部左对齐」读数点破位数错觉（`980` 压在 `14,260` 左侧显得更大）；仅切「文字左·数字右」不开 `tabular-nums` 仍有字宽微抖；两者配合，锯齿归零成笔直铅垂线。
  - **切隔线密度**：「重铁笼全框」数据墨水比过低；「全无隔线」宽行易跨行串读；「仅横线留白」兼顾行引导与洁净。
  - **切结构层次 & 点击表头排序**：在「乱合并数据区」下点表头排序会被拦截并解释为何正文合并破坏列完整；切「平铺无层次」则表头、记录与汇总混作一团；切「语义分层 + 汇总」后恢复表头排序与汇总区分，实时点亮原海报底沿 5 柱（行 / 列 / 单元格 / 对齐 / 结构）。
- **与最近 12 页的区分**：
  - 不同于 229（多栏连续文本报样）、273（深灰遥测仪表盘三层重排）、228（子网格双层嵌套穿轨）、145（多面板二分拼版）以及其余构图画布拖拽；230 是全库首个以**原生语义 `<table>` 的列宽算法、数字铅垂对齐、墨水减法与排序约束**为核心动作的活体表盘实验台。

## 3. 版式骨架
- **承袭 230 原海报的通栏纵轴建筑报表骨架**（无侧边工具栏、不锁 `min-height: 100svh` 避开平板空洞）：
  - **1440×900（2560×1440 扩宽至 1720px）**：极细顶眉 → 居中示范大标「表格布局」（「局」字内框嵌入原海报同款 4×3 白色表格线框）+ 粉色圆点横线总述 → 通栏活体表盘（上方一体列宽拖尺 `data-perf-drag` 与紧凑单行操控条，中段带原海报粉虚线括号的语义表格与 Canvas 测绘层，下方原海报同款香槟底诊断条与 CSS 声明）→ 紧接原海报 5 柱竖线分隔验收条（行/列/单元格/对齐/结构）。
  - **1024×1366 / 768×1024**：自然流式下接 01 节，不出现大块空白。
  - **390×844（手机竖屏）**：压紧顶眉与示范大标，让列宽拖尺与活体表盘首屏稳占 ≥ 46% 屏高，下方同屏可见香槟诊断条与核心按钮，表格窄屏内紧凑排布零横向溢出。
  - **844×390（手机横屏）**：切左 58% 活体表盘与列宽拖尺 × 右 42% 操控与香槟诊断并行。

## 5. 节目录（共 9 节，H2 均 ≤ 12 字，相邻节交互不重样）
1. **01 一张表的五块骨架** (`Anatomy of a Table`)：原话引用海报五要点，交互为「原海报 5×5 几何矩阵语义解剖器 + 读屏器播报预览」。
2. **02 左文右数与等宽数字** (`Alignment & Tabular Figures`)：阐释对齐与等宽数字如何让眼睛垂直比较大小，交互为「2D Canvas 扫视路径对比仪 + 有效数字取整滑杆」。
3. **03 自动还是固定列宽？** (`Auto vs Fixed Algorithm`)：讲清 CSS `table-layout: auto/fixed` 与 `border-collapse`，交互为「脏数据注入压力测试（左右双表实时对照）」。
4. **04 格线减法与合并边界** (`Data-Ink & Cell Spans`)：引入数据墨水比并温和补充海报「合并单元格」的适用边界，交互为「4 步渐进洗格线阶梯 + 表头/正文合并安全性对照」。
5. **05 窄屏怎么放宽表格？** (`Responsive Table Patterns`)：拆解宽表进手机的四种取舍，交互为「可调屏宽移动模拟器 + 4 种响应策略切换（含首列冻结粘性定位）」。
6. **06 从账本到语义回归** (`Origins & History`)：梳理 1977–2004 表格排版学与 Web 表格标准演进，交互为「年代节点源码切片对比（1996 嵌套表格 vs 现代语义表）」。
7. **07 什么时候用，何时别用** (`When to Use & Avoid`)：给出清晰选型清单并链接同小类兄弟页，交互为「6 场景交互分诊卡」。
8. **08 小练习：挑出最好读的表** (`Practice Quiz`)：四张同数据集报价表，仅差一个变量，中性标号 A/B/C/D。
9. **09 原海报与关键词** (`Original Poster & Keywords`)：可放大拖动原海报灯箱 + 海报三关键词与标志性香槟底封签。

## 7. 练习设计
- **题目**：同一份 4 档云服务月度费用对照表，以下四张表哪一张最适合快速对比价格与额度？
- **四选项（中性编号，每项与正确解仅差一个变量）**：
  - **方案 A**：轻横线留白、表头清晰，但数值列改为**左对齐**（十位与千位错位，一眼看错量级）。
  - **方案 B**：文字左对齐、数字右对齐且等宽，但加上**全框重竖线铁笼**（网格噪点压过数字）。
  - **方案 C（正确）**：文字左对齐、数字右对齐 + 等宽数字、表头随列对齐、仅用柔和横线与留白分组。
  - **方案 D**：轻横线留白、等宽数字，但数值列改为**居中对齐**（个位与小数位左右漂移，无法顺列直扫）。
