01

一张表的五块骨架

ANATOMY OF A TABLE

原海报把表格拆成五个词：行、列、单元格、对齐、结构。很多人把表格当成「画满格子的框」，其实它是一套二维坐标系统——横轴锁定同一条记录，纵轴锁定同一种属性，两者交汇处才是最小的数据单元。

语义与无障碍价值

  • 行「水平排列的数据集合，表达记录或项目」
  • 列「垂直排列的字段集合，表达属性或类别」
  • 单元格「行与列的交集，存放最小数据单元」
  • 对齐「统一对齐方式，提升可读性与美观」
  • 结构「清晰的表格结构，让信息一目了然」

02

左文右数与等宽数字

ALIGNMENT & TABULAR FIGURES

为什么专业报表几乎都遵守「文字左对齐、数字右对齐、表头随列对齐」？因为阅读文字靠左缘起笔，而比较数字靠个位、千分位和小数点纵向排成一条铅垂线。一旦开启 CSS 的 font-variant-numeric: tabular-nums，每个数字占宽相同，大小高低从宽度轮廓上一眼便知。

03

自动还是固定列宽？

AUTO VS FIXED ALGORITHM

W3C CSS 2.1 第 17 章规定了两种表格列宽算法。默认 table-layout: auto 必须先扫完所有单元格内容再反推列宽——只要某一行突然闯入一串长单号或 URL，整张表就会瞬间跳动失形。换成 table-layout: fixed 后，浏览器只看 <col> 与第一行宽度，加载更快，列轨纹丝不动。

04

格线减法与合并边界

DATA-INK & CELL SPANS

Edward Tufte 在 1983 年提出「数据墨水比」：把不传递数据的厚框逐层擦掉，数字自己就会跳出来。至于原海报中心提到的「合并单元格，突出重点信息」——补充一句这在表头分组或静态海报摘要里很有效，但在需要排序、筛选或复制的真实正文数据区里，跨格合并反而会打断列坐标。

06

从账本到语义回归

ORIGINS & WEB STANDARDS

网页里的表格走过一条耐人寻味的弯路：它诞生于统计与账本排版的理性传统，在 1990 年代末却被当作整个网页的拼版脚手架，直到 CSS 布局体系成熟，才终于卸下包袱、回到「结构化数据」的本位。

07

什么时候用，何时别用

WHEN TO USE & AVOID

判断一张界面该不该用表格布局，只要问一句话：读者是否同时依赖「所在行」和「所在列」来理解每一个格子？如果是，用原生 <table>；如果只是想把元素排齐，请交给现代 CSS 布局家族里的专职成员。
