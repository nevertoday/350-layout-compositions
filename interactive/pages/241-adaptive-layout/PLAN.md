# 241 自适应布局（ADAPTIVE LAYOUT）互动页方案

## 1. 一句话道理
自适应布局预先为不同屏幕区间准备几套定宽且结构独立的模板，在跨过档位门槛时整套切换、在档位内保持稳态不硬拉，从而用可控的设计版本换取每个目标设备上的清晰信息层级与一致体验。

## 2. 开场玩具：「阶梯换装分拣台」
- **怎么玩**：
  - 核心画布（`#rail-canvas`，标 `data-perf-drag`）直接化用 241 原海报底沿的「贯穿白虚线 + 白环黑芯轨道」，升格为**可左右拖拽的实机视口探测尺与阶梯响应示波轨**（320–1440px，支持鼠标/触屏横拖、方向键 `←/→` 微调，并可直接点选 7 台真实抽样设备或拖拉 M/L 门槛旗标）。
  - 轨道上方 1:1 排布原海报三座**奶油宣白预设模板槽**（小屏 S / 中屏 M / 大屏 L），槽内展示活体 UI 骨架（支持切换「原海报蓝图 / 资讯门户 / 电商货架」三题材），直接点击槽内列数按钮即可实时重配该套模板的列数与导航结构，且同步联动下方四维分拣控槽。
- **开场初始态（0/4 翻车错态，绝不先给答案）**：
  - 来访视口默认落在 `700px`，同时存在 4 处典型自适应工程事故：① 误开「硬拉伸单一模板」策略；② M 门槛设在 `540px`（早于 M 模板定宽 `768px`，致 640/700px 屏幕横向溢出）；③ L 门槛拖到 `1420px`（1280px 大屏滞留 M 模板出现大面积留白黑洞）；④ 小屏 `320px` 模板硬塞 4 列（单列 66px 碎裂）且大屏 `1200px` 仅排 2 列（单列过宽）。
- **怎样算玩错、读数说什么「为什么」**：
  - 所有指标由 `model.js` 从当前策略、门槛、三套模板定宽/列数与 7 台真实抽样设备（320/390/640/768/1024/1280/1440）单真源实算，可主动踩出 8 类错态：硬拉伸失真、门槛早于定宽致横向溢出（`T < W`）、门槛过晚致留白黑洞、门槛倒挂架空中屏、小屏多列碎裂、中屏列宽失衡、大屏少列臃肿、导航形态错配。
  - 读数直接用白话解释视觉后果（例如「切进 768px 模板却只有 700px 视口，右边 68px 被直接切在屏外，手指必须左右来回拖」），接受原海报解（320/768/1200）、现代紧凑解（360/720/1080）及任意满足 4 条无错条件的自调解。
- **与最近 12 页及相邻页的差异**：
  - 238 测单个固定容器宽度；239 测连续百分比流体三轨；240 测同一套响应式代码在三台硬件上的双切刀安全带。241 独有的动作是**在阶梯函数示波轨上拖动来访视口观察离散跳档，并独立拆改三套预设模板的定宽、门槛与内构列数**，换到别的编号完全无法套用。

## 3. 版式骨架
- 忠实承袭 241 原海报「全出血信号朱红橘底 × 顶部不对称刊头与右上蓝圆奶油弧点阵 × 全宽三阶梯奶油模板卡与虚线黑箭头 × 贯穿白虚线白环轨道 × 底沿奶油三圆蓝徽与几何压脚」海报骨架，零深色仪表盘侧栏感，不锁 `100svh`。
- **1440×900**：主栏宽 `1360px`（2560 舒展至 `1720px`），紧致刊头下直接完整展开三座阶梯奶油卡、阶梯示波拖轨、左右分栏奶油诊单与分拣控槽。
- **390×844（手机竖屏）**：收紧单行刊头、隐藏纯装饰大圆弧，首屏优先呈现「当前命中模板活体预览 + 三档紧凑切槽 + 2D Canvas 阶梯示波拖轨」（稳占首屏 ≥46% 屏高），同屏露出诊单首句，所有卡片等比不压扁。
- **844×390（手机横屏）**：切为左 58% 活体阶梯卡与示波拖轨 × 右 42% 紧凑刊头、白话诊单与核心切钮并行，一屏无溢出。

## 5. 节目录（8 节，标题均 ≤12 字，相邻节交互不重复）
- **01 海报上的三把锁**（`Three Pillars`）：拆解预设版本/按屏切换/多套模板原话，温和校准「而不是拉伸内容」的边界；交互：三枚原海报蓝徽卡片点击解剖。
- **02 阶梯换装与连续拉伸**（`Stepped vs. Fluid`）：划清固定宽度(238)/流体(239)/响应式(240)/自适应(241)/容器查询(242)的边界；交互：单滑条双联同步压测（连续响应式 vs 离散自适应 + Canvas 曲线叠加）。
- **03 三套模板各长各的样**（`Tailored Templates`）：深钴暗室；讲清不同屏不仅是换列数，更是任务流与信息架构重构；交互：6 项界面模块分档剪裁矩阵与负载减重估算。
- **04 谁来决定发哪套模板**（`Client, Server & RESS`）：客户端媒体查询、服务端 Dynamic Serving（含 `Vary: User-Agent`）与 RESS 混合方案；交互：请求链路选择器 + 关闭 Vary 头触发 CDN 缓存串版模拟。
- **05 自适应从哪来**（`Origins & Evolution`）：核实史实编年轴（Marcotte 2010 → Gustafson 2011 / Adapt.js 2011 / RESS 2011 → W3C MQ3 2012 → Apple Size Classes 2014 → Material 3 Breakpoints）；交互：6 节点可切换编年刻度与原始架构切片。
- **06 什么时候用，什么时候别用**（`When to Use & Avoid`）：适用与避坑清单；交互：4 套真实项目场景决策诊断卡。
- **07 挑出最稳妥的档位门槛**（`Quick Check`）：单变量四选一练习，选后现场渲染四台设备实测条。
- **08 原海报**（`The Original Poster`）：可点击放大/拖拽/Esc 关闭的原海报与海报三要素图鉴。

## 7. 小练习
- 题干：三套定宽自适应模板固定为 `S 320px`、`M 768px`、`L 1200px`，需稳妥承接 375px / 640px / 820px / 1280px 四台常见设备，以下哪组切换门槛最合适？
- 四个选项仅改变「M 门槛 / L 门槛」这一变量，全用中性数值表达：
  - `A`：`M ≥ 600px` · `L ≥ 1100px`（门槛小于模板宽，640px 与 1150px 区间直接横向溢出）
  - `B`：`M ≥ 768px` · `L ≥ 1200px`（**正确答案**：每档门槛 ≥ 对应模板定宽，四台设备零溢出且占宽均衡）
  - `C`：`M ≥ 768px` · `L ≥ 1440px`（大屏门槛过晚，1280px 桌面停在 768px 模板，留白过宽）
  - `D`：`M ≥ 960px` · `L ≥ 1200px`（中屏门槛过晚，820px 平板停在 320px 手机模板，沦为空白黑洞）
