# 278 看板布局（KANBAN LAYOUT）互动版方案

## 1. 一句话道理
看板把看不见的任务排队变成看得见的垂直列与横向泳道，再用每列的在制品上限（WIP）倒逼团队先做完手里的事，瓶颈才会当场显形、交付才会稳定可控。

## 2. 开场玩具：活体生产看板台（真实跨列拖拽 + WIP 拦车 + 泳道折叠 + 列序调换）
- **怎么玩**：
  - 1:1 化用 278 原海报的「5 列状态表头 × 4 条深松绿职能泳道」真实生产看板，顶部紧贴一条与 5 列对齐的 **2D Canvas 实时流转水位与瓶颈测绘带**。
  - **直接按住看板卡片跨列拖拽**（焦点卡「用户权限系统」标有 `data-perf-drag`，拖动时卡片浮起随手指/鼠标平滑移动，顶部 Canvas 同步绘制流向引弧与目标列 WIP 预判，松手落入目标列；也支持点击卡片的 `←`/`→` 快捷流转按钮或选中卡片后用键盘 `←`/`→` 推进、`↑`/`↓` 切卡、`Enter` 推往下一列）。
  - **点击列表头的 `⇄` 按钮**可互换相邻列顺序；**控制槽**可切换「泳道分组（混堆关 / 4 职能泳道）」「WIP 上限（关闭 ∞ / 严格上限，满额时会物理弹回拦车）」「卡片密度（过载 8 项 / 最小必要 / 极简缺标）」。
- **一打开是什么状态（0 / 4 错态）**：
  1. **列序倒置**：第 2 列「评审中 IN REVIEW」被放到了第 3 列「进行中 IN PROGRESS」前面（`待办 → 评审中 → 进行中 → 测试中 → 已完成`），流程逆行。
  2. **WIP 失限且爆仓**：WIP 上限关闭（∞），「进行中」一口气堆了 **5 张**卡（超出经验上限 3 张，+2 超载），并发严重过载。
  3. **泳道关闭（混堆）**：产品、设计、开发、运维四类任务混在一锅里，分不清哪条职能线积压。
  4. **卡片信息过载**：单卡塞满 8 项冗余信息且撤去优先级色标，高优紧急任务被文字淹没。
- **怎样算玩错 & 错了读数怎么说**：
  - 由 `model.js` 单真源实时从当前列序、各列卡片数组、WIP 规则与卡片密度算出全部指标，可精准诊出 **7 类错态**：列序倒置、WIP 失限（∞）、单列超载爆仓（开启 WIP 后若仍 > 上限或把太多卡塞进同一列）、执行列空转（把进行中全清空到 0 张）、职能混堆无泳道、卡片信息过载、卡片信息残缺（切到极简无标导致找不到优先级与负责人）。
  - 读数不仅报数字（当前在制品总数、瓶颈列占比、按利特尔法则估算的示意周期），更用白话指出「这样摆团队会怎么看、卡在哪里、为什么交付变慢」。
- **与最近 12 页的区别**：
  - 彻底不同于时间轴游标（277）、斜轴乐谱（109）、拓扑节点网（064）、立轴山水（315）、CSS relative 偏移块（232）、双斜梁（026）、剪影绕排（148）、水平轮播（276）、行长眼动纸（193）、树形分叉（063）、float 绕排（231）、画廊比例尺（275）——是真正能拖卡片、会触发 WIP 满员拦车、可切泳道与列序的活体工作流矩阵界面。

## 3. 版式骨架
- 忠实承袭 278 原海报「暖亚麻宣纸刊头（左粗森绿大标+竖杠总述 × 右双绿圆与 4×4 点阵）→ 全宽深松绿表头圆角矩阵看板 → 底部五柱原则与卡片要素条」的开放竖向建筑骨架，不锁 `100svh`、绝无深色圆角仪表盘侧边栏。
- **1440×900（2560 舒展至 1800px）**：顶眉 34px；刊头左 68% 排内嵌 5 列实时缩微 WIP 柱徽的示范大标「看板布局」与总述，右 32% 排原海报双绿圆、4×4 点阵与实况读数；中段全宽铺开 2D Canvas 水位测绘条 + 5 列 × 4 泳道活体看板；下接双分控制诊单条（左 44% 白话诊单 × 右 56% 控参）与 5 项原则实况检核条。
- **390×844 手机竖屏**：极简压缩刊头为单行（大标 + 缩微柱徽 + 验收胶囊），总述下移；顶部 2D Canvas 五列全局水位条全宽不滚，下方看板区采用内部横滑轨道（初始定位使焦点「进行中」列与 `data-perf-drag` 卡恰好居中并露出左右邻列边，页面零横向溢出），整个看板舞台稳占首屏 ≥ 48% 屏高并同屏露出白话诊单与核心开关。
- **844×390 手机横屏**：切为左 60% 活体看板与水位条 × 右 40% 紧凑刊头、白话诊单与控参并行。

## 7. 练习题设计
- **题目**：同一个 5 人产品团队手头有 14 张任务卡，下面 A / B / C / D 四块同样工整的看板，哪一块最能如实暴露瓶颈并稳住交付？
- **变量控制**：标签仅写 `A` / `B` / `C` / `D`，四张缩微图排版同样清爽，只差「工作流列序、WIP 限流与状态拆分」一个核心机制变量：
  - A：5 列且设了 WIP，但「评审中」排在「进行中」之前（列序逆流）。
  - B：5 列按 `待办 → 进行中(4/4) → 评审中(2/3) → 测试中(2/3) → 已完成` 排列，活动列全有 WIP 且未超载（**正确**）。
  - C：5 列顺序正确，但没设 WIP 上限，「进行中」已默默积压 8 张卡。
  - D：把进行中、评审、测试全合进一列「处理中(9/10)」，中间阻塞完全看不见。
