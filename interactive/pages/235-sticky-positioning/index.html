STICKY POSITIONING

元素在正常文档流中，滚动到阈值时吸附在顶部，内容继续滚动。

错态 · 祖先截断 单真源实算 · 体验调校

外层套了 overflow: hidden，粘性标题当场失灵

规范规定 position: sticky 只盯住「最近的滚动祖先」。祖先写了 overflow: hidden 会暗中建立一个不能滚动的滚动容器，浏览器以为你从未滚动过，标题只能跟着正文直接滑出屏幕。

把「祖先容器 overflow」切到 overflow: clip（现代裁切正解）或 overflow: visible，把滚动参照还给视口。

          01
          

            
什么是粘性定位

            
THE HYBRID STATE · RELATIVE MEETS FIXED

          

        


        

          

            

              原海报 · 核心概念
              
「粘性定位融合相对定位与固定定位：在阈值之前表现为相对定位；到达阈值后固定在指定位置。」

            

            
如果把网页文档流比作一条向上匀速前进的纸带，我们在同一小类里见过几种截然不同的站位方式：守规矩排队的 222 普通流布局、原位微移且保留旧坑的 232 相对定位布局，以及干脆脱离纸带、永久焊在屏幕玻璃上的 234 固定定位布局。

            
粘性定位（position: sticky）不是独立新物种，而是带边界开关的混合体。第一，它始终留在文档流里占住原本那块高度，不会像固定定位那样突然塌陷把第一行正文吸到顶栏背后；第二，它在滚过阈值线后借用固定定位的视觉停驻；第三，它永远只服务于自己的父容器。


            

              原海报说简了一点
              
原海报右侧画了「01 正常流程 → 02 过渡状态 → 03 吸附顶部」三段，这是入门最好懂的切面。在 W3C 正式规范里还有决定性的第四幕：到达父容器底边时被平滑顶走。正是这一步让它能完成章节接力，而不会像固定导航那样一路霸占到页脚。

          02
          

            
阈值与双向吸合

            
INSET THRESHOLDS & TWO-AXIS STICKY

          

        


        

          
原海报用 top: 0 演示了最常用的顶边吸附，但 position: sticky 实际支持 top、bottom、left、right 四个方向（以及逻辑属性 inset-block-start 等）。把 bottom: 0 赋给长表单的操作栏，按钮在抵达表单底部前都会紧跟手指；把 top: 0 和 left: 0 同时用在同一张宽数据表里，横滚看列、竖滚看行时，行列坐标永远不会丢失。

          03
          

            
四大失效暗坑诊所

            
WHY POSITION: STICKY SILENTLY FAILS

          

        


        
写 position: sticky 最挫败的时刻，是浏览器既不报错也不吸顶。下面四份病历覆盖了线上九成以上的失效现场——切一份病历，滚一滚旁边的实景预览，再亲手修掉那一行致命 CSS。

          04
          

            
从哪来

            
FROM MOBILE LIST HEADERS TO COMPOSITOR-DRIVEN CSS

          

        


        
在原生 position: sticky 普及之前，网页要实现「滚到顶就固定」，全靠 JavaScript 监听 scroll 事件、反复读取元素坐标再切换 position: fixed。但现代浏览器为了 60 帧顺滑滚屏，早就把滚动放到了独立的合成线程——主线程的 JS 回调永远慢半拍，一急滚标题就会抖动、错位甚至闪烁。粘性定位的诞生，本质上是一次把吸顶权限交还给浏览器渲染引擎的漫长工程接力。


        
        

          
          
          
          
          
        


        

          

            2012
            标准起航
          

          
Edward O'Connor 在 www-style 提案并落地 WebKit

          
2012 年 6 月 26 日，Apple 工程师 Edward O'Connor 在 W3C www-style 邮件列表提交 Sticky Positioning 提案，直指当时用 JavaScript scroll 监听切换 fixed 会破坏浏览器异步硬件滚屏、引发明显抖动（jank）。同年 8 月，WebKit 率先实现 -webkit-sticky。

什么时候用，什么时候别用

            
APPLICABLE SCENES & WHEN TO STEP BACK

          

        


        
        

          

            
              
            
            阅读导航
            
长文档右侧大纲或顶部阅读进度条，滚到正文结束即停驻，不盖页脚。

          

          

            
              
            
            分区标题
            
通讯录字母组、日程按月分组、商品品类分段，下一组自动顶走上一组。

          

          

            
              
            
            筛选工具栏
            
搜索结果上方有横幅介绍，滚过横幅后筛选条才顺势吸顶，省出首屏空间。

          

          

            
              
            
            标签切换栏
            
详情页的「参数 / 评价 / 问答」切换条，读到深处依然伸手可切。

          

        


        

          

            
什么时候别用粘性定位

            
    
              
  • 全站永久不退场的主控条：如果导航或应急悬浮按钮从第 1 像素到页底都必须常驻屏幕，请直接交给 234 固定定位布局，别硬套粘性定位平添祖先溢出隐患。
    • 
              
  • 需要跳脱容器自由叠层：徽章角标、气泡提示或模态弹窗，请看 233 绝对定位布局 或 237 覆盖布局。
    • 
              
  • 多层吸顶叠罗汉：公告条 + 主导航 + 筛选栏 + 分区头四层一起吸顶，在矮屏上能直接吞掉一半视口；配合 240 响应式布局，在矮横屏（如 max-height: 480px）应主动回退 position: static。
    • 
              
  • 锚点跳转忘配 scroll-margin-top：点击目录跳到 #sec-2 时，浏览器默认把标题滚到视口 0px，正好钻进吸顶栏背后——务必给各锚点标题补上不小于吸顶高度的 scroll-margin-top。
    • 
              
  • 网格与弹性盒里忘写对齐：在 226 弹性盒布局 或 227 网格布局 中做粘性侧栏，必须显式设 align-self: start，否则默认拉伸会让它锁死。
