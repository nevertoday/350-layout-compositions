01

一块内容，三副骨架

ONE CONTENT SOURCE · THREE STRUCTURAL PILLARS

原海报把同一套「Brand.」页面摆进了三台设备，并用三句要点定调：

桌面端：多列布局，完整展示，信息层级清晰。

平板端：两列布局，模块重排，重点内容优先呈现。

移动端：单列布局，垂直流畅，聚焦核心信息。

海报细读 · 配错了位

原海报顶部三组小签写着：「断点重排 / BREAKPOINT」「多端统一 / REORDER」「同一内容 / DEVICE」。第一组「断点重排」配 BREAKPOINT 尚可，但后两组中英文配错了位：REORDER 本意是模块重排，应归到「断点重排」；DEVICE 指的是多端设备，更贴合「多端统一」；而「同一内容」对应的应是单一内容源（ONE CONTENT，即同一份 HTML）。此外，原海报平板示范图底部卡片仍画成三列，与右侧两列线框小图略有出入。

响应式只维护同一份 HTML 内容源，靠流体网格、弹性媒体和媒体查询三根支柱协同工作。它和相邻的几种网页布局分工很清楚：只锁死一套宽度的是238 固定宽度布局；只靠百分比连续缩放、不换列数的是239 流体布局；为几档固定屏宽各做一套离散模板的是241 自适应布局。响应式把连续伸缩和断点换挡合二为一——宽够时平滑伸展，快撑破时立刻重组骨架。

03

按内容设断点，不按机型

CONTENT-DRIVEN BREAKPOINTS VS DEVICE LISTS

很多团队至今还在死背「375 手机 / 768 平板 / 1024 桌面」这套十年前的老机型像素表。可市面上折叠屏、分屏窗口和带侧栏的浏览器数以百计——就像开场标尺里随内容移动的安全带所示，真正该触发断点的，是内容自己快撑破的那个宽度。现代 CSS 甚至能借助227 网格布局的 minmax() 让列数按卡片最小可读宽自动折算。

重排不是隐藏，顺序定去留

REORDERING PATTERNS & FOCUS ORDER

Luke Wroblewski 在 2012 年把当时主流的多端重排总结为基本流体、逐列下落、布局位移等经典模式。但重排有个容易踩中的暗坑：借助226 弹性盒布局或网格的视觉重排属性把块搬来搬去时，键盘 Tab 焦点和屏幕阅读器依然按 HTML 源码顺序走——视觉顺序和代码顺序一旦拧麻花，键盘用户就会在页面上乱跳。

05

弹性媒体与视口声明

VIEWPORT META & ART DIRECTION

写再完美的媒体查询，漏掉两件事照样功亏一篑：

  • 视口声明（Viewport Meta）：页面头部必须写 width=device-width, initial-scale=1。漏写它时，手机浏览器默认把网页当约 980px 宽的桌面页硬缩塞进屏幕，你的小屏断点永远不会被触发。
  • 艺术指导（Art Direction）：一张 16:9 横幅主图直接等比缩到 375px 手机屏里，高度只剩两百像素出头，核心细节缩成米粒。用 HTML 的 <picture> 按断点切一幅更紧凑的竖构图，才能让画面在窄屏照样有分量。
  • 页面骨架之外的组件：当一张独立卡片既可能放进宽主栏、又可能塞进 260px 侧栏时，视口宽度已经回答不了它的处境——这一层分工请交给242 容器查询布局。

当前：已声明 viewport，但 16:9 横图直接等比缩小，手机上核心几何主体面积示意约 19%。切到 <picture> 艺术指导对比看看。

原海报与关键词

ORIGINAL POSTER & KEYWORDS

断点重排 BREAKPOINT / REORDER 原海报标 BREAKPOINT

视口跨过内容临界宽度时，主动由 1 列换挡至 2 列、多列并重组导航形态与模块顺序。

多端统一 MULTI-DEVICE 原海报错配为 REORDER

桌面、平板、手机共享同一套设计语言与信息架构，靠统一规则跨屏一致运作。

同一内容 ONE CONTENT 原海报错配为 DEVICE

一份 HTML 内容源直达所有终端，重排的是空间优先级，不是阉割信息。
