# 234 固定定位布局（FIXED POSITIONING）交互页方案

## 1. 一句话道理
`position: fixed` 把元素抽离普通文档流并锚定在浏览器视口玻璃上，让高频导航与工具在任意滚动深度下都「伸手可及」——但它同时也像贴在窗玻璃上的便利贴：贴太满会挡住阅读风景，忘记给文档流让位会切掉首行与跳转标题，而祖先的一行 `transform` 就能让它悄悄失效、跟着页面滚跑。

## 2. 开场玩具
- **玩法**：直接化用 234 原海报中央的**深海蓝青框活体浏览器视口**——里面是一张真正可滚、可点锚点跳转的迷你网页（复刻原海报的 4 枚孔雀青绿固定部件：顶部导航栏、左侧浮动工具轨、底部工具栏、右下悬浮客服球，以及内部 3 张虚线滚动内容卡「1. 什么是固定定位？ / 2. 基本用法 / 3. 应用场景」）。
  - 视口底沿焊着一条水平**滚页滑轨（`data-perf-drag`）**，左右拖动（或直接在视口里滚轮/触控滑动、点顶栏锚点跳转）即可让内容页在固定层下方实时滑动；
  - 右翼内嵌一块 **2D Canvas 纵深剖面与滚页流向仪**，随 `scrollY` 实时画出「滚动纸带在固定玻璃层下方穿行」的侧面剖视图、遮挡热区与可视区净占比；
  - 左翼三枚海报同款水平指针直接挂在顶栏、侧轨、底栏外侧，右翼挂在悬浮球与包含块外侧，就地调控每个固定件的形态与 CSS 参数。
- **开场状态（0 / 4 翻车态，绝不先给答案）**：
  1. **四面胖栏霸屏**：顶栏 `116px` + 底栏 `92px` + 侧轨 `88px` + 大悬浮球 `72px` 全开，固定壳层吞掉约 `51%` 视口面积（净可视区仅剩 `49%`，远低于 `72%` 经验舒适底线）；
  2. **未留文档流让位与锚点余量**：`padding-top: 0` 且 `scroll-padding-top: 0`，首张卡片标题在 `scrollY = 0` 就被顶栏拦腰截断，点顶栏锚点跳转也会吞掉章节标题；
  3. **层叠倒挂**：固定层 `z-index: 1`，滚动区内的推广横幅为 `position: relative; z-index: 20`，滚过时正文直接反盖导航栏与悬浮球；
  4. **祖先 `transform` 劫持包含块**：外层 `.page-shell` 误带 `transform: translateY(0)`，根据 CSS Transforms 规范它取代视口成了包含块，拖动滚页滑轨时所有「固定」栏竟然跟着文章一起滚走！
- **怎样算玩错、读数说什么「为什么」**：
  - 不仅这 4 项初始错误能诊出，用户还能玩出新错：把所有固定部件全关掉 → 诊出「退回普通流，没有常驻锚点」；把顶部留空拉到 `160px` → 诊出「顶部空洞过大，首屏白白浪费」；切换到手机窄视口不收起侧轨 → 诊出「窄屏侧轨压窄阅读栏」。
  - 每次操作由 `model.js` 单真源按真实视口几何像素重算：净可视面积占比、首行被遮像素、层叠是否反压、包含块归属，并给出白话「用户会看到什么、为什么会这样」以及同步更新的真实 CSS 代码块。
  - **多组正当解**：只要保留至少 1 枚固定锚点、固定层总占用 ≤ 28%（净可视 ≥ 72%）、顶部让位与 `scroll-padding-top` 匹配顶栏高、固定层级高于内容层、且无祖先 `transform` 劫持，无论选「顶栏+悬浮球」「顶栏+瘦底栏」还是「顶栏+窄侧轨」均可过关。
- **与最近 12 页的区别**：
  - 233（绝对定位）是酸黄奶油 800×600 坐标框拖几何块；278 是 5 列看板拖卡片；110 是紫粉渐变坡面；065 是 3D 风景玻璃层；027 是对称山水天平；316 是玄夜重门；194 是稿纸裁边；149 是紫色字母雕塑；277 是暖杏时间轴；109 是曜黑斜轴乐谱；064 是中心圆拓扑网；315 是宋画立轴。
  - 本页 234 是**真能滚动、真能锚点跳转的迷你浏览器视口 + 侧面纵深滚页剖面仪**，操作对象是「滚动页与固定玻璃层的相对运动」，完全无法套用到其他任何编号。

- 忠实承袭 234 原海报的**深海蓝对称三翼蓝图架构**（绝非「左舞台右仪表盘」，不锁 `100svh` 避开平板空洞）：
  - **1440×900（桌面，容器宽 1360px；2560×1440 舒展至 1780px）**：
    - 34px 极细深海顶眉（分类 · 编号 · 实时校准进度徽）；
    - 海报同款双栏刊头：左为带实时固定锚框的示范大标「**固定**定位布局」+ 孔雀青 `FIXED POSITIONING` + 总述；右为原海报三枚图例行（实色青块「固定于视口」/ 虚线框「滚动内容」/ 斜线纹「覆盖层（可选）」），实时映出当前各项读数；
    - 中段为原海报对称三翼：左翼 25%（顶栏/侧轨/底栏三道水平指针控槽）× 中轴 48%（圆角青框活体迷你浏览器 + 底沿水平滚页滑轨 `data-perf-drag`）× 右翼 27%（2D Canvas 纵深滚页剖面仪 + 悬浮球/层级/包含块指针控槽）；
    - 底沿承接原海报深蓝代码窗气质的通栏「白话实况诊单 × 实时 CSS 码窗」。
  - **1024×1366 & 768×1024（竖屏平板）**：刊头 + 图例紧贴下方「60% 活体视口 + 40% 纵深剖面仪」并排，再下接双列控槽与诊单，无空洞。

  - **844×390（手机横屏）**：切左 55% 活体浏览器视口与滚页滑轨 × 右 45% 标题、实况诊单与核心快捷操控并行。
- 正文七节（01–07）在清透海雾浅纸（`#F2F7F7` / `#E8F1F1` / `#F8FBFC`）与深海藏蓝蓝图暗室（`#061A34` / `#04152E` / `#010F2A`）间明暗交替推进。

## 7. 练习
- **题干**：390×844 手机文档站需要 56px 固定顶栏，且正文区有一张带 `position: relative; z-index: 5` 的状态提醒卡。用户会点目录跳到 `#install`，也会用键盘 `Tab` 浏览链接。下面四套样式仅差一个变量，哪一套全程不翻车？
- **四个选项（中性标签，仅差单变量）**：
  - `方案 A`：外层 `.page` 带 `transform: translateZ(0)`（其余合规）→ 祖先 transform 劫持包含块，滚页时顶栏跟着滚走。
  - `方案 B`：`main` 有 `padding-top: 56px`，但缺少 `html { scroll-padding-top: 64px }` → 首屏完好，锚点跳转与键盘焦点回溯时会被顶栏裁切遮挡。
  - `方案 C`：无祖先 `transform` + `.nav { z-index: 100 }` + `main { padding-top: 56px }` + `html { scroll-padding-top: 64px }` → **正确**。
  - `方案 D`：其余全同方案 C，仅 `.nav` 设为 `z-index: 1` → 滚过 `z-index: 5` 的定位卡片时正文会反压顶栏。
