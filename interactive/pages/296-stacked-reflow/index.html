01

拆掉横轴，视线只走一条路

One axis · zero horizontal friction

原海报把堆叠重排浓缩成一句话：「内容模块纵向堆叠，顺序清晰，结构自适应。」落到屏幕尺寸剧烈收缩的场景里，它干的其实是一件减法：干脆取消横向空间依赖，把所有平级区块放进同一条从上到下的阅读动线。

仔细看 296 号原海报会发现一个值得拆开的细节：右下角「应用示例」画的是桌面四栏合并成手机单列，而右上角双蓝图对比的其实是单个模块内部从「左图右文」翻成「标题优先」。补充说明 真正站得住的堆叠重排，页面级的多列转单列与模块级的标题优先两层都得同时到位——只把外框排成一列，如果每块里面还左右互挤，窄屏依然难读。

在同一小类里，它和其他几种重排手法分工明确：大屏留白、小屏才汇成单列的是 291 大体流动模式；随宽度逐列往下掉的是 292 列下落模式；骨架不动只微调字号留白的是 294 微调模式；把次级导航或筛选藏出边界的则是 295 画布外模式。

02

堆叠重排从哪来

Origins · normal flow to WCAG Reflow

纵向堆叠并不是智能手机发明之后才冒出来的新花样——它本来就是网页与纸面阅读最原始的默认秩序，多栏并列反而是宽屏上后加的约束。

1996 年 12 月 17 日发布的 W3C CSS1 推荐标准（Håkon Wium Lie 与 Bert Bos 起草）在第 4.1 节确立了块级元素的正常文档流：不加额外定位或分栏声明，所有区块天然从上到下依次堆叠。2010 年 Ethan Marcotte 提出响应式网页设计，2011 年 Luke Wroblewski 出版《Mobile First》（A Book Apart）进一步主张先为小屏单列理清内容优先级，再随视口变宽渐进展开多栏。

需要坦白交代一个命名事实：名称溯源 Luke Wroblewski 在 2012 年 3 月发表《Multi-Device Layout Patterns》时，只归纳了五种模式——Mostly Fluid、Column Drop、Layout Shifter、Tiny Tweaks 与 Off Canvas，里面并没有「堆叠重排」这一独立名字。「堆叠重排」是后来设计教学里对「窄屏撤横成纵」这一共性动作的描述性叫法（在窄屏终态上与 291、292 以及跨断点改骨架的 293 布局切换模式 有所交叠）。同年 CSS Flexbox 发布首次候选推荐，2018 年 6 月 W3C WCAG 2.1 以 SC 1.4.10 Reflow 把「320 CSS px 宽（1280px 桌面 400% 缩放）无双向滚动」写入无障碍标准；2019 年 Heydon Pickering 与 Andy Bell 首版出版《Every Layout》（2021 年第二版引入 Flexbox gap），把这套规律提炼为 The Stack 与 The Switcher 两个组件原语（更细的容器自适应见 300 组件级响应布局）。

  1. 1923
    Wertheimer 邻近律《Psychologische Forschung》第 4 卷提出近邻归组法则，成为块间与块内间距比的知觉基础。
  2. 1996
    W3C CSS1 推荐标准（12-17）第 4.1 节定义正常文档流，块级盒子默认纵向顺排、垂直外边距合并。
  3. 2010–2012
    响应式与《Mobile First》Marcotte（2010）、Wroblewski《Mobile First》（2011）与多设备五模式（2012）、CSS Flexbox 首次 CR。
  4. 2018
    WCAG 2.1 SC 1.4.10 Reflow06-05 推荐标准要求 320 CSS px / 400% 缩放单向重排且不丢信息。
  5. 2019
    《Every Layout》首版Pickering & Bell 把纵向节奏与自动横纵折排写成 The Stack / The Switcher（2021 第二版改用 gap）。

03

块内层级：标题先出场

Title first inside every stacked block

原海报第二条核心原理写得非常准：「保持层级：标题优先，信息跟随。」把外框折成单列只是上半场；如果模块内部还死守宽屏的左图右文、左标签右输入框，或者让装饰大图先占满半屏，读者进到这一块还是得先猜半天它在讲什么。

这里要顺手划清一条界线：本节只调单个模块内部的标题与正文顺序；如果你要在窄屏里把「侧栏模块」整块搬到「主内容模块」前面，改变的是模块之间的出场先后，那就属于 297 顺序重排 的范畴——并且动手改 CSS order 时务必留心，不要让视觉顺序和键盘 Tab 焦点顺序打架。

04

内外间距，定住堆叠节奏

Outer gap vs inner rhythm · Gestalt proximity

模块一列排开之后，区分「哪里是一块、哪里是下一块」靠的不再是列缝，而是垂直距离。原海报把这条称作「模块间距：节奏一致，呼吸舒适」。

按照 1923 年韦特海默（Max Wertheimer）总结的格式塔邻近律，大脑会自动把距离更近的元素打包成同一组。所以在纵向堆叠里，模块外距必须明显大于模块内部的标题—正文间距：常见经验值是外距落在内距的 1.5× 到 2.5× 之间（经验值，视卡片有无边框与底色微调）。外距小于或等于内距，上一块正文就会粘到下一块标题身上；外距拉得过宽，手机小屏里下一块露不出头，又容易让人误以为页面已经结束（假底）。

05

四步把宽屏拆成好堆叠

Four-step practice · from wide to stack

原海报底部给出了四步「实践要点」：① 确定信息优先级 → ② 模块化拆分内容 → ③ 垂直堆叠重排 → ④ 检查节奏与间距。顺着这四步走，用几行现代 CSS（如《Every Layout》里的 The Stack / The Switcher 思路）就能把复杂桌面块稳稳落成手机单列。

如果你的内容是大量等权商品卡、希望宽度够时自动增列而不必手写一堆断点，可以配合 299 自适应网格；若宽屏双栏需要实时对照阅读，则应转向 298 折叠双窗格。

06

什么时候别硬套堆叠

When NOT to force a vertical stack

原海报最后写了一句「从并列到堆叠，内容不变，结构更优。」说多了一点 堆叠重排能保住信息不丢，但并不是所有二维信息变成一长条以后都会「更优」。

WCAG 2.1 SC 1.4.10 本身就明文豁免了依赖二维空间关系才能读懂的内容——比如数据表、地图、设计画布和复杂工具栏。Amy Schade（Nielsen Norman Group，2017-09-17）分析移动端对比表时也明确指出：盲目把多列参数拆成纵向条目，会直接破坏同行横向比较。此外，把桌面长筛选栏硬堆到手机顶部会把真正的主内容挤出首屏（这时更该用 295 画布外模式），需要边改边看的双栏工具硬堆成上下长条也会让人滚到迷路（更适合 298 折叠双窗格）。

同小类：响应式重排模式 291–300

  • 291 大体流动模式大屏居中留白，小屏顺次堆成单列。
  • 292 列下落模式随宽度逐列下移，而非一次全堆。
  • 293 布局切换模式跨断点重组整页骨架。
  • 294 微调模式骨架不动，只微调字号与留白。
  • 295 画布外模式次级面板停在屏外，按需拉入。
  • 297 顺序重排主动改写各模块之间的出场先后。
  • 298 折叠双窗格宽屏双栏对照、窄屏折叠切换。
  • 299 自适应网格按最小列宽自动增减列数。
