            布局原语协作分工
            SIBLING PRIMITIVES · HOW THEY COMPOSE
          

          
在真实页面里，侧栏原语只管「一窄一宽的并排与折行」，其余结构各自交给同族原语，绝不互相越权：

          

            243 堆栈负责侧栏和正文内部统一的纵向节奏间距
            244 盒子为侧栏或内容块提供统一内边距与边界线
            245 居中器在主区内给长文限定舒适行宽并居中
            246 簇群把标签、工具按钮横向聚成有间距的自然行
            248 切换器负责 2–4 个等宽栏在横排与竖排间一键切换
            249 封面原语管首屏垂直居中主体与顶部/底部撑满
            250 自适应网格原语在主区内按最小卡片宽自动增减等权列数
            251 比例框把主区媒体、图片或头像锁定固定宽高比
            252 横向卷轴承载主区内超宽的表格、图谱或横向卡片流
            253 悬浮层管理需要覆盖在正文之上的弹窗或临时抽屉
            254 图标文字组合让侧栏导航里的小图标与文字基线严丝合缝
          

        

      

    


    
    

      

        

          04
          

            
从圣杯到量子原语

            
WHERE IT CAME FROM · 2006–2019 EVOLUTION

          

          
网页设计师花了十三年，才把「固定侧栏 + 流式主栏」从脆弱的负外边距技巧，提炼成几行不问屏幕尺寸的固有算法。

        


        
    
          
  1. 
            2006
            
    
              
    《寻找圣杯布局》：无表格的侧栏难题
    
              
    2006 年 1 月 30 日，Matthew Levine 在 A List Apart（第 211 期）发表《In Search of the Holy Grail》，示范如何用 CSS 浮动与负外边距实现「定宽侧栏 + 流式主区」且让正文在源码中靠前。那时为了拼出侧栏，样式表必须写满精确抵消的像素补丁。
    
            
    
          
    2. 
          
  2. 
            2010
            
    
              
    响应式网页设计：媒体查询接管折行
    
              
    2010 年 5 月 25 日，Ethan Marcotte 在 A List Apart 发表《Responsive Web Design》，确立流式网格、弹性媒体与 @media 视口断点的三件套。侧栏从此可以在小屏折叠，但前提是作者必须提前猜对所有屏幕断点。
    
            
    
          
    3. 
          
  3. 
            2012–2018
            
    
              
    W3C Flexbox 规范成熟
    
              
    W3C 的 CSS Flexible Box Layout Module Level 1 自 2012 年 9 月进入候选推荐（CR），至 2018 年 11 月发布 CR 快照，浏览器原生的 flex-basis、flex-grow 与 flex-wrap 空间分配算法全面统一。
    
            
    
          
    4. 
          
  4. 
            2018
            
    
              
    固有网页设计（Intrinsic Web Design）
    
              
    2018 年，CSS 工作组成员 Jen Simmons 在 An Event Apart 提出「Intrinsic Web Design」，主张摆脱对固定断点的执念，让元素根据自身内容与所在容器空间自行协商尺寸。
    
            
    
          
    5. 
          
  5. 
            2019
            
    
              
    Every Layout 正式命名「The Sidebar」原语
    
              
    2019 年，Heydon Pickering 与 Andy Bell 在 Every Layout 中把 flex-grow: 1、flex-grow: 999 与 min-inline-size 组合成「The Sidebar」，称之为「量子布局（Quantum Layout）」——同一组件无需媒体查询，在并排与堆叠两种状态间按容器空间自发坍缩。
    
            
    
          
    6. 
        


        
        

          

            补充说明
            怎么理解原海报里的「侧栏固定」？
          

          

            「固定参照：侧栏固定，提供持续的方向感与操作预期。」—— 247 原海报设计要点 01
          

          

            原海报强调的是宽屏阅读时侧栏作为「心理锚点」的稳定性，这在文档站和后台系统里完全成立。不过在工程实现上，「视觉稳定」不等于把宽度和位置写死：一旦把侧栏原语放进手机竖屏或窄卡片里，强行固定不动反而会把主区挤扁。真正的侧栏原语只在容器足够宽时安静守边，空间不足时便主动折到上方或下方并撑满整行——既守住宽屏的秩序，也不牺牲窄屏的呼吸。

什么时候别用

            
WHEN NOT TO USE · FOUR ANTI-PATTERNS

          

          
侧栏原语只擅长「一主一副、权重不对称」的两栏关系。遇到下面四种场景，硬套侧栏只会适得其反——点击每张卡切换「错用现场」与「推荐替代」。

        


        

          

            

              红线 01
              
            

            
要放 2–4 个权重相等的并列栏

            

              
功能 A功能 B（被迫大得多）

              
功能 A功能 B功能 C

            

            
侧栏原语天生偏心主区（999:1），硬拿它排定价套餐或特性对比，第一项会被压成窄条、后一项肥大失衡。

            
需要 2–4 个等宽栏在横排与竖排间整体切换时，请换用 248 切换器（Switcher）。

          


          

            

              红线 02
              
            

            
要排三栏及以上或大批等权卡片

            

              
左中右挤断

              
卡 1卡 2卡 3卡 4

            

            
把三个以上子项塞进同一个侧栏原语容器，min-inline-size 会触发不可预测的错行孤儿（两上一下）。

            
多卡片集合请用 250 自适应网格原语；若确需双侧栏，应外层套一层侧栏原语、内层再嵌一层。

          


          

            

              红线 03
              
            

            
侧栏基准宽配得比主区底线还贪心

            

              
W_wrap = 1040px（宽屏也叠）正文被迫掉到下一行

              
200px主区 55% 以上舒展呼吸

            

            
把侧栏塞满广告、图表与卡片，导致 flex-basis 拉到 340px 以上或把 min-inline-size 设到 75%，临界线直接突破桌面宽。

            
遵循原海报 TIP「保持侧栏简洁、稳定、可预测」：把非锚点信息移入正文或抽屉，将侧栏宽控在桌面容器的 20%–32%（经验区间）。

          


          

            

              红线 04
              
            

            
单焦点深度阅读或品牌落地页

            

              
多余侧栏故事被推偏、分心

              
单轴居中沉浸阅读

            

            
如果页面只有一条线性叙事、没有频繁跨章跳转的需求，硬加侧栏只会白白切掉近三分之一视口并持续分散余光。

            
直接用 245 居中器 配 243 堆栈 守住单栏行宽，或用 249 封面原语 做整屏开场。
