01

墨量太轻，框齐眼反歪

INK WEIGHT VS. BOUNDING BOX

「将标点微微置于版心之外，修正视觉边界，使文本更整齐。」

—— 187 号原海报总述

排印软件对齐文字时，默认盯紧的是每个字符四周看不见的字身框（bounding box）。可人眼读版面时看不见字框，只看见白底或深底上真正落墨形成的视觉字墙。

一个实心粗宋体汉字（如「山」）的墨迹稳稳撑起整格，而一枚弯引号、逗号或句号在全角方格里只占偏安一隅的极少墨量。硬把它们关在版心虚线里，这一行的实字就被顶退一截，在整齐的文字墙边缘生生啃出一道凹槽。

原海报细读 · 温和补充

187 号原海报用粗宋体排出了五句参差诗文——巧融陶弘景《答谢中书书》「山川之美，古来共谈」与王羲之《兰亭集序》「游目骋怀，足以极视听之娱，信可乐也」，把左引号与第 4 行满行的逗号微推虚线外，作视觉图解极为醒目。不过原海报五行本身是参差行，只有第 4 行触碰右界：实操中，行尾右缘凸排主要服务于存在硬右壁的 179 两端对齐 与 177 右对齐左参差，像 176 左对齐右参差 这类散尾段落本来就没有平直右墙可修。

02

不同符号，挂多少才刚好

OPTICAL MARGIN ALIGNMENT · WESTERN SPECIMEN

凸排标点并不是把所有符号一刀切推出整整一格。西文排版里还有一个更广义的概念叫光学边距对齐（Optical Margin Alignment）：不只是引号、逗号与连字符要按各自字宽微凸，连 A / V / W / T 这类带着大片斜角空隙的大写字母，在硬边界处也会微微探出——且下方每一类「实测微凸」数值都由当前 Fraunces 字体像素扫描实时算出。

FRAUNCES 700 · LIVE OPTICAL MARGIN BENCH

拨动旁侧四类字符档位，亲眼看斜边字母挂太猛会外凸，标点挂不足会塌边。

03

从古腾堡到网页标准

FIVE CENTURIES OF MARGIN PROTRUSION

把轻小符号微推栏外，并不是现代排版软件突发奇想的新花样。它从 15 世纪金属活字的手工微调一路走来，历经算法微排版与桌面出版软件，至今仍在网页标准里等待各大浏览器补齐拼图。

c. 1450–1455 · MAINZ

古腾堡《四十二行圣经》的栏外连字符

在 Hàn Thế Thành（2000，TUGboat 第 21 卷第 4 期第 3.1 节）对美因茨《四十二行圣经》的微排版考据中，古腾堡为令双栏右缘在肉眼下显得笔直，将行尾的连字符、句号、逗号及部分窄末字微微置于栏线之外，并配合多种字宽变体保持词距均匀。

出处：Hàn Thế Thành, Micro-typographic extensions to the TeX typesetting system, TUGboat 21(4), 2000, §3.1（引 Martin Davies 1996 与 Adolf Wild 1995）。

04

中英日，各算各的边界账

CLREQ · JLREQ · LATIN COLUMN RULES

SIMPLIFIED ZH · W3C CLREQ §6.1.3

简体中文：以守版心为主，挂则最多挂一个

W3C《中文排版需求》第 6.1.3 节明文指出：「绝大多数的中文出版物没有悬挂行尾点号的惯例。」若采用行尾悬挂，「通常，行尾只可悬挂一个标点符号；适合行尾悬挂的标点符号有顿号、逗号及句号」，且连续出现两个标点（如 。”）时不应悬挂。

TRADITIONAL ZH · W3C CLREQ §6.1.3

港台繁体：居中点号横排不挂，直排可用

CLREQ 第 6.1.3 节接着写明：「由于港台地区的点号位于字面正中，若在横排时使用行尾悬挂，体例可能显得突兀、不良，故横排时不做行尾悬挂配置；但可用于直排。」横竖排版的不同边界规矩，可另见 192 垂直文字排版 与 193 水平文字排版。

JAPANESE · W3C JLREQ §2.5.1 / §3.8.2

日文「ぶら下げ組」：专治行头禁则

W3C《日文排版需求》把行尾悬挂称为「ぶら下げ組」：仅对本应折到下行首的句点（。）与读点（、），将其贴于基本版面外缘，以此减少追出或追入导致的字距不均。

简体中文密排报栏：同一句话以相同字号与栏宽排布，左侧严守版心在第 1、3 行被迫推字拉散，右侧挂出单个逗号后字距均匀平顺，末行连续双标点「。”」依 CLREQ 仍守在版心之内。

05

浏览器不买账，网页怎么写

CSS HANGING-PUNCTUATION & FALLBACKS

W3C CSS Text Module Level 3 早已定义原生属性 hanging-punctuation，但按 MDN 与 Can I use 实查结果：截至目前仅 Safari 17.4+ 完整支持（Safari 10–17.3 为部分支持），Chrome、Edge 与 Firefox 仍未原生支持。在跨端网页里，常用首行负 text-indent 或独立定位大引号兜底——且务必给容器留出足够外白，否则遇到 overflow: hidden 会把标点切掉一半。

勾选 CSS 属性值组合 
blockquote {
  hanging-punctuation: first allow-end;
}

Safari 17.4+ 原生解析 first 与 allow-end，容器预留了充足外白，引号完整悬于左界外侧。

06

什么时候用，什么时候别用

WHEN IT SHINES · WHEN TO KEEP IT INSIDE

凸排标点最怕「不看场景到处开」。它最适合宽边距大字引言、诗集书扉与多栏对齐长文；而在零边距窄卡片、财务数据表、连续双标点与 178 居中排版 里强行开启，反而会制造裁切、错列与失重。顺便分清最容易混淆的邻居：185 悬挂缩进 动的是整段续行的左缩进（服务词条检索），186 首行缩进 退的是段首两字（区分自然段），而本页 187 只把单枚轻标点微推版心线外；它也常与 180 强制两端对齐、188 基线对齐 协同工作却各司其职。

推荐场景

书评大字引言

宽留白大字引言最显效果：大号开引号一旦挂出左界，下方文字瞬间站成一根笔直支柱。

翻车禁区

手机零边距窄卡

卡边没有留出外白时，挂出去的引号会被卡片边界或屏缘直接切碎，关掉反而干净。

翻车禁区

财务负号对账表

表格里的负号或货币符承载精确语义，若随视觉微调飘出列界，容易漏看正负或跨列误读。

翻车禁区

居中请柬标题

居中排版依靠中轴对称而非左右垂直边界，硬把单侧引号甩出去只会让视觉重心偏歪。

187 凸排标点（本页） 仅单枚轻标点微微跨出版心线，正文主体留在原位，目的是修直视觉字墙。
185 悬挂缩进 → 整段第 2 行起全部向右大步内缩，留出整条空白走廊突出词头，与标点微凸完全不同。
