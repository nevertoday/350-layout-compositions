# 271 瀑布流页面（MASONRY / WATERFALL PAGE）设计方案

## 1. 一句话道理
拆掉网格里强行对齐的水平行底线，让每张卡片保持等宽并按内容原生高矮自然生长，每来一张新卡就落进当前最矮的那一列——既保住横竖混排画面的完整比例、消除等高网格下的大块空洞，又借底部参差露出的半张卡片勾住视线持续往下浏览。

## 2. 开场玩具：活体瀑布流砌墙台
- **怎么玩**：在取自 271 号原海报的暖羊皮纸展墙上，直接排布原海报全部 8 张同源主题插画卡（自然之旅、设计灵感、生活记录、摄影作品、徒步路线、编辑引言、视频精选、好物推荐），外加 4 张可按需异步投放的新卡。用户直接操控四个属于瀑布流本身的核心动作：
  1. **排布法则切换**：`等高行锁 (Grid)` / `纵列硬分 (Columns)` / `最短列补位 (Masonry)`；
  2. **高宽比限高闸轨 (`data-perf-drag`)**：居中宽幅横向拖拽标尺（范围 `0.70×` 到 `3.00×`），拖动时实时重算每张卡高度、瀑布流落位与 2D Canvas 水位线透视；
  3. **视口列数调节**：`2列` / `3列` / `4列` / `6列`（窄屏 `1列` / `2列` / `3列` / `4列`），按真实容器宽实时测量单卡宽度；
  4. **异步投放与预占位**：切换 `无宽高比占位` / `预写宽高比 (aspect-ratio)` 并点 `+ 投放新卡`，亲眼看到无占位时图片解码瞬间把整列顶歪的真实跳动距离（px）。
- **一打开是什么状态**：故意停在 **0/4 翻车态**——`等高行锁`（短卡下方撕出斜线标示的空洞）、限高闸停在 `3.00×`（放任超长竖图把单列拖出长尾）、列数过密（桌面 6 列、手机 4 列，单卡挤成细条）、未开启宽高比预占位。
- **怎样算玩错、错了读数怎么说**：
  - 选 `等高行锁`：Canvas 标出所有行底空洞，读数报实际浪费空洞占比与平齐行断层；
  - 选 `纵列硬分 (CSS Columns)`：看似消除了行空洞，但 Canvas 阅读动线箭暴露 `1→2→3` 竖直坠落、打破左右扫读顺序，且点 `+ 投放新卡` 会触发「旧卡跨列跳排」警告；
  - 限高闸拖太左（`≤ 1.05×`）：读数报错「裁得太扁」——所有竖图被压成方砖，参差落差归零，失去瀑布流底部露半卡的下拉诱因；
  - 限高闸拖太右（`≥ 2.00×`）：读数报错「长图霸屏」——单卡过度拉长，列尾落差超过阈值，侧列底部出现断崖；
  - 列数过密（单卡低于经验下限）报「单卡挤碎」，列数过稀（桌面仅 2 列、单卡超 450px）报「单卡过宽、多维浏览密度丢失」；
  - 未开预占位就投放新卡：实时亮起陶土色位移冲击带，标出实测下推像素与高 CLS 误触风险。
- **读数说什么「为什么」**：所有读数（空洞率、列尾落差 px、单卡实宽 px、参差起伏档位、偏移 px）均由 `model.js` 同源布局引擎实时算出，同时解释对视线连贯度、下拉动力与防误触的影响。
- **与近期 12 页的明显区别**：
  - 区别于 270（克莱因蓝卡距卡尺 + Subgrid 锁齐 + 亮黄焦点）：271 聚焦「拆掉水平线、最短列落位、防长图霸屏、CSS Columns 跳列陷阱、异步加载 CLS 偏移」，无外距卡尺、无焦点角标；
  - 区别于 269（左栏四控件 × 右栏 S 曲线单列流）：271 采用满宽多列错落瀑布墙与底部原海报四柱图标诊断带；
  - 区别于 240/296/142/102/020/309/225/129/187/019：玩法紧扣瀑布流独有的「最短列补位 + 高宽比双边甜区 + 异步投放跳动」，别的编号无法套用。

## 3. 版式骨架
- **1440×900（及 2560×1440）**：严格沿袭 271 号原海报的暖羊皮纸通栏杂志骨架——顶沿左 76% 粗体错落大标「瀑布流页面」+ `MASONRY / WATERFALL PAGE` + 原海报总述，右 24% 绘原海报四条橄榄色竖向水波流与散点徽标及 `n/4` 印章；其下是一条与纸面融为一体的紧凑砌墙调音条（无深色仪表盘框）；下方直接铺开满宽 4 列活体瀑布流展墙（2560 宽屏容器放开至 1680px，主体充实不缩心），底沿咬合原海报同款「错落 / 浏览 / 弹性 / 丰富」四柱实检带与一句白话诊断。
- **1024×1366 / 768×1024**：不锁 `min-height: 100svh`，内容自然贴合高度，调音条折叠为紧凑两行，瀑布墙自适应 3 列，零大片空白。
- **390×844（手机竖屏）**：顶标压紧为单行标题 + 小波纹印章，紧接含居中宽幅 `data-perf-drag` 高宽比滑轨的紧凑两行控制条（所有按钮 ≥ 44px 触控高度），活体瀑布流展墙在第一屏直占 ≥ 48% 屏高，底部直见单行核心诊断。
- **844×390（手机横屏）**：切为左 38% 精炼标题、控件与诊断 × 右 62% 全高瀑布墙，避免竖向压扁。

## 4. 配色和字体
- **配色（实采自 271 号原海报）**：
  - 暖羊皮纸底 `#F9EDDA` / 浅米卡面 `#F4E4CB` / 焙沙纸辅底 `#F1E1C7` / 鼠尾草米纸 `#EAE5D3`
  - 焙陶赤褐 `#CE5D2B`（高对比正文/标签深陶色 `#A13F15`，亮橙图标 `#E86A2E`）
  - 苔藓橄榄绿 `#6B6942`（深橄榄文字 `#454427`）
  - 浓缩咖深棕 `#2C2113`（深色节底 `#22190E`）与暖炭墨 `#16120D`
- **字体搭配（全库唯一，含两款最近 12 页均未使用的字体）**：
  - `Noto Sans SC`（400 / 700 / 900）：中文正文与厚实无衬线主标题（贴合原海报字形气质；正文内中英文混排统一使用，不跳字）；
  - **`Young Serif`**（400，最近 12 页未用）：节号 `01–08`、英文副标与陶土引号点缀，自带圆润手工艺印刷温润感；
  - **`DM Mono`**（400 / 500，最近 12 页未用）：原海报同款几何等宽感英文副题 `MASONRY / WATERFALL PAGE`、列高读数、高宽比刻度与指标标签。

## 5. 节目录（共 8 节，相邻两节不用同一种控件）
- **01 · 拆掉横线，补最矮列**（What breaks the grid）：原海报四要点 + 步进式单卡落砖器（点按「投下一张」/「切换轮流发牌 vs 最短列」，逐张观察列高水位差）。
- **02 · 从泥瓦脚本到泳道**（Where it comes from）：核实简史（2009 David DeSandro Masonry → 2010 Pinterest → W3C CSS Grid Level 3 `display: grid-lanes`）+ 三代引擎 X 光切换卡（附「追加第 9 张」观察旧卡是否跳列）。
- **03 · 限住长图，留出参差**（Taming extreme ratios）：双屏中缝可拖对比帘（左无上限长图霸屏 vs 右 3:4 截断配「长图」角标），直观测算首屏可见卡数与列尾落差。
- **04 · 先报比例，再放图片**（Preventing layout shift）：弱网分段加载回放剧场（播放按钮 + 模拟点击收藏目标，亲测无占位引发的误触与 CLS 暴涨 vs 预写 `aspect-ratio` 的零跳动）。
- **05 · 哪些场景最适合它**（Where it shines）：四大适用场景 + 视口宽档位速查器（手机/平板/笔记/宽屏一键切换查看经验列数、槽宽与底缘半卡露头），并一句话链接 269、272、275。
- **06 · 什么时候别用瀑布流**（When to walk away）：温和校准原海报边界（「说多了一点」标牌）+ 「找出 #07 14:20 通知」小实验对比瀑布流与对齐列表的检索耗时，一句话链接 270、274、277、286。
- **07 · 练一练：哪份设计成立**（Practice · pick the best）：四张仅标 `A/B/C/D` 的等幅缩微瀑布流线框稿，每项只差一个变量（不限高长尾 / 均衡成立 / CSS Columns 竖向跳序 / 强裁等高方砖），选后揭晓标注与原理解析。
- **08 · 原海报与关键词**（The original poster）：可放大拖拽（`draggable="false"`）的原海报与原海报四个关键词。

## 7. 练习设计
- **题目**：同一个手机发现页里的 6 条图文内容，下面四份双列设计稿里哪一份真正发挥了瀑布流的优势且没有工程隐患？
- **四项单一变量对照**（选项只标 `A`、`B`、`C`、`D`，无好坏提示词）：
  - **A**：最短列补位 + 双列恰当，但 **未限长图高度**（#2 竖长海报独占左列大部，拖出悬殊长尾）；
  - **B（正确）**：最短列补位 + 双列 + **高宽比限幅（超长图截断标「长图」）** + 底部轻度参差露出半卡；
  - **C**：双列 + 限高恰当，但 **改用纵列先填满（CSS Columns）**，编号 `1→2→3` 竖直向下，加载新卡会让旧卡整体跳列；
  - **D**：最短列补位 + 双列，但 **全部裁成统一 1:1 等高方砖**，失去原图比例优势与底缘参差引流。
