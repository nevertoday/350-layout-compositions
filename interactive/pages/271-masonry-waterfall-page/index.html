01

拆掉横线，补最矮列

BREAK THE HORIZONTAL LOCK

普通网格像货架：横线和竖线同时锁死，一张矮卡旁边放了张高图，矮卡下面就会空出一大块死角。瀑布流只保留竖向等宽的列轨，把横向那条行底线彻底拆掉——每来一张新卡，只问一个问题：此刻哪一列最矮？

相比按行齐高的卡片网格布局（270），瀑布流让原图不必为了凑齐行高而被硬裁；它落地在页面工程里，也是底层瀑布流布局（236）算法加上限高、列数与异步加载策略后的完整产品形态。

  1. 错落STAGGER

    “高度不一，自然错落”

    竖照、横视频、短笔记与引语各按原生高度生长，视口底部总会露出一两张只显半截的卡片，不自觉地勾着手指继续往下滑。

  2. 浏览BROWSE

    “顺畅浏览，视觉引导”

    没有齐整的水平切口把视线拦停，眼睛在左右列之间自然滑移，适合没有明确终点、靠偶遇惊喜驱动的漫游场景。

  3. 弹性FLEXIBLE

    “自适应排列，空间利用高效”

    窄屏收成双列，桌面舒展到四列或五列；每张卡都紧贴上一张卡的底边，屏效比等高网格高出一截。

  4. 丰富RICH

    “容纳多样内容，信息层次丰富”

    一张图配两行字、纯文字金句、带播放标的短视频、商品推荐可以同屏共存，靠底色和体量自然拉开节奏。

02

从泥瓦脚本到泳道

WHERE IT COMES FROM

英文里的 Masonry 原意是“石匠砌墙”——挑选大小不一的石头严丝合缝地嵌进空档。这种版式在网页里走过了十五年以上，从早期的脚本补丁一路演进到浏览器原生规范。

  1. 2009–2010

    David DeSandro 写出开源库 Masonry

    他在学习 jQuery 时为了消除 CSS 浮动留下的竖向空隙，做了“像泥瓦匠砌墙一样先竖后横填缝”的插件 jQuery Masonry，并于 2011 年 5 月重写发布 v2.0，随后推出配套的 imagesLoaded 解决图片未就绪导致的叠压。

  2. 2010.03

    Pinterest 把图钉板带进主流消费产品

    Ben Silbermann、Paul Sciarra 与建筑学背景的 Evan Sharp 推出 Pinterest 内测版，将物理灵感图钉板转译为多列不等高卡片墙，迅速确立了视觉发现页的范式，中文互联网随后习惯称它“瀑布流”。

  3. 2020s–至今

    W3C CSS Grid Level 3 收敛至 display: grid-lanes

    Firefox 率先在实验开关后试水 grid-template-rows: masonry；围绕“该并入 Grid 还是独立模型”争论多年后，CSS 工作组逐步收敛至原生 display: grid-lanes 方向，让浏览器直接接管最短列排布并兼容逻辑阅读顺序。

PREVENTING LAYOUT SHIFT

        

        

          
瀑布流最隐蔽的体验事故不在静态画面，而在加载那一秒：如果不预先告诉浏览器每张图的宽高比，图片晚到 400 毫秒撑开高度，就会把用户正准备点下去的那张卡狠狠踹向下方。

          
Google 核心网页指标里的累积布局偏移（CLS，良好线 ≤ 0.1）专门衡量这种意外跳动。成熟的做法是在接口返回列表数据时顺带吐出每张图的原始宽高，前端先用 HTML 的 width / height 或 CSS 的 aspect-ratio 占住坑位，图到了只做填充、不挪坐标。

WHERE IT SHINES & COLUMN SCALE

          

          
当读者抱着“随便逛逛、看看有什么新鲜事”的心态进来，且内容本身混杂着横竖照片、文字笔记与轻视频时，瀑布流才显出真正的活力。

什么时候别用它

          
WHEN TO WALK AWAY

        

        

          

            海报说多了一点
            
原海报总述写它“适配多维信息与持续浏览场景”。后半句“持续浏览”很准，但遇到需要横向比参数、按时间回溯、或带着明确目标找一条记录的多维信息时，错落排列反而会帮倒忙。

          


          

            

              
横向比价与参数筛选

              
左右卡片基线错位，眼睛没法水平扫过价格、规格和按钮。这类任务该交给卡片网格布局（270）或数据表格布局（274）。

            

            

              
强时间顺序的日志与动态

              
第 4 条卡片落进第 2 列、第 5 条又跳去第 4 列，读者根本分不清哪条更新。需要先后透明时，请用时间线布局（277）。

            

            

              
目标明确的精准搜索

              
用户已经知道自己在找什么，需要一条清晰的单列扫描轴和可回退的页码，宜用搜索结果布局（286）。
