          01
          

            
幽灵原位：流中不动，画布微移

            
TWO-PASS NORMAL FLOW & GHOST FOOTPRINT

          

        


        

          

            

              海报原话
              「参照原位：元素在文档流中的原始位置。保留占位：原位置的空间仍被保留。相对自身：从自身原始位置进行偏移。」
            

            

              浏览器渲染相对定位走的是干净的两阶段流程：第一步完全按
              222 普通流布局
              把所有元素的尺寸、折行和位置算定；第二步才单独把 position: relative 的视觉外观搬离原位。
            

            

              正因为后续元素早在第一步就定死了坐标，它既不会向前补位，也不会被你推走——哪怕是正文中间的一个行内标签（<span>），移走后行间照样留出与它等宽的透明缺口。
            

            

              容易忽略的细节：海报要点总结写着「不影响其他元素位置」，对普通流里的兄弟确实成立；但如果父容器设了 overflow: auto，相对定位把视觉盒往右或往下推出边界时，仍会把可滚动区域撑大并呼出滚动条。

              方向少说了一半
              海报底部写着「正值（+）向右 / 向下移动；负值（-）向左 / 向上移动」，并在示意图里把向下箭头标作 bottom(+)、向右箭头标作 right(+)。
            

            

              这其实是 CSS 里最容易看反的一件事：top / right / bottom / left 在规范里叫内缩属性（inset properties），正值代表「从元素原本的那条边向盒子内侧推」，并不是直角坐标系里的 X/Y 轴。
            

            
    
              
  • top: +28px / left: +32px：从原顶边向下推、从原左边向右推——只有这两条符合海报的口诀。
    • 
              
  • bottom: +28px / right: +32px：从原底边向上推、从原右边向左推！你可以立刻在旁边点「试设 bottom:+28 / right:+32」，看真实红块 C 往左上方跑去。
    • 
              
  • 同时写对边会触发过约束：按 CSS 2.1 §9.4.3，同时写 top 和 bottom 时 bottom 被丢弃；同时写 left 和 right 时，LTR 丢弃 right，切到阿拉伯语等 RTL 书写方向后反过来丢弃 left。
    • 
            

            

              在现代多语言项目里，CSS Positioned Layout Level 3 推荐使用跟随书写方向的逻辑属性 inset-block-start 与 inset-inline-start，把物理左右彻底解耦。
            

          

        

      

    


    
    

      

        

          03
          

            
零偏移真身：锚点与层叠陷阱

            
CONTAINING BLOCK & STACKING CONTEXT TRAP

          

        


        

          

            

              打开任意大型网站样式表，你会发现绝大多数 position: relative 一行 top / left 都没写。大家请它出场，不是为了挪动自己，而是为了两项不可替代的后台职责：
            

            

              第一，为内部的
              233 绝对定位布局
              或
              237 覆盖布局
              子件提供局部原点（包含块），让未读红点、角标、浮层菜单老老实实挂在所属卡片身上，而不是飞到整页边缘。
            

            

              第二，打开 z-index 权限——但这里藏着前端最高频的层叠陷阱：只写 position: relative（保持 z-index: auto）不会隔离后代；一旦你给父卡写上任何整数（哪怕 z-index: 1），它就建起一座独立层叠上下文。里面子菜单写到 z-index: 9999，也永远压不过外面 z-index: 2 的兄弟卡片。

          06
          

            
什么时候别用：别拿微调干排版

            
WHEN NOT TO USE IT & RENDERING PIPELINE

          

        


        

          

            

              忌 01
              

                
别用来拼整页多栏或大距离挪位

                
大偏移会留出巨型空白幽灵洞并盖死邻居，换块屏幕就错位。多栏骨架交给 226 弹性盒布局 或 227 网格布局。

              

            


            

              忌 02
              

                
别用 top / left 跑高频位移和悬停动画

                
每帧改 top / left 容易在浏览器主线程触发重排与重绘；持续位移、悬停弹起应优先写 transform: translate()，直接走合成层（GPU），且同样保留文档流原位。

              

            


            

              忌 03
              

                
别指望把块移走后下方内容自动顶上来

                
相对定位永远死守原坑。真要脱离文档流、悬浮吸顶或文字绕排，请分别选用 233 绝对定位、234 固定定位、235 粘性定位 或 231 浮动布局。

              

            


            

              忌 04
              

                
别给每个容器顺手补上 z-index: 1

                
只需要做包含块时，只写 position: relative、把 z-index 留作 auto，避免无意间建起一串层叠牢笼困死内部弹层。
