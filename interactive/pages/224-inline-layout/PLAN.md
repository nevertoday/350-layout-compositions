# 224 行内布局（INLINE LAYOUT）设计方案

## 1. 一句话道理
行内布局不是把元素机械横排，而是让文字、数字、图标、芯片与按钮共乘同一套行盒（Line Box）和基线坐标系，在不打断横向阅读流的前提下，通过控制高度差、垂直对齐与节奏间距，让视线一次平顺扫过整行信息。

## 2. 开场玩具：活体行内流道 · 基线校准轨（Inline Baseline Rail Workbench）
- **形态与真实性**：真实浏览器 CSS 行内格式化上下文（IFC）流道 DOM + 严丝合缝叠合的 2D Canvas X-Ray 基线/行盒/视心测绘层（所有坐标、折行数、行盒高度、基线偏差均从实绘 DOM 的 `getBoundingClientRect()` 与字体基线探针实时采集，交由 `model.js` 单真源统一判定）。
- **三套原海报真实 UI 场景**：
  1. `文本信息行`（原海报第 1 行：`新品上市` `|` `限时优惠` `[低至 7 折]` `活动时间：05.01–05.31` `[立即购买]` `→`）
  2. `元数据行`（原海报第 2 行：`设计师` `•` `2024.05.18` `阅读 3 分钟` `•` `[教程]` `#排版` 书签图标）
  3. `状态与操作行`（原海报第 3 行：`已保存` `•` `[草稿]` `协作者：[三叠圆标] +2` `•` `分享` `[发布]`）
- **怎么玩**：
  - **横向拖拉流道右端朱橙箭柄（或流道可拖区，标 `data-perf-drag`）**：实时推拉容器可用行宽（`300px`–`100%`），亲眼看到真实行内流如何自动折行生成多条行盒与独立基线。
  - **直接点击流道里的任意元素**（文字、芯片、图标、按钮），在紧贴流道底沿的「元素属性刀闸」里实时切换它的真 CSS 属性：`display`（`block` / `inline` / `inline-flex`）、`vertical-align`（`top` / `baseline` / `middle` / `bottom`）、元素高度倍率（正常 / 过高撑爆），以及整行的节奏间距（`0px`–`28px`）与信息权重对比。
  - **按 `Space`（或点击「扫视验流」）**：沿每个元素的真实渲染中心放飞一束眼动扫视轨迹光束，直观对比平滑水平流与断行锯齿折返。
  - **右上角原海报同款奶白正圆标本镜**（`● — [—] ○ ★`）实时同步当前流道的基线稳定度，错态时符号高低错落，达标时稳落同一虚线。
- **开场状态（非答案）**：刻意停在 `0/4` 复合错态——原海报「文本信息行」中 `[低至 7 折]` 芯片被误设 `display: block` 强行把一行劈成三段、高度撑爆到 `46px`、`[立即购买]` 顶撞 `vertical-align: top` 偏离基线、节奏间距 `0px` 粘连且主次压平。
- **怎样算玩错（双向检出 9 类正反错态）**：
  - 误用 `display: block` 劈裂连续流（`BLOCK_BREAK`）；
  - `vertical-align` 选错造成图标/芯片上下跳动（`BASELINE_DRIFT`）；
  - 单个芯片/按钮过高撑裂整条行盒（`HEIGHT_SPIKE`）；
  - 节奏间距过窄 `≤2px` 造成文字粘连（`GAP_CRAMPED`）或过宽 `≥24px` 造成散架断气（`GAP_SCATTERED`）；
  - 容器拖得过窄导致强行碎折成 3+ 行（`WRAP_FRAGMENTS`）；
  - 权重全平缺乏主次区分（`HIERARCHY_FLAT`）；
  - 全部纯 `inline` 强设垂直高宽失效或串行（`INLINE_BOX_TRAP`）。
  - 读数既报实测数据，也用白话直指「人眼读到这里为什么会卡顿/折返」，并认可多种合法解（原海报标准流 / 紧凑工具栏流 / 宽幅大字流 / 用户手调任意达标态）。
- **与最近 12 页的区别**：最近 12 页全是 2D 构图/排版静态画框或天平/星图/暗房/藏室，且无薄荷青纸色系；本页以真实 CSS 行内流 DOM 与基线测绘为核，操作的是行内元素的 `display`、`vertical-align`、高度差与流道行宽，无法原样套用给任何其他编号。

## 3. 版式骨架
忠实转译 224 原海报「薄荷青底全宽水平流道展板」骨架（不锁 `min-height: 100svh`，避免平板留白）：
- **1440×900（主宽 1360px；2560×1440 舒展至 1600px）**：顶部原海报招牌刊头带——左侧超粗纯黑自示范标题「行内布局」紧踩全宽信号朱橙长箭头 `━━━━━━▶`、下方朱橙 `INLINE LAYOUT` 与三场景切签，右侧悬浮原海报同款奶白正圆标本镜；紧接全宽三枚翡翠圆徽实况探针带（同一行 / 基线 / 连续性）→ 全宽奶白圆角活体行内流道（含 X-Ray 叠层与朱橙箭宽拖柄）→ 紧贴流道底沿的左诊单右元素 CSS 刀闸控制坞。
- **390×844（手机竖屏）**：单行压紧顶部标题+迷你标本徽+朱橙细箭，总述与三圆徽探针后置，让全宽活体流道画布（保持清晰可读、绝不压扁）+ 诊单首句 + 主修复/验流双键稳占首屏 ≥46%。

## 5. 节目录（7 节，每节标题 ≤12 字，明暗交替、控件不重复）
- **01 基线不是几何中心**（浅薄荷纸）：温和纠偏原海报「视觉重心落在基线上」，1:1 复刻原海报 10 枚混排标本（视觉/对齐/文字/Icon/♡/123/●/ABC/标签/★），提供「4 模式对齐切换 + 点击任意标本放大检视 em-box / x-height / baseline」。
- **02 隐形支柱与行盒**（奶白纸）：拆解 W3C CSS 2.1 §10.8 隐形支柱（Strut）与半行距，通过「分层剥离复选开关 + 行高/字号双滑轨」驱动 2D Canvas 剖面图，现场解释图片底部神秘 4px 缝隙的成因与解法。
- **03 四个行内盒暗礁**（深松青暗室）：用「4 标签真 CSS 实况槽 + inline / inline-block / inline-flex 开关」现场暴露 width 失效、上下 margin 无效、上下 padding 串行与 HTML 换行幽灵空格。
- **04 源流与原海报三场景**（浅薄荷纸）：梳理 Knuth《The TeXbook》(1984) → W3C CSS1 (1996) → Eric Meyer (2000) → CSS 2.1 (2011) → CSS Inline Layout Level 3 (`text-box-trim`) 源流（点击时间轴节点展开）；下方配备原海报「推荐行内 vs 非行内」交互滑幕对照，并一句话链接兄弟页 222/223/225/226/227。
- **05 什么时候别用行内**（奶白纸）：四组真实失效反例卡（纵向数据列、双端撑开导航、独立定宽图文卡片、移动端超长参数串），每张卡片带「一键换正解」动画演示并指向 230/226/223/227 在线页。
- **06 挑出稳当的行内方案**（深松青暗室）：四选一单变量实战练习，选后揭示逐项因果并点亮每张标本的基线透视线。

## 7. 小练习设计
- **题干**：文章顶部元数据行（作者图标 + 作者名 · 日期 · 阅读时长 · 分类芯片 · 收藏按钮），在字号、颜色、文案完全相同的情况下，下面 4 套行内排布与对齐设置（只差「行内排布与对齐」一个变量）里哪一套最适合快速扫读？
- **四选项（标签仅写方案 A/B/C/D + 中性 CSS 参数，零剧透）**：
  - 方案 A：元素全用 `inline-block`，全部 `vertical-align: baseline`，分类芯片高 `42px`
  - 方案 B：文字基线对齐，图标与 `24px` 芯片 `vertical-align: middle` 对齐文本视中，项间 `10px` 留白
  - 方案 C：作者、日期、分类芯片与收藏均设 `display: block` 纵向左对齐排开
  - 方案 D：元素全用 `inline-block`，全设 `vertical-align: top`，项间留白 `0px`
- **正确答案与理由**：**方案 B**。A 因芯片高度差过大撑裂行盒、导致图标底缘下沉；C 打断行内连续流变成块级堆叠，增加扫视折返；D 顶对齐让小字和按钮各自飘浮且零间距粘连；唯独 B 控制住高度差、让图标与小芯片在文本视中落位并留出清晰呼吸节奏。
