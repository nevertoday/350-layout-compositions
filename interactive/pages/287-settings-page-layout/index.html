    分组为什么能省眼力

    Grouping, Proximity & Hick–Hyman Law

    原海报 · 分组 「将相关设置放在同一模块内，形成清晰的视觉分区。」

    面对 16 个平铺排开的设置项，眼睛只能像扫货架一样从第一条逐行读到最后一条。心理学家威廉·希克（1952）与雷·海曼（1953）发现，人类在等概率选项中做选择的时间随选项数呈对数增长；当选项被收进 4 个语义明确的分组时，大脑先按组名瞬间排掉四分之三的无关区域，只需在命中的小组内扫描三四行。

    补一句 分组不是越多越好：如果按技术模块命名（比如「缓存策略」「持久化钩子」）而非用户任务，或者把 16 项硬拆成三级深层抽屉，找起来反而比平铺更慢。当全站设置超过约 30 项（经验值）时，应配合左侧搜索框做即时过滤，具体检索结果呈现见 286 搜索结果布局，多层目录组织见 290 分层导航布局。

    选对控件胜过写说明

    Control Semantics & Progressive Disclosure

    原海报 · 控件层级 「通过控件类型与排版区分主次，降低认知负担。」

    好控件自己会说话：看到开关，用户知道一拨就通电；看到分段按钮，知道几个选项互斥单选；看到复选框，知道能多选并随表单提交。把互斥单选用成复选框、把 3 个常用词藏进下拉框，或者把危险的「重置所有设置」做成最显眼的按钮，都是设置页最常见的层级事故。按照施乐之星（1981）确立的渐进披露思路，低频技术项（如响应式断点、行宽上限）应默认折叠在底端，只在需要时展开。

    即时生效还是点保存

    Feedback Loop & Commit Model

    原海报 · 反馈 「通过状态变化及时反馈操作结果，增强可信感与可控性。」

    唐·诺曼在《设计心理学》（1988 年首版，2013 年修订版）里把用户最大的焦虑称为「评估鸿沟」——我按下去之后，系统到底听见没有？雅各布·尼尔森（1994）的第一条可用性启发式也正是「系统状态可见性」。对于屏幕阅读器用户，W3C WAI-ARIA 规范建议用 role="status" 温和播报保存结果，既不抢走焦点也不让用户蒙在鼓里。

    细看原海报 原海报里同时出现了即时感很强的开关（如「显示页眉区域」）和底部的「保存设置 / 取消」按钮。真实工程里尽量别把两种生效规则混在同一区域：轻量偏好用「即时生效 + 轻提示与撤销」；会触发重算或有风险的配置则用「草稿态 + 显式保存」，高危重置再配合确认弹窗（见 281 对话布局）；若是一次性提交录入，直接归回 284 表单布局。

    留白与密度的比例尺

    Spacing Ratio & Touch Target Floor

    原海报 · 留白与间距 「合理的留白与间距提升信息可读性，强化模块边界。」

    很多人以为分组靠的是画粗框，其实最稳妥的分界线是外距大于内距。依据格式塔接近律，经验上当组间外距达到组内行距的 1.8×–2.5× 时，哪怕去掉卡片边框，眼睛也能瞬间识别哪几行同属一家；一旦组内行距反超组间外距，视觉归属立刻倒挂，页面看似「很宽松」实则支离破碎。

    原海报底部的三档密度（紧凑 / 标准 / 宽松）本质上是面向不同熟练度用户的权衡：高频专业工具（代码编辑器、云控制台）可选紧凑档一屏多显，但触屏设备上仍需守住约 40–44px 的最小点击高度（苹果 HIG 建议 44pt），防止手指一按连带碰坏相邻开关。

    外 / 内 = 2.00× 处于 1.8×–2.5× 经验舒适带，两组边界清楚、组内凝聚力稳固。

    实时按上方像素值绘制 · 开启「44px 触屏靶区」可直观察看行距过窄时相邻开关是否发生手指碰撞。

    什么时候别做设置页

    When Not to Use & Single-Variable Practice

    USE IT WHEN

    适合用设置页面布局

    • 需要长期生效、调整频率较低的全局偏好（语言、通知策略、安全权限、排版默认值）。
    • 参数超过 6–8 项、横跨多个主题域，需要靠侧栏分组、搜索与恢复默认降低心智成本。
    • 调整结果直接改变整体工作环境，像 287 原海报那样能配合实时预览即时验证。

    SKIP IT WHEN

    这四种情况，别硬做设置页

    • 别把默认值偷懒推给用户：雅各布·尼尔森（2005）指出绝大多数用户几乎从不修改默认设置——能自动跟系统的深浅色或时区，先默认做对。
    • 高频操作别藏进设置页：写作时常调的对齐、字号应做在就地工具栏（见 283 画布工作区布局），进设置页会直接打断心流。
    • 一次性线性采集请换表单：账号注册、下单结账走 284 表单布局 或 285 分步表单；全局数据监控走 273 仪表盘布局；大量批量记录编辑走 274 数据表格布局；层级目录资源浏览走 280 树形浏览布局。
    • 少于 4–5 项别硬套三栏大窗：一个轻量弹窗或单列卡片就能清清爽爽装下，多一层侧边栏反而画蛇添足。
    PRACTICE · SINGLE VARIABLE

    小练习：6 项导出设置，哪套结构最顺手？

    假设你要改版一款笔记应用的「导出设置」，一共只有 6 个选项：日常常用的「文件格式、包含目录、图片压缩、默认路径」4 项，外加极少用的「实验性 PDF 引擎、自定义 CSS 模板」2 项高级参数。以下四套方案的配色、字体和控件类型完全相同，只差「分组与披露结构」这一个变量，你会选哪一套？
