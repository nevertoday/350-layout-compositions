# 287 设置页面布局 · 设计方案（PLAN）

## 1. 一句话道理
设置页的核心不是把所有开关堆在同一块屏上，而是通过**主题分组、语义化控件层级、清晰的状态反馈与有节奏的留白密度**，让用户不靠说明书也能迅速定位目标选项、预判操作后果并安心确认改动。

## 2. 开场玩具（活体设置页架构诊修台）
- **玩法**：直接化用 287 原海报的「左暗灰导航 + 中间配置区 + 右侧实时预览与反馈」三栏桌面设置窗口。用户可以：
  1. 在右侧实时预览画布（标 `data-perf-drag`）上直接**左右拖拽侧边栏/主内容区分界线**（或方向键微调），以 60fps 实时改变主内容区与侧边栏宽度比例，联动中间滑块、当前信息表与临界宽度警告（如原海报的「侧边栏宽度过小」）；
  2. 直接操作窗口内的真实控件（切换布局模式卡片、拨动开关、切对齐与间距、点保存/取消/重置、切左侧导航分组，以及切换「原海报·页面布局 / 通知提醒 / 隐私安全」三套真实设置场景）；
  3. 调整窗口顶部的四维架构开关（分组 / 控件层级 / 反馈机制 / 留白密度）与底沿原海报三档密度卡，亲手把糟糕架构修成有序布局，也可故意踩入多种反模式。
- **开场错态（0/4 待梳理）**：一打开不是答案，而是刻意落在 4 项全错的真实烂设置页——12 项设置平铺一锅端零分组、布局模式错用复选框且危险「重置所有设置」漆成翠青主按钮反客为主、高级选项摊在最顶、静默无反馈且侧边栏被挤窄到 14% 却毫无警告、组内 4px 与组间 6px 窒息粘连。
- **怎样算玩错与单真源读数**：由 `model.js` 单真源核算 10 类真实失误（平铺混排、过度碎卡、控件错配与危险钮抢戏、全员下拉盲盒、静默无反馈、高频弹窗骚扰、粘连窒息、组内宽于组间归属倒挂、侧边栏过窄 `<18%`、侧边栏过宽挤塌主区 `>44%`）。读数不报虚伪精确分数，只报几何比例、外内距比、错配计数、未保存变更数，以及标注「示意」的希克选择深度，并解释「为什么这样排会让人怎么看」。接受「原海报标准解」「专业紧凑解」「新手宽松解」多组合法解。
- **与最近 12 页的差异**：不同于 286 搜索结果倒排页、285 分步切分轨、324 朱砂裁景刀窗、244 盒模型剥层、243 垂直堆栈、202 等距网格等，本页是真实可操作、可拖分栏预览、可故意改坏再修好的**三栏桌面设置应用本体**。

## 3. 版式骨架
- **1440×900（主宽 1380px）与 2560×1440（舒展至 1760px）**：不锁 `100svh`。顶部开放冷灰白刊头（左黑青双色自示范大标 + 实时校准徽，右原海报青黄重叠几何徽与 5×6 点阵）→ 下承左 21% 原海报四色折线标注脊与单真源诊单 × 右 79% 三栏浮窗设置工作台 → 全宽白底底坞（左「布局原则」四实况徽 × 右「控件密度示例」三张可点线框卡）。
- **1024×1366 & 768×1024 平板**：自然流排零空洞；诊单收成横带置于三栏窗上方，768 宽下暗色导航栏折叠为顶横标签条保证控件与预览舒展不挤压。
- **390×844 竖屏手机**：压紧单行刊头与场景签；把**实时预览画布（`data-perf-drag`）**与精简架构条、诊单首句前置到首屏 ≥50% 视口高度，下方流畅展开真实控件与反馈操作，全部触控区 ≥40px，绝不横向溢出或压扁图形。
- **844×390 横屏手机**：左 55% 实时预览画布与主控区 × 右 45% 紧凑刊头、单真源诊单与四维架构条并行。

## 4. 配色和字体
- **配色（逐像素实采自 287 原海报）**：冷灰白展纸 `#F1F2F4` / 纯白工作窗 `#FFFFFF` / 柔灰卡 `#F8F9FA` / 冷雾底 `#EAEEF1`；主强调翠青绿 `#098781`（浅底高对比压深字 `#066E69`，暗室亮青 `#4CD4CB`）；深青灰暗侧栏与 03 暗室 `#283238` / `#1D262C`；明黄琥珀信号 `#FDBE02`（浅底高对比文字 `#8A5E00`，暗底亮琥珀 `#FFD147`）；操作反馈绿 `#E4F2EC/#0B5E42`、警告黄 `#FCF4E1/#7E5200`、信息蓝 `#E8EFF5/#1F4F7A`、警示赤 `#FDECEC/#A61D24`；纯墨 `#0A0D10`。
- **字体（全库唯一，三款西文在近 12 页全部 0 次使用）**：`Noto Sans SC`（正文与中文标题）+ `IBM Plex Sans`（工业感英文副标与标签）+ `Playfair Display`（正/斜体，用于节号与编辑引语）+ `Space Mono`（等宽像素/百分比读数与技术标注）。

## 5. 节目录（7 节 + 页脚，相邻节零控件重复）
- `01` **分组为什么能省眼力**（10字）：格式塔接近律与希克定律 → 交互：**限时找设置秒表挑战**（平铺/分组/深嵌三结构真实找项计时）。
- `02` **选对控件胜过写说明**（10字）：控件类型与语义匹配、渐进披露与危险项降权 → 交互：**5 项任务控件配对诊台**（点选控件块插槽，实时试交互与反馈）。
- `03` **即时生效还是点保存**（10字，深青灰暗室）：诺曼反馈闭环、原海报开关与保存钮混用的细节辨析 → 交互：**生效模型与反馈时序 2D 模拟仪**（切即时/草稿/静默三模式 + 注入延迟/校验冲突看状态波）。
- `04` **留白与密度的比例尺**（10字）：外距/内距经验比（1.8–2.5×）与 44px 触控底线 → 交互：**双滑杆留白蓝图画布**（实时调组内/组间像素 + 触控靶区重叠 X 光）。
- `05` **从属性表到侧栏设置**（10字）：1981 Xerox Star → 1984 Mac Control Panel → 2001 System Preferences → 2022 System Settings → 交互：**四代设置架构线框演化器**（切换 4 个年代同题对比）。
- `06` **什么时候别做设置页**（10字）：适用边界、四个反例（链接 283/284/285/273/280/274/281）+ **单变量四选一小练习**（仅差分组与披露结构，A/B/C/D 中性标签 + 微型线框图）。
- `07` **原海报与关键词**（7字）：高清原海报（点击放大灯箱、拖拽、Esc 关闭）+ 原海报四要点/四原则/密度说明与同类小节导航。

## 7. 小练习
- **题目**：给一款笔记应用的「导出设置」（6 项：文件格式、包含目录、图片压缩、默认路径，外加低频的「实验性 PDF 引擎」「自定义 CSS 模板」）选版式；四套方案配色、控件、字体全相同，仅改变「分组与披露结构」一个变量。
- **选项（全中性描述）**：
  - A：6 项按常用到冷门等距单列排开，全部默认展开
  - B：分「基础导出（4 项）」与「高级选项（2 项，默认折叠）」两块，组间留白为组内 2 倍
  - C：左侧设 6 项独立侧栏标签，每点一项在右侧展示该单个控件
  - D：平分「常规」「排版」「路径」三张横排卡片，各自带独立「保存」按钮
- **正解**：B（清晰归类 + 渐进披露收起低频高风险项 + 统一保存闭环；A 缺乏主次边界、C 对 6 项过度导航增加跳转成本、D 拆出三个独立保存按钮制造提交状态困惑）。
