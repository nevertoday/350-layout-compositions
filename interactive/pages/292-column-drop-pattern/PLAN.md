# 292 · 列下落模式（Column Drop Pattern）互动版方案

## 1. 一句话道理
当屏幕宽度收窄到容不下所有并排列时，与其把每一列都压成难以阅读的细条，不如按内容重要度把次要列逐级「放落」到主栏下方——用列序保住主角，用落差建立从高到低的阅读动线，让每一列在任何屏宽下都留在舒服的阅读宽度内。

## 2. 开场玩具
- **命名**：重力列下落阶梯台（Matte-Graphite Column-Drop Monolith，2D Canvas 开放建筑立面台，带 `data-perf-drag`）。
- **视觉母题**：1:1 承袭 292 号原海报的哑光炭黑底、四根酸柠黄/粉笔白/酸柠黄/烈焰橘垂直立柱（带悬浮双线顶帽、大字标与底端虚线垂坠空心圆）、右上凹腔概念区、最右侧虚线视流动线脊，以及底沿点阵 + 四枚几何要点图符 + 通栏起止箭头。
- **玩法**：
  1. **横拖画布（`data-perf-drag`，支持触屏横向与键盘 `←/→`）**：在 `360px–1280px` 连续收缩/拉宽视口通道，实时触发真实重力列下落（4 列 → 3+1 → 2+2 → 1 列，或三栏资讯站 3 → 2+1 → 1），并画出橘色抛物落轨 `↘` 与每列实绘像素宽。
  2. **直拖立柱顶帽（纵向）**：直接拉高/压低任意一列高度，检验原海报「由高到低」阶梯落差；亦可切换平齐、陡崖、逆坡试错。
  3. **直点列序勋章（`#1`–`#4`）**：点击两列互换优先顺位（决定哪列稳居高位、哪列先下落）。
  4. **三套真实现场切换**：`原海报 · 四列阶梯`、`三栏资讯站`、`多维产品目录`，并可切换 **CSS `order` 错序开关** 直观看到键盘 Tab 焦点乱跳。
- **开场初始状态（绝非答案）**：刻意停在 **`0/4 · 挤扁倒挂错态`** —— 视口停在 `740px` 平板宽但下落阈值锁死在 `140px`（四列硬挤到每列 `163px` 窒息）；四列高度倒挂（`68% / 68% / 68% / 92%`，末列反超首列呈逆坡）；主栏优先顺位被放进末位（一收窄就会先坠到底层）；同时开启了脱离 DOM 源序的 CSS `order` 导致 Tab 焦点逆跳 3 处。
- **双向玩错机制**：
  - 阈值过低（`< 215px`）→ **挤压窒息**（列宽过窄折行破碎）；阈值过高（`> 335px`）→ **过早塌陷**（大屏浪费横向空间，提早堆成单长柱）。
  - 高度平齐（坡差 `< 14%`）→ **平顶无峰**；末高首低（负坡差）→ **逆坡倒灌**；高差过激（末列 `< 34%`）→ **断崖压扁**。
  - 主栏不在高位顺位 → **主栏先坠**；开启错位 CSS `order` → **WCAG 1.3.2 Tab 逆跳**。
  - 接受多组合法解：`原海报阶梯解`、`Wroblewski 三阶解`、`出版宽松解`。
- **单真源读数**：`model.js` 的 `evaluate(state)` 由当前帧实绘几何矩形统一算出最窄列实宽、活跃/下落列数、高差坡度、主栏落位、Tab 逆跳数与节奏档位（标「示意」），同步驱动画布、诊单白话和底沿四枚原海报要点卡。
- **与近期 12 页的明确区隔**：
  - 不同于 291（亮奶油纸浏览器视口+外边距+S丝带）：292 无浏览器外壳、无外边距扩张玩法，而是哑光炭黑建筑立柱重力下落 + 可直接拽动每列高度与交换下落顺位 + WCAG 焦点连线验错。
  - 不同于 327（玄墨纯白对称负形雕刻）和 206/248（克莱因蓝网格/切换器）：292 用炭黑 × 酸柠黄 × 粉笔白 × 烈焰橘，且首屏把原海报四列阶梯与右上概念凹腔、右侧四阶动线脊融为一体。

## 3. 版式骨架
- **绝不锁 `min-height: 100svh`**（防止 1024×1366 与 768×1024 平板大面积空洞）。
- **1440×900（宽屏主宽 1380px，2560 舒展至 1760px）**：
  - 极细单行眉标 → 阶梯自示范刊头（左：按原海报高度阶梯错落的四枚顶帽字块 `列 / 下 / 落 / 模式` + `COLUMN DROP PATTERN`；右：原海报竖线 `概念解析` 与三题材切签）
  - 核心双区联台：左 `68%` 哑光炭黑重力列下落画布（右侧自带原海报四阶虚线视流动线脊） × 右 `32%` 单真源诊单卡 + 精控微调槽（视口宽/下落阈值/高度节奏/DOM顺序与多解试错快钮）
  - 紧接 1:1 复刻原海报底部「`模式要点 KEY POINTS` 7×4 酸柠点阵 + 四枚实时几何图符柱 + 通栏 `起点 → 视觉动线 → 终点` 酸柠长箭」收束首屏。
- **390×844（手机竖屏）**：单行极简眉标 + 紧致单行阶梯标题（总述后置），等比画布稳占首屏 ≥ 46% 高度且不压扁，画布下直露单真源诊单首句与关键一步校准钮。
- **844×390（手机横屏）**：左 `56%` 重力列下落画布 × 右 `44%` 紧凑标题与诊单并行，首屏完整可见。
- **正文节奏**：七节在「暖粉笔白 `#F4F1EA` → 浅苔灰纸 `#EAECE2` → 03 深炭黑暗室 `#191C1B` → 暖粉笔白 `#F4F1EA` → 淡羊皮纸 `#F9F7F2` → 浅苔灰纸 `#EAECE2` → 07 深炭展墙 `#151817`」之间明暗交替。

## 7. 小练习设计
- **题干**：一份三栏技术文档页（主正文 60%、右侧目录 22%、相关示例 18%）正在适配 `768px` 平板竖屏。四套方案字号、色彩、间距完全一致，仅在「768px 断点处如何下落」这一变量上不同，哪一套最符合列下落模式的核心原则？
- **四个中性选项（只差「怎么下落」单一变量）**：
  - `方案 A`：三栏维持同行，按比例压缩为 440px / 160px / 132px。
  - `方案 B`（正确）：正文 530px 与目录 206px 留顶行，相关示例率先下落到底部通栏，DOM 源序保持正文在前。
  - `方案 C`：在 768px 直接三栏全拆成三行 100% 通栏堆叠。
  - `方案 D`：正文先落到底部通栏，目录与示例并排占顶行，再用 CSS `order` 调整显示顺序。
- **正确理由**：列下落的核心是「按宽逐级放落次要列，保住主列与高频辅助列的舒适读宽」。768px 下同时放三列会挤碎侧栏（A），一口气全堆叠又浪费了平板横宽并过早藏起目录（C），把主栏先踢到底层并改 `order` 则同时违背优先级与键盘无障碍顺序（D）；只先放落最低优先级的相关示例（B），兼顾了正文读宽、目录直达与 DOM 顺序一致。
