01

为什么普通流最省脑

Why Linear Flow Cuts Cognitive Load

海报用三句话概括了普通流的全部底气：顺序让读者无需思考路径，节奏给呼吸留出停顿，连续阅读让上下句始终粘在一起。当界面只剩一条单一纵轴时，大脑不必每看完一段就重新扫屏寻找「下一块该看哪」，注意力全部留给了内容本身。

02

块怎么自己推开位置

How Normal Flow Computes Boxes

根据 W3C CSS 2.1 第 9.4 节的定义，所有未设置浮动或绝对定位的元素默认都活在普通流里：块级盒沿纵轴一个个叠排（详见223 块级布局），行内盒在行内从左到右折行铺开（详见224 行内布局）。普通流最宝贵的能力是彼此感知——任意一块内容变长，下面所有兄弟块都会自动往下让位。下面这块沙盒用的是真实浏览器 DOM 渲染，直接动手试：

第一段实测高 -- px
兄弟块顺流下推 +0 px
块间实测净距 -- px

<p> 这是普通流里的第一段正文。只要不写死像素高度，文字变多时它会自动撑高。 外边距折叠：24px + 18px → 取大值 24px

<div> 紧随其后的兄弟块
行内标签 A 行内标签 B 行内标签 C
<footer> 底部收束段：始终安稳跟在兄弟块下方，彼此绝不覆盖。

默认普通流：内容变长，兄弟自动下移

点一下「+ 往第一段加一句字」，盯住下方兄弟块的位置变化和上方实测像素值。如果需要彻底隔离内部浮动或阻止外边距穿透，可以用 display: flow-root 建立独立块格式化上下文（详见225 流根布局）。

.lead { position: static; height: auto; margin-bottom: 24px; }
.sibling { margin-top: 18px; } /* BFC 实测净距 24px */
03

从哪来：网页生来是流

Origins & W3C Specification History

纸书印刷先定死开本与坐标，再把字塞进框里；而万维网从诞生第一天起，面对的就是尺寸各异的终端屏幕。普通流不是「简陋的默认样式」，而是为了让同一份 HTML 文档在任何设备上都能无损重排的根本发明。

TIM BERNERS-LEE · CERN · 1991

第一份 HTML 标签说明书，只有一条线性流

1991 年末，蒂姆·伯纳斯-李（Tim Berners-Lee）在欧洲核子研究中心（CERN）整理出《HTML Tags》，列出最初约 18 个用于学术文档的语义标签（标题、段落、列表、超链接）。无论是早期的 WorldWideWeb 浏览器还是纯字符界面的 Line Mode Browser，都按源码顺序从上到下线性排版，不依赖固定像素坐标。

出处：Tim Berners-Lee, HTML Tags (CERN, 1991)

CERN Line Mode Browser (1991) LINEAR STREAM

NORMAL FLOW DOCUMENT

Title, paragraph, and list flow strictly in HTML source order without fixed coordinates.

[ FIGURE: AUTO-PLACED IN FLOW ]

Every terminal width wraps lines naturally and pushes following lines downward.

补一句前提

海报写「从上到下」指的是横排文字（horizontal-tb）下的直觉体验。在现代 W3C CSS Display Level 3 与书写模式规范里，普通流更准确地说遵循块轴（block axis）与行内轴（inline axis）：如果把中文排成传统直排（writing-mode: vertical-rl），行内文字变成从上到下，而段落与段落之间的块流方向则会自然改为从右到左。

04

顺着用，还是换布局

When to Stay in Flow & When Not To

优先留在普通流

单线程理解、顺序重要、跨屏兜底

海报原话：「普通流布局适用于文章、说明文、报告等需要线性阅读的内容，让信息传递更高效、专注、舒适。」

  • 长文章、博客与技术手册：论证、步骤与代码逐段推进，不需要视线横跳。
  • 表单与结账流程：单列从上到下填写，填完一项视线自然落到下一项，减少漏填。
  • 移动首屏与渐进增强底座：所有复杂桌面布局缩到 390px 手机端时，往往最终都会退回一条干净的普通流。
什么时候别只用普通流

需要并排比较、二维定位或持久悬浮时

硬把所有界面都塞进单列普通流，会让用户不停狂滚屏幕，或丢掉全局参照。下面四类需求出现时，请切到对应的同族布局：

导航条、工具按钮排成一排，或仪表面板要同时对齐横纵两轴时，普通流只能傻傻竖排拉长页面。

  • 一维对齐与空间分配交给 226 弹性盒布局。
  • 二维行列骨架交给 227 网格布局，嵌套卡片跨级对齐交给 228 子网格布局。
  • 不等高图库密铺交给 236 瀑布流布局。

241 自适应布局：为几档典型设备分别定制独立版面。

242 容器查询布局：组件按自身容器宽度而非整屏宽度改变排布。

Four Craft Details That Make Flow Shine

1

为什么单列文章要设最大宽度

2

块级元素天生会占满父容器全部可用宽度。如果直接放在 1440px 屏幕上，一行字会拖得像一条跑道，读者折回下一行开头时极易跳行或重读。

3

给章节切换留出呼吸感

4

当章节标题与上一段拉开较大距离、与自己下方的首段保持紧凑，不需要加粗花哨边框，页面层级也会自己浮现出来。勾选「剥离视觉样式」，你会发现哪怕退回纯白黑字，这份阅读秩序依然纹丝不动。

行长上限：已启用（34em） WCAG 1.3.2 顺读一致

原海报与核心词

Original Poster & Key Concepts

原海报三大支柱

  • 01
    顺序 ORDER

    从上到下的自然先后，读者无需思考路径即可进入阅读。

  • 02
    节奏 RHYTHM

    标题、段落与留白构成稳定节拍，提供清晰的停顿与呼吸。

  • 03
    连续阅读 CONTINUITY

    内容在同一列连续展开，信息紧密相扣，增强理解与记忆。

要点提示 KEY TAKEAWAY

普通流布局适用于文章、说明文、报告等需要线性阅读的内容，让信息传递更高效、专注、舒适。

Normal flow layout is ideal for articles, documentation, and reports that require linear reading, making information delivery more efficient, focused, and comfortable.
