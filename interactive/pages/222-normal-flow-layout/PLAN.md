# 222 普通流布局（NORMAL FLOW LAYOUT）设计方案

## 1. 一句话道理
普通流是浏览器在零额外定位指令下的默认排布法则：元素严格按 HTML 源码顺序在单一阅读流中依次推进，块与块彼此让位、绝不叠压，让视线、键盘焦点与屏幕阅读器走同一条无歧义的路径。

## 2. 开场玩具：文档自然流修复台（Flow Stream Workbench）
- **载体与视觉语言**：2D Canvas（标 `data-perf-drag`），1:1 承袭 222 原海报的浅蓝单列微网页（深钴蓝标题条 + 浅天蓝正文行 + 双峰白日插图块 + `✳ 要点提示` 结语块），左侧贴合活体 **DOM 流序轨（#1–#5 连线）**，右侧贯通原海报招牌的 **`阅读 开始 START HERE ● ⋯ ▼ 阅读 结束 END HERE`** 竖向阅读流轴。支持三套语境标本：**原海报长文 / 技术文档 / 研究报告**。
- **怎么玩**：
  - **画布内横向拖动**（或拖右边栏宽标尺）：连续调节单列阅读宽度（220–680px），实时观察正文自动折行、块高伸缩并顺流推开下方所有兄弟块（`height: auto` 的真实流式联动）。
  - **直接点击画布里红色「脱流」标签**（或块控件）：把脱离普通流的 `position: absolute` 插图块一键归回普通流 `static`，立刻消除叠压；也可反向把块拉出流或锁死固定高度看溢出撞段。
  - **画布内直点或竖拖重排块序**（或 ↑/↓ 键）：修复被 CSS `order` 打乱的视觉顺序，让 DOM 序号 #1→#5 与画面自上而下完全一致，消除红色逆流交叉线。
  - **调节垂直节拍滑杆**：控制块间节奏，让标题亲近所属段落、段落之间有清晰呼吸停顿。
  - **按 `Space`（或点「演播阅读流」）**：钴蓝阅读光点沿 `START HERE ●` 一路向下滑过每个块并同步标出实际读序折返、遮挡卡顿与换行回扫负担，直至抵达 `END HERE ▼`。
- **一打开的状态（0/4 复合错态，绝不先给答案）**：
  1. **顺序逆流**：`⑤ 结语要点` 被错排到 `② 导语段` 之前，DOM 流线出现 1 处红线交叉回折；
  2. **插图脱流叠压**：`③ 山日插图` 被设为 `position: absolute`，不再占流内高度，`④ 承接段` 向上塌陷直接钻进图底被遮挡；
  3. **节拍粘连**：块间垂直节奏被压扁到 `4px`，标题与正文糊成一片灰墙；
  4. **通栏超宽**：单列行宽拉满 `96%`（约 54 汉字/行），超过 WCAG 1.4.8 推荐的 40 汉字上限，换行回扫吃力。
- **怎样算玩错、读数怎么说（单真源双向检出 8 类错态）**：
  - `model.js` 先根据当前栏宽、字体折行算法、流内/脱流标志与块序算出每个块的精确像素矩形（`x, y, w, h`）和实际每行字数，画面绘制与诊断卡片读取同一份几何结果。
  - 双向可错：顺序逆流（红线交叉 > 0）、脱流叠压（实测重叠像素 > 0）、定高溢出撞段（文本实绘高 > 锁定框高）、节拍过挤（< 12px 或标题上距 ≤ 下距）、节拍撕裂（> 46px 断成孤岛）、通栏超宽（> 38 汉字/行）、狭栏断句（< 15 汉字/行）、强制双栏拆断线性流。
  - 每次报错都用白话讲清「读者视线此刻会发生什么」以及具体修复动作；认可「原海报标准流」「紧致技术文档流」「舒朗长文阅读流」及任意满足 4 项几何条件的自调组合。
- **与最近 12 页的区别**：
  - 不同于 176（单段排字修边）、221（Ruby 注音比例）、261（页眉主体页脚分拣）、262（顶栏导航收纳），本页专注**块流联动、DOM 序与视觉序耦合、脱流叠压/定高碰撞、单列行长重排**——换到别的排版编号完全无法套用。

## 3. 版式骨架
- **外框母题**：1:1 承袭 222 原海报标志性的 **天蓝外框（`#9AC2F4`）包裹 22px 圆角瓷白单页纸（`#FCFBFC`）**，右侧内嵌贯通全高的 **`阅读 开始 ● ⋯ ▼ 阅读 结束`** 竖向流轴；不锁 `min-height: 100svh`，避免平板留大空白。
- **1440×900**（主宽 1380px；2560×1440 舒展至 1620px）：顶部精简自示范单行刊头（`普通流布局` + 钴蓝短杠 + 三语境切换 + `演播阅读流 Space`）→ 中部双区严丝齐底（左 37% 为原海报 `01 顺序 / 02 节奏 / 03 连续阅读` 实时探针叠层 + 浅冰蓝圆角 `✳ 要点提示` 单真源诊单卡；右 63% 为宽敞 2D 文档流修复画布 + 底沿一行精控滑杆与多解/试错药丸）→ 最右 72px 贯通原海报竖向流轴。
- **1024×1366 / 768×1024 平板**：自然流排，768 下画布满宽居中，`01 / 02 / 03` 实时探针横排三等分齐底，诊单卡满宽承接。
- **390×844 手机竖屏**：压缩 8px 天蓝外框与单行刊头，说明文字与 `01/02/03` 探针后置，让等比高清文档流画布稳占首屏 ≥ 46% 高度，折线内直露栏宽滑轨、`✳` 诊单首句与 `一键归流 / 演播阅读流` 双按钮。
- **844×390 手机横屏**：左 55% 活体文档流画布 × 右 45% 刊头、诊单首句与核心滑轨按钮并行，零横向溢出。

## 5. 节目录（7 节 + 页脚，标题均 ≤ 12 字，相邻节不复用同款控件）
- **01 为什么普通流最省脑**（Why Linear Flow Works）— 单列顺读 vs 碎卡散点的**双页视线路径透视对比**（场景切换按钮 + SVG 眼动分叉计数）
- **02 块怎么自己推开位置**（How Flow Computes Boxes）— **真实 DOM 活体沙盒**：直接往真实段落里「加一句字」看兄弟块顺流下推、切换「外边距折叠」、开启「定高溢出陷阱」（一句话链向 223 块级、224 行内、225 流根）
- **03 从哪来：网页生来是流**（Origins & Spec History，深钴暗室）— **1991 → 1996 → 1998/2011 → 2018+ 演进时间轴** + 同一份 HTML 的历史渲染预览，并温和补充海报「从上到下」在竖排书写模式下的泛化（块轴 / 行内轴）
- **04 顺着用，还是换布局**（When to Use & When Not）— **场景决策切签矩阵**（适用场景 + 「什么时候别用」四大破流场景），逐一以一句话链向同小类 223–242 在线版
- **05 写好普通流的四道细活**（Four Craft Details）— **真实微文章 CSS 调律开关板**：实时勾选 `max-inline-size` 行长锁、标题不对称间距、`Tab/读屏器顺序标号透视` 与 `一键剥离 CSS (WCAG C27 实测)`
- **06 小练习：挑最顺的一流**（Spot the True Flow，深钴暗室）— 四张中性标记（方案 A/B/C/D）的单变量对比图，选出唯一满足「顺序、不叠、节拍清、行长稳」的方案并给出逐项 CSS 剖析
- **07 原海报与核心词**（Original Poster）— 可点开放大、拖动（`draggable="false"`）、Esc 收起的 222 原海报 + 原海报三大核心支柱与要点卡

## 7. 小练习设计
- **题干**：一篇 2000 字产品说明文档需兼顾桌面（1280px）与手机（390px）线性阅读，包含标题、导语、插图与章节。四个方案其余视觉完全相同，仅差一个普通流变量，哪一套最稳妥？
- **选项**（全中性编号，无暗示词）：
  - **方案 A**：DOM 顺排、栏宽 32 汉字/行、全员 `static` + `height: auto`，但小标题上下间距与段距全为相等的 18px（失去亲密归属）。
  - **方案 B（正确）**：DOM 顺排、栏宽 32 汉字/行、全员 `static` + `height: auto`，小标题上距 32px 大于下距 10px，图块随流占位。
  - **方案 C**：DOM 顺排、栏宽 32 汉字/行、标题节拍清晰，但插图用 `position: absolute; top: 180px` 脱流定位（窄屏折行或放字时正文撞入图底）。
  - **方案 D**：DOM 顺排、全员 `static` + `height: auto`、标题节拍清晰，但正文容器未设 `max-width`，桌面拉满 62 汉字/行（超宽难回扫）。
