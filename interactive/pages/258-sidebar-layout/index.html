01

为什么分置一侧

WHY SEPARATE NAVIGATION TO THE SIDE

海报总述写道：「将导航或辅助信息分置一侧，主体内容集中呈现，提升浏览效率与信息可达性。」

它的底层道理并不玄学，而是顺应人眼扫读习惯做的「空间分工」。尼尔森诺曼集团（Nielsen Norman Group）在 2010 年与 2017 年先后发布的水平眼动追踪研究（Jakob Nielsen / Therese Fessenden）表明，从左到右阅读的网页访客把约 80% 的注视时间留在页面左半边；而在 2021 年对桌面左侧垂直导航的专项研究中（Page Laubheimer），研究团队进一步指出：当顶级分类较多或不断增长时，垂直左对齐列表比折行堆叠的顶部栏更容易一眼扫清，目光只需沿一条纵线直线下移，不必反复换行折返。

更关键的是心理安全感——把高频入口和结构目录安放在稳定的一侧，读者无需记住自己刚才从哪一层点进来。下面这组「眼动扫读对比」直观拆解了海报提出的四项效果价值：定位快速、专注阅读、结构稳定、效率提升。

点一个目标章节，观察两种排法的视线跳次（示意）

寻找「数据导出」：顶部双行需横向折返约 12 次示意注视；左侧对齐列表沿纵轴直扫仅约 5 次即可命中。

定位快速

原海报：快速找到所需内容

所有词首严丝对齐在一条垂直起扫线上，配合关键字前置，扫一眼就能锁定目标章节。

专注阅读

原海报：减少干扰，提升专注

用深浅对比将工具与目录收拢到一侧，把连续、平整的大片浅色画幅完整交还给正文。

结构稳定

原海报：符合用户浏览习惯

切页时只有主体内容更新，侧边坐标纹丝不动，用户随时知道「我在哪、能去哪」。

效率提升

原海报：学习与操作更高效

横向跨章跳转一步直达，省去「回首页 → 重新点菜单 → 再找子页」的折返损耗。

02

宽比边界与滚动锚定

PROPORTION GUARDRAILS & STICKY ANCHOR

做坏一个侧边栏通常只需要犯两个工程错误：要么宽度没管住，要么滚动行为写错。按桌面端常见经验值，完整文字侧栏一般落在 200–280px（约占 1280px 屏幕的 16%–24%）；更窄就应该改用 56–72px 图标轨，而不要把汉字挤成省略号。至于滚动——试试亲自上下滑动下面的双栏蓝图，切换三种真实 CSS 实现，感受差异。

把侧栏钉住，还要给它自己的滚动条

第一屏里三种写法看起来一模一样。只有当你真的往下读到第三段、第四段时，结构隐患才会暴露。

在「普通文档流（static）」里，侧边栏和正文绑在同一卷纸上，你往下读半屏，顶部的 01–04 节就消失不见了。

在「只钉住却不给 overflow-y: auto」的失误里，虽然前几节一直留在左上角，但当目录超过十来项时，底部的 10–12 节被永远裁在视口外，用户怎么滚都点不到最后一节。

现代标准做法是用 CSS Grid 定义轨道 240px minmax(0, 1fr)，给侧边栏加 position: sticky; top: 0; max-height: 100vh; overflow-y: auto;，同时用 minmax(0, 1fr) 防止主内容里的宽表格或代码块把右侧撑爆。

滚到底部回头再看左侧——推荐模式下目录既不随正文滚飞，自身也能独立滑到底部第 12 节。

双轨独立 · 稳健 layout.css 
.shell {
  display: grid;
  grid-template-columns: 240px minmax(0, 1fr);
}
.sidebar {
  position: sticky;
  top: 0;
  max-height: 100dvh;
  overflow-y: auto;
}

正文再长，侧边栏都稳贴视口顶边；目录条目超过一屏时，鼠标移到侧栏就能单独上下滑，两不耽误。

HTML 语义铁律（WHATWG HTML Living Standard）： 全站主导航请用 <nav aria-label="主导航">（隐式 navigation 地标）；侧边相关推荐、本文目录或注释再用 <aside>（隐式 complementary 地标），切忌只因为长在边上就滥用 <aside>。

05

什么时候用，何时别用

USE CASES, ANTI-PATTERNS & DECISION CHECK

说多了一点

原海报说侧边栏能「减少干扰，提升专注」「让学习与操作更高效」。这在条目超过 5 项且需要反复跨章跳转的产品里完全成立；但如果你的页面只有三四个栏目，或者是一篇希望读者一气呵成读完的故事长文，硬生生在左侧立一根常驻侧边栏，反而会白吃掉两成屏宽、不断分散余光。

放心用 · 原海报四大适用场景

  • 课程目录与学习路径十节以上的长程学习，随时确认进度并自由跳课。
  • 知识模块与章节导航技术文档、帮助中心与多层级百科，分类会持续生长。
  • 平台后台与工具界面多业务模块高频切换，搭配窄图标轨效率极高。
  • 报告与数据分析页面长篇季报或指标看板，配合固定大纲直跳结论与附录。

什么时候别用 · 四类典型反例

  • 顶层只有 3–5 个栏目的官网左侧大半留白显空荡，改用 262 顶部导航 更舒展。
  • 结账流程与沉浸叙事长文此时最怕跳走分心，请改用 255 单列页面 守住主线。
  • 手机竖屏常驻展开390px 宽度根本容不下双轨，必须退让为 263 导航抽屉 或 264 底部导航。
  • 超宽画布且不给折叠开关电子表格、视频时间轴或设计画布一旦锁死宽侧栏，操作区会被长期勒紧。
