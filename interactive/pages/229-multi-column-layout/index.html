城市慢读特刊：多栏如何替眼睛分段

面对宽阔的纸页或桌面屏幕，把文字从左到右通栏排满看似省事，眼睛却在每次换行时承受超长的水平回扫。把同一股连续文本拆进等宽多栏，正是为了把单行字数压回视线一扫即达的节奏里，减少串行与漏行。

真正的 CSS 多栏不是手工切块，而是让文字像水流一样，在首栏触底后自然折入次栏顶端，自左而右顺畅倾泻。只要纸幅或窗口一变，整篇文章便顺着栏宽重新分配落点。

版面注记

好的版面，不是把内容填满，而是让阅读更轻松。保持栏目呼吸与完整单元，视线才能一气读完。

只要栏距宽于行间净空、大标题横跨诸栏立住入口，再给图注块补上防截断护航，长篇文字就能兼顾信息密度与呼吸感。

01

宽屏为何要拆成栏

Why Wide Lines Break Reading

原海报说：「将内容按逻辑划分到不同列中，提升信息组织效率；按从左到右、从上到下的顺序自然过渡，降低阅读跳跃感。」核心原因不在装饰，而在人眼的换行回扫。

字体排印学者罗伯特·布林赫斯特（Robert Bringhurst）在 1992 年出版的《字体排印风格要素》里总结过一组流传最广的经验行长：西文单栏约 45–75 个字符（66 字符为理想中位），多栏则收紧到 40–50 个字符；换算到等宽汉字，多栏单栏通常落在约 13–30 个汉字的经验舒适带。一行过长，眼睛从行尾折回下一行开头时跨度太大，容易串行或重读；拆成多栏，就能在宽版面上把每行压回视线轻松接住的距离。

02

古腾堡到 CSS 草案

From 1455 Print to W3C Multicol

多栏并非网页时代的发明，而是印刷史延续五个多世纪的阅读装置——只是到了浏览器里，固定纸页高度变成了无限纵向滚屏，游戏规则才彻底改写。

  1. 约 1455古腾堡在美因茨印制《四十二行圣经》（B42），确立每页双栏、每栏 42 行的活字多栏典范。
  2. 19–20 世纪广幅报刊用 5–8 栏配合通栏头条，在同一大张纸上并行容纳不同篇幅的新闻稿。
  3. 1981约瑟夫·米勒-布罗克曼在 Niggli 出版社推出《平面设计中的网格系统》，把多栏与栏距纳入精确的数学网格。
  4. 1999 / 2001CSS 共同创始人 Håkon Wium Lie 起草首批 CSS3 多栏布局工作草案（1999-06-23 提案、2001-01-18 草案），后由 Rachel Andrew 与 Florian Rivoal 等编辑推入现行标准。

栏距与行距的拉锯

Gutter vs. Leading

原海报在第三栏总结得很准：「过窄：拥挤杂乱 · 适中：清晰平衡 · 过宽：割裂零散」。但它在底部的提示盒里写了一句值得商榷的数：

原海报 TIP：「栏距通常设为正文字号的 1/2 ~ 1 倍。」说得偏窄了一点

按格式塔邻近律，读者的眼睛永远把「距离更近的字」看成同一组。对于行高 1.6–1.8 的中文正文，两行之间的净空本身就有 0.6–0.8 倍字号；如果无分隔线却把栏距压到 0.5 倍字号，横向栏缝反而比纵向行空更窄，眼睛就会顺势直穿栏缝串进隔壁栏！

事实上，W3C CSS Multi-column 规范把 column-gap: normal 的基准值定在 1em（1 倍字号）——这只是底线；不画竖分隔线时，实际正文多栏通常需要 1.25–2.2em 才稳当；只有在中间加上 column-rule 细竖线物理截断视线时，栏距才适合收回到 1em 左右。

当你读完这一行的末尾，眼睛需要顺着本栏往下落到下一行起首。如果两栏之间的空白比两行之间的空白更窄，大脑就会把右边那一栏的文字当成同一句话继续往右读过去。

拉开栏距，或者在缝隙中央落下一道极细的竖线，就能明确告诉眼睛：到边界了，先往下走完这一栏，再折入下一栏顶部继续读。

04

CSS 自动算栏公式

How CSS Computes Columns

CSS 多栏最容易用错的一步，就是直接写死 column-count: 3。屏幕一变窄，三栏立刻被压成每行三四个字的窄条。

W3C 规范给出的解法是 column-width（理想最小栏宽）或组合简写 columns: 200px 3：浏览器按伪算法先算最多能放几栏 N = max(1, floor((U + gap) ÷ (width + gap)))，再把剩余宽度均分给这 N 栏，不写一句媒体查询就能自适应折栏。需要严格二维网格定位请看 227 网格布局，单轴弹性分配请看 226 弹性盒布局，按视口或容器断点彻底切换版式则看 240 响应式布局 与 242 容器查询布局。

05

跨栏锚点与防断块

Spanners, Balancing & Breaks

原海报第四、五条点出了多栏成败的另一半：「标题跨越多栏，建立整体性与视觉焦点」「通过对齐、重复元素与视觉引导，保持版面统一与阅读连贯」。落到 CSS 里，靠三把小剪刀管住流动。

  • column-span: all让大标题横跨全部列，同时迫使它上方的多栏先各自找平高度，再在标题下方开启新一轮多栏流。
  • break-inside / break-after阻止卡片、图注被拦腰劈进两栏，也防止孤零零的小标题粘在栏底、正文却跑到下一栏顶。
  • column-fill: balance在限定高度的栏盒里，优先把各栏摊平，而不是按 auto 把左边塞满、右边留出大空洞。

期刊专栏：如何止住栏间断层

多栏流把整篇文章视作一股连续墨线。未加约束时，只要纸面碰到底线，浏览器就会毫不犹豫地从当前像素切开，而不会顾及这段语义是否已经讲完。

定高容器默认按 column-fill: auto 先填满首栏再进次栏，容易让右侧留出空洞。

06

何时好用，何时别用

When to Use & When Not To

原海报列出的四类场景——文章排版、杂志内页、数据报告、产品介绍——有一个共同前提：单块多栏的高度最好能收进一屏左右。一旦在网页上把超过一屏高的长文拆成多栏，读者就会掉进「溜溜球滚屏」陷阱。

2 次折返爬楼 11.0 屏总滚动量

典型的「溜溜球滚屏」反模式

适合用多栏的网页场景

  • 一屏内可读完的导读与杂志跨页：高度不超视口，视线自然右上回接。
  • 术语表、页脚链接清单、短特征列表：短条目自然向下折列，省去手工拆 DOM 组。
  • 印刷 PDF / @media print 导出样式：打印介质本身有固定页高，正是多栏的主场。
  • 宽屏产品参数说明区块：用 columns: 220px 3 随窗宽自动并列或退回单栏。

什么时候千万别用

  • 超过一屏高的网页长正文：来回上下滚屏极度折磨读者，请回到单栏舒适行长配合 222 普通流布局。
  • 需要横向逐行对齐对比的数据：多栏顺序是「先下后右」，横向对照请用 230 表格布局 或 228 子网格布局。
  • 无限加载的卡片瀑布墙：用 column-count 冒充瀑布流会导致阅读顺序竖着走、加载新卡片时整页重排跳动，图片流请看 236 瀑布流布局。
  • 窄屏手机强拆两栏以上：单栏低于 13 字立刻变碎条，务必靠 column-width 自动回退单栏。
