# 236 · 瀑布流布局（MASONRY LAYOUT）互动页方案

## 1. 一句话道理
瀑布流布局通过「列宽一致、高度随内容自由伸缩、新卡片自动落入当前最短列」的装箱规则，消除了传统等行网格中由高矮差异拉出的横向空白行坑，在有限屏宽内用自然的高低错落呈现更高的信息密度与漫游效率。

## 2. 开场玩具
- **命名**：活体包豪斯九卡砌墙台（2D Canvas 实时重排舞台 + 横拖变宽 `data-perf-drag` + 点卡调高 + 四维错态诊治 + 追加新卡）。
- **视觉母题**：1:1 化用 236 原海报下半部 9 张红/黄/翡翠绿/浅米/墨黑包豪斯几何卡片，每张卡自带原海报同款几何插画（3 竖条、虚线补位积木、绿波红圆、日圆绿拱点阵、绿瞳眼睛、8 点加载环、双直角标尺、三场景图标、13 竖线刻度）。
- **开场状态（0/4 经典翻车错态，绝不提前给答案）**：
  1. 排布算法 = **行锁死（普通网格）**（行内留出约 28%–35% 惨白行坑，画布上以朱红斜纹直接标出浪费面积）；
  2. 列宽纪律 = **不等宽乱列（54% : 20% : 26%）**（窄列挤扁图形、宽列松垮）；
  3. 列间隙 = **0px 粘连无缝**（色块贴死串色）；
  4. 卡片高度节奏 = **强行全等高**（高低落差 0%，退化成僵硬豆腐块，毫无错落感）。
- **怎么玩 & 怎么会玩错**：
  - **画布横向拖动（`data-perf-drag`，`touch-action: pan-y`）**：直接推拉舞台右缘虚线视口边界，把容器从 340px 单/双列拉展到 980px 四/五列，卡片沿弹簧轨迹实时飞入最短列；若窄容器硬塞 4–5 列触发「窄列挤扁」错态。
  - **画布内直接点击任意卡片**：循环切换该卡高度（矮 / 中 / 高 / 超长条），若造出极端超长卡片导致列底参差过大，触发「超长拖尾失衡」错态。
  - **四维切槽 & 追加压测**：算法除了「行锁死」，还能切到「多栏竖排 `column-count`」（触发「竖填断序 + 追加跳列」错态），也可在「最短列补位（标准 Masonry）」与「容差补位（`grid-lanes` 容差）」两个合法解间切换；间隙拉到 40px+ 触发「缝宽撕裂」错态；点击「＋追加新卡」亲测无限滚动时最短列与多栏竖排的差异。
- **读数单真源**：`model.js` 从画布上每张卡片的实际几何 `(x, y, w, h, col, order)` 实时核算「空洞率」「列底落差」「高度跨比」「单列宽」「阅读跳序」与诊断结论（错在哪 + 为什么 + 下一步怎么试）。
- **与最近 12 页的明显区别**：不采用左文右图或仪表盘侧栏（区别于 235/196/028/066/151/234/279/195/150/233），也不做多轨波纹节奏（111）或展卷（317），而是忠实还原 236 原海报「上刊头 + 三彩圆实测带 + 全宽通栏包豪斯 9 卡瀑布流主体 + 底沿诊单控台」的垂直海报骨架，动作完全源自瀑布流独有的「变宽重排、最短列补位、点卡改高、追加不跳列」。

## 3. 版式骨架
- **1440×900 桌面**：主栏宽 1340px（2560×1440 舒展至 1720px）；不锁 `100svh`。顶眉 32px → 包豪斯非对称刊头（左：五字字脚随当前算法真实高低错落的示范大标 + 英文 + 红杠总述；右：原海报红圆/点阵/绿半圆/黄矩形动态组合徽章）→ 原海报三彩圆实况指标带（细竖线分隔 + 通栏虚线）→ 全宽通栏活体 9 卡瀑布流砌墙台 → 紧贴底沿的双栏诊单与四维控台带。
- **1024×1366 / 768×1024 平板**：自然流式排布不锁高，无中间白洞；画布保持合理纵横比，诊单与控台紧凑落于其下。
- **390×844 手机竖屏**：刊头压紧为紧凑单行（藏起大徽章、保留小三色点），三彩圆收成单行紧凑指标条，活体瀑布流画布稳占首屏 ≥ 46% 屏高并同屏可见诊单首句与算法切钮；卡片与几何圆等比绘制绝不压扁。
- **844×390 手机横屏**：切为左 57% 全高瀑布流画布 × 右 43% 紧凑刊头、白话诊单与核心切钮，一屏顺畅操作。

## 5. 节目录（每节标题 ≤ 12 字，相邻控件完全不重样）
- **01 最短列怎样自己补位**（`SHORTEST-COLUMN PACKING`）：单步放砖步进播放器（放入下一张 / 自动连放 / 倒退 / 切容差），可视化最短列水位线与 `flow-tolerance` 如何稳住顺读。
- **02 三条实现路线的暗坑**（`THREE IMPLEMENTATIONS`）：三轨实现并排压测台（CSS 多栏 / JS 绝对定位 / CSS `grid-lanes`），点击「追加 6 张新卡」与「显示 Tab 焦序」暴露多栏跳列和键盘折返。
- **03 节奏、留白与视线的账**（`RHYTHM & THE MYTH` · 墨黑暗室）：温和纠正原海报黑卡「阅读更高效 · 减少用户思考成本」（标「说多了一点」），双任务视线对比舞台（自由漫游找灵感 vs 定向查价格日期），展开节奏分布、间距与节省空间。
- **04 它从哪来**（`ORIGIN & EVOLUTION`）：四张包豪斯年代档案卡横向切换（石工砌墙隐喻 → 2009–2010 David DeSandro jQuery Masonry → 2010 年 3 月 Pinterest 三位创始人与 Evan Sharp 钉板迭代 → 2020 Firefox 原型至 2025–2026 W3C CSS Grid Level 3 `display: grid-lanes`），含同小类布局一句话链接。
- **05 什么时候用，什么时候别用**（`WHEN TO USE & AVOID`）：六枚真实产品场景筹码分诊台，左侧天然主场、右侧四条避坑红线（含图片未声明宽高引发 CLS 跳动），点筹码直接给替代布局链接。
- **06 挑出最稳的一堵墙**（`PRACTICE QUIZ`）：四选一单一变量视觉诊断题（方案 A/B/C/D，中性标签，只差排布规则），选后在缩略墙体上直接浮现空洞/跳序/裁切标尺与解析。
- **07 原海报与延伸**（`ORIGINAL POSTER`）：原海报高清放大拖动灯箱（Esc 关）+ 海报全部要点原话汇总 + 同小类其他编号链接。

## 7. 练习设计
- **题目**：你要给一个移动端摄影与插画灵感社区做发现页，每张作品原图比例从 3:4 竖图到 16:9 横图不等，且用户滑到底部会不断追加加载新作品。以下四套方案列宽、间隙与原图完全相同，只有排布方式不同，哪一套最稳？
- **四个选项（标签仅写 方案 A / B / C / D，只差「排布规则」一个变量）**：
  - **方案 A**：等行网格排布（同行按最高卡锁行高，矮卡下方出现大片行坑）
  - **方案 B**：CSS 多栏竖排（从上到下填满整列再换下一列，横向阅读断层且追加新卡时前排整墙跳列）
  - **方案 C**：最短列自动补位 + 合理容差（零行内空洞，编号横向推进，触底追加只往墙脚续接，不动已读区）✅ **正确**
  - **方案 D**：强制裁切等高卡片（每张图都剪成 4:3，表面齐整但竖构图画作被硬生生腰斩）
