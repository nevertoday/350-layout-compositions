# 237 覆盖布局（OVERLAY LAYOUT）互动页设计方案

## 1. 一句话道理
覆盖布局的核心是「借空间、不丢语境」：在 Z 轴抬起一层临时任务，用可控遮罩压低底层干扰却隐约保留位置感，同时靠独立层叠与清晰退出闭环，让人进得去、看得分明、退得回原位。

## 2. 开场玩具
- **命名**：活体三层光学覆盖台（原海报午夜青/洋红/紫透叠平面 × 真实 UI 覆盖窗 × 0°正视/32° Z 轴侧剖双视角）。
- **怎么玩**：
  - 在主画布（`data-perf-drag`）上**左右横拖**，像拉动光学灰片一样实时调节中景遮罩不透明度（0%–100%），在 32° Z 轴侧剖视图下则可横拖调节三层拉开距；支持键盘 `← / →` 微调、点击画面底层露出的「清空草稿」按钮实测是否穿透误触、点击前景「×」或按 `Esc` 实测退出闭环，并可在「确认弹窗 Modal / 侧边抽屉 Drawer / 大图覆文 Scrim」三类真实场景间切换。
- **开场初始态（0/4 灾难错态，绝不先给答案）**：
  1. **层叠牢笼**：前景浮层被关在带 `transform` 的局部层叠上下文卡片内，即便声明 `z-index: 9999`，仍被底层 `z-index: 20` 的紫蓝顶栏劈穿压住；
  2. **缺幕透字**：中景遮罩仅 6%，底层页面与前景文字叠字打架，实算对比度跌破可读带；
  3. **点击穿透**：未开启 `inert` 背景阻断，点前景外侧会直接误触背景「清空草稿」触发红闪告警；
  4. **无退套娃**：同时叠了两层弹窗抢焦点，且隐藏关闭键并屏蔽 `Esc`。
- **怎样算玩错 & 读数怎么说「为什么」**：
  - `model.js` 单真源从实绘图层几何、层叠树与实算混合亮度对比度动态识别 8 类失误：`trapped`（`transform` 层叠牢笼反穿）、`z_under`（同上下文低 `z-index` 倒挂）、`scrim_thin`（遮罩过淡 < 30% 致前景背景混叠）、`scrim_wall`（遮罩过死 > 82% 抹掉语境退化为硬跳页）、`leak_through`（缺 `inert` 造成点击/焦点穿透）、`nested_overload`（套娃叠弹抢焦点）、`no_exit`（无出口锁死）、`over_cover`（前景面积 ≥ 88% 闷死底层失去显露意义）。
  - 读数不止报数字，而是直说「用户眼睛会怎么看、手会点错什么、为什么会卡住」；支持多组正当解（原生 `<dialog>.showModal()` Top Layer 解、根层高 `z-index` 解、抽屉与大图渐变遮罩解）。
- **与最近 12 页的明显区隔**：
  - 不同于 067（暖米钴蓝包豪斯几何体直拖造 T/X 节点）、236（暖米九卡瀑布流砌墙）、235（暖奶油三分区粘性滚卷）、112（电光蓝渐进圆列阶梯）和 197（深森绿四区比例切割）；237 忠实承袭原海报的午夜黑蓝 + 青/洋红/紫光学玻璃层叠美学，玩的是 **Web UI 覆盖布局独有的层叠上下文突围、光学遮罩控度、背景 `inert` 防穿透实测与 `Esc` 退出闭环**。

## 3. 版式骨架
- **1440×900（主宽 1380px，2560×1440 舒展至 1780px）**：严格对应 237 原海报「左 34% 午夜刊头脊柱（嵌活体三层错影的厚黑示范大标「覆盖布局」+ `OVERLAY LAYOUT` + 标志洋红短杠 + 原海报青/洋红/紫三彩圆实况灯柱 + 白话单真源诊单 + 原海报左下三色空心方框前景/中景/背景引线与 8×4 紫点阵）× 右 66% 满幅光学三层覆盖舞台（带原海报 6×4 青点阵、右侧洋红竖点阵、白框焦点窗与右下紫青双圆）下接四维控台与实时 CSS/HTML 片段」；左右两栏高度自然齐平，不锁 `100svh`。
- **1024×1366 / 768×1024**：平板自然转为顶刊 + 全宽舞台 + 下方双栏诊单与控台，无任何大块空洞。
- **390×844（手机竖屏）**：顶眉与刊头压紧单行，光学主舞台紧接顶栏占据首屏 ≥ 46% 屏高（严守纵横比绝不压扁），同屏可见遮罩拖轨提示与白话诊单首句。
- **844×390（手机横屏）**：切为左 56% 光学覆盖舞台 × 右 44% 紧凑标题、诊单与核心控钮并行布局。
- **正文七节交替节奏**：午夜暗房（Hero）→ 冰白画廊（01 起源）→ 柔紫雾纸（02 层叠牢笼）→ 午夜暗室（03 遮罩与对比度）→ 冰青雾纸（04 四种覆盖真界面）→ 深靛紫暗室（05 什么时候别用）→ 素白冷纸（06 挑出更好的一版）→ 午夜原海报暗房（07 原海报与校准）。全页延续原海报 0px 锐利直角光学玻片语言，摒弃圆角深色仪表盘卡感。

## 5. 节目录
- `01` **从哪来：重叠窗到顶层** (`ORIGIN · 1975–2025`) — 四代演进时间轴切换 + 内联层级剖面图解，一句话链接同小类 222/232/233/234/235。
- `02` **层叠牢笼：9999 败给 20** (`STACKING CONTEXT LAB`) — 交互式 CSS 层叠上下文 X 光树，勾选 `transform`/`opacity`/`filter`/`isolation` 或切换原生 `<dialog>` Top Layer，实时重算绘制栈并直观演示反穿与脱困。
- `03` **遮罩控度：显露与对比** (`SCRIM & CONTRAST LAB`) — 真实大图覆文校准器，调遮罩透度、色调（全屏平幕 vs 底部渐变幕）与模糊度，实时核算 WCAG 2.1 SC 1.4.3 亮度对比度。
- `04` **四种覆盖：各司其职** (`OVERLAY PATTERNS`) — 真实可点开的迷你工作台，现场触发 Modal、Drawer、Popover、Toast 四种覆盖，直观体验阻断、轻关与焦点行为差异。
- `05` **什么时候别用覆盖** (`WHEN NOT TO OVERLAY`) — 四类反面案例「滥用态 ⇄ 正解态」切换对照，结合 NN/g 与 WAI-ARIA 原则说明何时该回到正常页面或行内反馈。
- `06` **挑出更好的一版** (`PRACTICE QUIZ`) — 单变量四选一可视化界面诊断练习（中性标签方案 A/B/C/D，仅遮罩与隔离方式一处差异），选后逐项拆解原因。
- `07` **原海报与关键词** (`ORIGINAL POSTER`) — 可点击放大拖动与 `Esc` 关闭的 237 原海报、原海报词条与温和校准注记。

## 7. 练习
- **题目**：用户点击「删除整个项目」后需确认不可逆操作；四版界面仅在「中景遮罩与背景隔离」这一变量上不同，哪一版既保住上下文又守住安全？
- **四项差异（单变量）**：
  - 方案 A：0% 无遮罩、背景按钮仍可点击高亮
  - 方案 B：55% 半透明暗夜遮罩 + `inert` 锁定底层交互（唯一正解）
  - 方案 C：100% 纯黑实底彻底盖死背景页面
  - 方案 D：12% 极淡透明膜、未锁底层滚动与点击
- **理由**：删除属于不可逆操作，必须用中度半透明遮罩（经验参考 35%–72%）压低底层干扰、同时隐约保留背后项目名作为语境锚点，并配合 `inert` 阻断误触；0% 与 12% 拉不开视觉主次且存在穿透误触，100% 实黑则把背景语境抹空。
