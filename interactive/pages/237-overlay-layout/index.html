从哪来：重叠窗到顶层

            
ORIGIN · 1975–2025

          

        

        

          覆盖布局并非网页发明。它从 1970 年代位图屏幕上的「重叠窗口」出发，在 CSS 里经历了长达二十多年的 z-index 缠斗，直到浏览器原生 Top Layer 成熟才真正定型。它和同一小类的
          222 普通流、
          232 相对定位、
          233 绝对定位、
          234 固定定位、
          235 粘性定位
          分工不同：前几位管元素怎么排位与随滚动锚定，覆盖布局专管「多层叠在一起时谁在前、盖几分、焦点锁在哪」。

层叠牢笼：9999 败给 20

            
LAYER · STACKING CONTEXT X-RAY

          

        

        

          原海报第一要点写着「层叠关系 LAYER」。前端开发最常踩的坑是以为 z-index 是全页通用的楼层号——其实 1998 年 W3C CSS2 规范就定下规矩：只要祖先触发了新的「层叠上下文（Stacking Context）」，子元素的 z-index 就成了封闭楼层里的房间号，飞不出父容器的外部权重。勾选下方属性，亲眼看 9999 怎么输给 20。

    遮罩控度：显露与对比
    
            
    DEPTH · SCRIM & WCAG 2.1 CONTRAST
    
          
    
        
    
        
    
          原海报第二要点是「遮挡与显露 DEPTH」。遮罩（Scrim）既不能透明到让前景字和底图打架，也不能黑死到抹掉背后的画面语境。尤其在大图覆文场景下，W3C WCAG 2.1 SC 1.4.3 要求常规正文对比度达到 4.5:1（大字 ≥ 3.0:1）——试试把「全屏平暗」换成「底部渐变幕」，看看如何兼顾文字清晰与主图通透。

    四种覆盖：各司其职
    
            
    EMPHASIS · MODAL, DRAWER, POPOVER, TOAST
    
          
    
        
    
        
    
          覆盖布局并不是只有“屏幕正中弹黑框”一种样子。按打断强弱，网页 UI 把覆盖分成四档：点击下方迷你工作台里的四个触发钮，真正在窗口里把它们打开，感受「阻断、留语境、轻关与零打断」的区别。
